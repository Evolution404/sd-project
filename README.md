# 输电项目全流程管理系统

采用 Node.js 24、SQLite、Vue 3、TypeScript、Element Plus 和 ExcelJS。服务端正式编译到 `dist/server` 后运行。当前程序使用独立的 Schema 113，覆盖输电台账、专业需求、年度框架、子项目、执行协议、参考计价、真实费用及分次结算。

服务端运行代码统一采用严格TypeScript，数据库访问集中在专用Repository及查询模块。本轮访问日志、业务复查和发布验收见 `docs/implementation/访问日志与最终交付_2026-11-13.md`，历史重构过程见 `docs/implementation/rewrite-20261110/执行记录.md`。


- 网址：`http://127.0.0.1:8788`
- 账号：`demo`
- 密码：`DemoOnly-2026!`（仅供本机演示，请勿用于正式服务器）

也可单独执行 `npm run demo:seed`，只创建或检查演示库，不启动服务。演示数据包含线路、物理/逻辑杆塔、档距、物资、作业对象、操作类型、价格特征、参考价格、需求、年度框架、执行协议，以及含已核价、实际费用和分期结算的项目；所有工程名称及价格均为**虚构示例**，不得用于真实报价或施工。

演示环境和真实环境独立；真实数据继续使用 `npm start` 或 `make dev`，详情见 `docs/implementation/2026-11-10_独立演示环境与业务样例数据.md`。

## 启动

```sh
npm ci
npm run build
npm run init-admin
npm start
```

本机访问 `http://127.0.0.1:8787`。首次初始化创建管理员，密码不得为空，最长256位；建议使用高强度密码。已有管理员不会被初始化脚本覆盖。Mac 开发可执行 `make dev`。开发前后端热更新分别使用 `npm run dev:api` 与 `npx vite --host 127.0.0.1`。

默认仅监听本机。内网部署可设置 `HOST=0.0.0.0`，管理员先在系统管理中添加客户端的完整 IP。连接身份以实际套接字地址为准。业务接口要求登录，正式批准、需求确认、费用核定和结算审核分别检查服务端权限。

## 数据与恢复

```text
data/
├── schema113.sqlite
├── schema113.sqlite-wal
├── schema113.sqlite-shm
├── logs/                 # 按北京时间及大小轮转的HTTP访问日志
├── objects/sha256/        # 内容寻址的证据文件
└── backups/              # 数据库和证据文件备份
```

旧 `business.sqlite`、原附件及备份继续保留。新程序创建自己的数据库文件。开发和测试显式设置临时 `DATA_DIR`。初始化校验完整结构指纹，遇到同为113但定义不同的数据库也会拒绝启动，需要选择匹配备份或新的独立目录。

```sh
npm run backup
node scripts/restore.mjs /绝对路径/备份目录 /绝对路径/全新恢复目录
```

恢复前校验数据库外键、完整性及全部证据文件的字节数与 SHA256。恢复目标必须尚不存在。恢复后将 `DATA_DIR` 指向恢复目录启动。

## 2026-11-09 系统独立与最少录入

本系统**完全独立，不考虑 PMS 编码或任何关联**，不做同步、一次性专用导入、外部编码映射或兼容。普通 Excel 只用于本系统业务录入。

**用户不应填写线路编码、物理杆塔编码、逻辑杆塔编码或其他纯技术身份。** 这些值应由服务端在创建时生成或评估为冗余后精简；用户输入线路名称、电压等级、杆塔号、真实位置及必要业务事实。普通新建杆塔应自动建立合法物理/逻辑关系；共塔需要明确选择已有实物，歧义时提醒确认。

线路及各类主数据的内部编码由服务端生成。普通杆塔只需线路和杆塔号，一次保存自动建立物理实体与回路关系。同塔多回选择已有实物，同号歧义需明确判断。整基更换在详情办理，事务内建立新实物并保留各回路旧版本及正式更换审计。

决策文件：docs/decisions/2026-11-09_系统独立_自动编码_最少录入.md。

## 业务使用

1. 在基础数据中维护电压、计量单位、需求优先级、项目类别和归口单位。在作业标准中维护作业对象及操作类型，在物资管理中维护物资，在参考价格中维护规则和额外价格特征。输电设备台账维护线路、物理/逻辑杆塔及档距。
2. 新增需求时选择操作、真实位置和数量，补足现场问题、验收标准和来源。同一需求允许多个位置，单位和作业对象由操作定义取得。需求先进入待确认，确认决定单独办理。
3. 创建年度框架和子项目，关联需求后立即形成独占归属。正式入库后编制逐位置批准范围和预算，可只承接需求的部分位置及数量。
4. 对完整需求或项目实际承接范围分别试算并确认参考价。重叠规则需要明确选择及依据。缺价格时显示已计价小计及缺项。
5. 从项目、资金档案或跨项目查询进入项目财务工作区，核定实际费用并编制分期结算。每张结算单可填项目总额或使用末级费用明细，需求新增解决量可以单独填报。保存、提交和审核分别办理。结算进度按生效已批准结算占核定实际费用的比例计算。
6. 有明确费用明细的结算可办理逐项核对。结项确认冻结当时的工作量、实际费用、结算进度及差额。最新批准范围内的需求继续受解绑保护。

需求、项目和结算编号由服务端生成。Excel 多单据明细通过“主表行号”关联，单单据可自动关联。所有正式金额直接按人民币金额处理。

## Excel

设备台账、专业需求页面和项目结算页面提供空白模板、筛选结果导出、勾选项导出、数据维护回导、业务报表和预检工作台。结算入口继承当前子项目及其批准、资金版本。

维护工作簿携带稳定身份与原正式版本。需求包含需求清单、作业位置、预计物资、来源依据及按需使用的补充现场字段、现场价格特征。结算包含结算单、费用明细、需求解决明细。用户填写操作、物资、线路名称及杆塔号等真实事实，系统管理隐藏且受保护的稳定身份与版本。同名同号出现歧义时提示核对。设备台账 Excel 使用“线路／物理杆塔／逻辑杆塔／档距”四张业务表：普通新建杆塔只填逻辑杆塔表；独立物理杆塔表用于单独维护已有实物。一份文件支持主线、支线、主线接入杆塔、普通杆塔、明确共塔以及真实档距的批量新增和维护回导；系统根据表内引用按依赖顺序生成身份与关联，不要求用户填写编码或 ID。档距连接必须明确填写起止杆塔号，绝不根据杆号或行顺序推测。档距的“输电中心管辖长度”所有业务表单、详情、历史、筛选和Excel均使用米，最多3位小数；NULL（未知）与0米（明确无管辖长度）严格区分。数据库使用整数毫米仅作无浮点误差的内部精确存储，旧事实不迁移。支线跨线路档距只允许通过已指定的主线接入塔。工作簿业务列头为中文，隐藏的身份和原版本由系统保护；筛选导出使用当前设备分类和已应用条件，勾选导出只采用所选记录。不存在任何外部系统编码映射。

金额填写元，最多2位小数。工作量填写实际单位数量，最多4位小数。`__KEEP__` 或缺少单元格保持原值，`__CLEAR__` 清除可空字段，`__EMPTY__` 表示空文本。明细 `action=delete` 明确删除该行，未出现的行保持原值。替换作业位置需要明确删除原位置并新增新位置。

预检只保存工作批次，不修改正式台账。设备台账默认整批全部成功或全部回滚；需求和结算可选择逐单据或整批原子提交。预检界面先按完整结果排序、筛选，再分页显示。提交重新检查版本和引用，幂等回执与业务记录在同一事务保存。结算导入只生成草稿。业务报表带只读标记，不能回导。

单批最多5000张单据、25000行业务明细。仅接受12MB以内的 `.xlsx`，解压总规模不超过80MB，最多2000个ZIP条目。公式、富文本、超链接及Excel错误单元格需要修正为真实值。

## 界面和操作

所有业务数据表统一使用 BusinessTable。支持显示列定制、列顺序、固定和宽度记忆；设备台账在数据库查询层过滤、排序和分页。正式批准草稿的必需勾选和数量不能隐藏。右上角“外观设置”支持跟随系统、浅色、深色三种模式；侧栏右侧边缘可拖动调节宽度（默认240px，范围208～400px），双击边缘恢复默认，方向键可微调；侧栏折叠与宽度偏好会保存。表格列宽同样通过拖动表头边界调整并持久化，默认中文表头保持单行。

## 页面与查看

十二个主要入口按工作台、业务办理、资金与结算、设备与物资、标准与计价、基础配置与系统分组，导航分组可折叠。主模块和主数据分类采用 Vue Router Hash 地址。搜索、分页、列筛选、排序和已删除范围写入URL查询参数，支持刷新及浏览器前进后退。搜索改变时返回第一页，分类新进入重置查询，后退恢复此前分类查询。

需求、子项目、设备和其他主数据的查看统一打开模态框，查看与关闭保持列表地址和查询位置。项目编制与审核、分次结算、操作类型和参考价格的复杂编辑使用独立办理页。项目详情查看财务摘要，正式费用、结算与核对统一进入同一项目财务工作区。刷新保留列表位置，未保存表单不写入业务事实。服务端继续检查业务身份、权限和正式版本。

表格默认铺满可用宽度，列少时自动伸展，宽表在表内滚动。行内展示一项主要操作，其余在“更多”菜单。列设置支持拖动手柄排序，聚焦手柄可按上下方向键、Home、End，并自动记忆显示、固定、顺序和宽度。

杆塔号按所选线路判重，跨线路同号可直接新建各自独立实物，真实共塔明确关联已有实物。物理杆塔查看框直接显示其全部关联逻辑杆塔。业务Excel支持整行选择和表头改名，正式字段绑定通过工作簿命名元数据保留，回导仍校验身份、版本及业务约束。模板及导出使用中文文件名和表头，“新增必填／条件必填”显示在字段名上方。新增必填标记针对新事实，维护时未填项保持原值。表头排序持续点击在升序、降序之间循环。

## 杆塔性质、材质及P10使用指引（2026-11-12）

基础数据中正式维护杆塔性质（内置耐张、直线）与杆塔材质（内置角钢塔、钢管杆）。物理杆塔的原塔型已替换为受控杆塔材质。两组字典可新增、改名、停用并查看正式历史，已引用身份不随名称变化。详见 docs/implementation/杆塔性质与材质字典_实施验收_2026-11-12.md。

### P10 操作帮助真实控件定位（第二轮收口）

在顶部“使用指引”中通过“操作搜索”打开某类业务说明，点击“定位当前按钮”，会在当前可见且唯一的控件上显示一段不触发业务写入的只读ElTour。页面未切到对应页签、弹窗未展开或者同时存在多个同类行级按钮时仅给出文字说明，不代替点击。当前82类说明中25类已绑定可定位的语义锚点，覆盖全部12主模块；其余57类将在后续动态菜单、四角色状态和审计中继续核实。项目离线包提供此功能但不替用户完成实际操作。

## HTTP访问日志

管理员在系统管理的“访问日志”页签按时间、IP、账号、方法、状态码和关键词查询，查看请求详情并下载筛选后的UTF-8 JSONL。所有时间采用北京时间。日志位于运行目录 `data/logs/`，默认保留最近30个自然日，单文件10MiB，按北京时间日期及文件大小轮转，重启继续保留。显式 `DATA_DIR` 下使用其 `logs/` 子目录。

可通过 `ACCESS_LOG_RETENTION_DAYS` 和 `ACCESS_LOG_MAX_FILE_BYTES` 调整保留天数及单文件字节上限。响应头 `X-Request-ID` 对应每条日志的 `request_id`。日志不记录请求正文、密码、Cookie、认证头或查询字符串，客户端IP取真实连接。日志读写故障输出 `ACCESS_LOG_IO_FAILURE`，管理员界面提供诊断。详细验收记录见 `docs/implementation/访问日志与最终交付_2026-11-13.md`。

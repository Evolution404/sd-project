## 业务授权与边界

用户针对《计划预算与费用_待裁决_2026-10-30.md》第2节明确回复“采用上述规则”，批准：

1. 在子项目当前批准预算内人工分配，各计划当前有效核定预算合计不得超额。
2. 管理员确认预算及调整，保留核定版本；不增加多级审批。
3. 计划结束/取消不自动释放预算；调减、删除当前预算必须单独编制并确认。
4. 子项目预算调减前，先处理计划核定预算超额。

授权已写入 AGENTS.md、原待裁决文件及实施计划。工作量估算不自动转为核定预算；预付款再归集、费用确认权限及实际付款口径未因本次授权自动确定。

## 功能与增删改查

入口：项目中心→子项目详情→检修计划→检修计划预算。复用 Element Plus 表格、表单、描述列表、筛选与模态框；输入项只有预算金额和编制依据，技术标识、版本和确认人自动记录。必填红星与就近红字，关闭原生浏览器校验气泡。

| 操作 | 实际流程 | API |
| --- | --- | --- |
| 新增 | 编制人工预算草稿，保存不占额度 | `POST /api/executions/:id/budget-drafts` |
| 查询 | 查看当前预算、项目可分配额、净结算及差异；筛选待确认/已确认/已删除/全部草稿 | `GET /api/executions/:id/budget?draft_status=draft`；状态可用 confirmed/deleted/all |
| 详情与历史 | 草稿创建、编辑、删除和确认历史；全部不可覆盖的核定版本 | `GET /api/plan-budget-drafts/:id`；计划预算接口的 versions |
| 草稿修改 | 明确核对当前批准依据与预算版本，编辑金额/依据后保存 | `PATCH /api/plan-budget-drafts/:id` |
| 草稿删除 | 填写删除依据，删除后不改变已核定预算；可在已删除草稿查询 | `DELETE /api/plan-budget-drafts/:id` |
| 核定与调整 | 管理员查看拟核定金额、原额、项目可分配额和依据，确认后生效 | `POST /api/plan-budget-drafts/:id/confirm` |
| 删除当前预算 | “删除当前预算”编制撤销草稿；管理员再次确认后当前占用归零，保留原预算版本及全部实施、结算事实 | 同一草稿接口 kind=release；同一管理员确认 API |
| 上层核对 | 项目已分配/未分配预算；协议、框架展示计划分配合计 | `GET /api/projects/:id/plan-budgets`；现有逐级 settlement-summary 及资金对象详情 |

草稿正常列表默认排除已确认和已删除记录，必须显式选择对应状态查询。删除当前核定预算采用已获准的撤销版本，具有真实删除入口与效果，不用停用代替删除；后续再编制预算产生新的核定版本，旧事实不会复活或覆盖。

编辑人员可编制、修改和删除草稿；只有管理员可核定，包括调减与撤销。只读账号仅可查询。所有权限均由服务端校验。

## 核算与并发保护

- `plan_budget_drafts` 保存编制及删除状态，审计保留历次内容；已确认或已删除的原草稿不允许再覆盖。
- `plan_budget_versions` 为不可覆盖/清除的确认事实，记录金额、原额、依据、对应项目批准版本及当时项目预算、确认人和时间。`plan_budget_current` 只取每计划最新版本参与合计。
- 确认在 SQLite 即时写事务中重检项目批准依据、计划预算基线、草稿版本和各计划合计，过期草稿须编辑核对后再确认；并发确认不会超配。
- 确认支持幂等标识：相同请求重试不生成新核定版本，复用标识到其他内容或重复确认已确认草稿会拒绝。
- 项目变更批准在同一事务检查计划预算合计，不得先把项目预算调低，再留下超额分配；未通过时项目范围、预算及批准历史均不半更新。
- 已结束/取消计划仍计入预算分配；工作量释放不释放预算。明确确认撤销后才释放，关联完成量、净结算和原始凭证不变。
- 计划已分配预算是项目批准预算内的分解，不作为新增成本叠加到项目、协议、框架预算或结算。项目级未归集结算继续独立，不向计划自动分摊。
- 核定预算和净结算分列，结算超过当前核定预算时展示差异。本轮未新增“计划预算截断真实结算”或“把预付款自动改作实际付款”的政策；原有项目/需求结算上限继续有效。

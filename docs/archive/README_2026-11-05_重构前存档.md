## Mac 本地测试：一条命令启动

在终端运行：

```bash

make dev
```

自动检查 Node.js 24+、首次安装依赖、构建最新前端并在 `http://127.0.0.1:8787` 启动本地服务。**首次运行**会交互式创建管理员（密码不设最低长度或复杂度要求，但不能为空，输入不回显），第二次以后直接启动。保持终端窗口打开，按 `Ctrl+C` 停止。

## Windows 10 x64（交付 ZIP）

1. 将发布 ZIP 整包解压到可写目录（例如 D:\SDProject），不要直接在压缩包中运行。
2. 双击 **初始化管理员.cmd**，设置用户名与自选非空密码（不设默认密码）。
3. 双击 **启动服务.cmd**，保持服务窗口运行。
4. 服务器本机打开 http://127.0.0.1:8787；局域网终端通过 http://服务器IP:8787 访问，按需在 Windows 防火墙放行 TCP 8787。
5. 所有运行数据保存在解压根目录 `data/`（数据库、WAL/SHM、附件、备份），Windows 启动和初始化脚本固定使用此目录。发布 ZIP **不包含** `data/`，解压升级时切勿删除或覆盖已有 `data/`。请将程序解压在具有写权限的本地磁盘目录。
6. 发布包包含 Windows x64 Node 运行时、前端已构建文件和生产依赖，不需要在目标 Windows 安装 npm、Node.js 或编译器。
7. 建议仅在可信局域网运行；跨网/不可信网络必须配置 HTTPS、访问限制。运行窗口不能关闭，否则服务停止。

### PowerShell 5.1 与文件编码

- `scripts/first-run.ps1`：**UTF-8 with BOM**（EF BB BF）；其中有中文提示，Windows PowerShell 5.1 需要 BOM 识别 UTF-8。
- `*.cmd`：纯 ASCII，避免 CMD 随系统代码页出现乱码；中文只放文件名或 PowerShell 内。
- `*.mjs`、`*.json`、`*.sql`、`*.ts`：UTF-8 **无 BOM**；PowerShell 5.1 如需写入这些文件，使用 `[System.IO.File]::WriteAllText($path,$text,(New-Object System.Text.UTF8Encoding($false)))`，不要使用默认 `Out-File` / `Set-Content -Encoding utf8`（5.1 默认会写 BOM）。
- 不将执行策略改为全局 Bypass，入口只针对初始化进程使用 `-ExecutionPolicy Bypass`。

### IP 访问控制的边界

- 未授权来源在 Node.js 的 TCP connection 事件中立即进行 `resetAndDestroy()`，不进入 HTTP 业务处理，也不提供登录页、健康检查、403 或其它 HTTP 响应；本机回环地址仍允许管理。
- 该操作发生在 TCP 三次握手完成之后：网络扫描仍可能看到监听端口。要使未授权 IP 在 TCP 握手前就被过滤，必须由宿主机 Windows 防火墙/网络防火墙进行 DROP；应用层无法自行屏蔽 SYN。
- IP 白名单修改后对**新连接**即时生效；已建立的长连接不保证自动断开，重连时强制核验。

## 电压等级字典的统一维护

管理员在 **系统管理 → 数据字典 → 类别：电压等级** 维护电压等级。基础台账不再重复出现电压等级入口，线路台账在“所属电压”字段直接引用此字典。该类别为专业字典数据，唯一存储在 `voltage_levels` 表，以保留原有线路外键和业务历史；其他普通业务字典仍由 `dictionary_items` 存储。

新增或编辑电压等级只需维护名称、排序和启停状态，编码由系统自动生成并隐藏。电压字典支持版本、排序、启用和停用；停用只禁止新的线路引用，不删除已有线路关联。电压字典使用当前完整结构直接建库，不保留旧表改造链。


## 首批审计修复与数据升级

当前数据库结构标记为 **v101（开发用一次性 schema）**；首次运行时直接创建完整表结构，无需逐版本升级。数量统一采用四位小数，API 和存储字段 `_scaled` 中的 10000 表示 1。金额仍按分计算。项目入库后保存需求快照，执行沿用批准范围；直接修改已批准项目仍然受保护；变更单可由编辑人员提交，再由具备批准权限的账号正式批准，产生新的不可变批准版本和当前有效范围/预算。在途范围发生变更时强制先结束或取消相关批次。

需求页现已支持草稿列表及恢复、更新草稿并以原批次提交、自定义字段共同值及逐基覆盖；需求详情支持附件上传下载和位置重新核实。操作模板可配置 text、number、select、boolean、date 类型，后端校验必填项及类型，并保存字段定义的历史快照。

执行 `npm run check` 验证构建、接口及当前 schema 建库；执行 `npm run test:browser` 验证真实 Chrome 流程、审计回归和非 localhost HTTP 来源。浏览器测试只使用临时数据库，不依赖正在运行的业务服务。浏览器默认使用 macOS Chrome，其他安装位置可设置 `CHROME_PATH`。修复范围和剩余功能见[审计修复记录](审计修复记录_2026-10-29.md)。

## 表单交互规范

项目中新增、编辑、配置、关联和业务确认时一律使用居中模态框，不在列表底部出现展开式输入表单；详情可以使用右侧抽屉，但修改通过弹窗操作。弹窗可以使用取消、右上角关闭、Esc 或遮罩关闭，保存成功后自动关闭，并在弹窗内显示校验错误。新建需求的导航及页面标题一律为 **“新建需求”**，多杆塔选择能力不需要写进页面标题。


## 线路工作台

基础台账以 **线路台账** 为入口，另有杆塔查询、档距查询。线路仅分主线与支线；支线归属主线并引用主线接入杆塔，可在接入点未确定时保存草稿，确认后录入内部杆塔及档距。新数据目录采用统一完整结构；线路、逻辑塔和物理塔仍各有稳定业务 ID，不按线路名称推测关联。

在线路内可单基或批量添加杆塔，支持连续编号、粘贴编号、逐行调整、空值填充或覆盖所选行、插入位置、共塔关联和实际换塔。公共属性修改明确显示关联线路；列表调序不会自动重写已有档距。内部线路、逻辑位置、实际杆塔编号自动生成，旧接口继续兼容已有编码。

档距业务参数只有 **档距长度（米）**，采用四位小数整数保存。起止杆塔选择、相邻候选预览、批量粘贴长度、未确定长度暂存、拆档和合档均在线路工作台完成。拆合档保留原记录；需求采用的档距版本和长度快照不会随当前台账变化。长度或端点改变后，需求需重新核实才能继续关联新项目。

勾选杆塔或已填写长度的档距，可直接发起需求。档距长度只作台账依据，不自动填成本次施工数量。档距需求支持草稿恢复、核实和项目范围引用。结构类型和用途建议值可在系统管理的数据字典维护，也支持按实际情况输入。

执行 `npm run check`、`npm run test:browser` 检查新库建表、业务接口、审计历史和浏览器流程；浏览器截图位于忽略提交的 `release/ledger-workspace.png` 与 `release/ledger-desktop-1280.png`。PMS 文件仍仅作字段和关系参考，本轮没有自动导入这些原表。

## 数据库存储与结构策略（2026-11-05）

- 所有运行数据位于项目/Windows 解压根目录的 `data/`。SQLite 数据库、WAL、SHM、附件和备份均在此目录；`dist/` 仅放前端构建结果和 Windows 发布 ZIP，不包含业务数据。
- 数据库模块为 `server/database/`，完整结构在 `server/database/schema.sql`，当前 Schema 版本 109。连接、初始化、事务、备份已经独立；业务模块内剩余的 SQL 仍需继续迁入 Repository，并未宣布彻底治理完成。
- 不自动升级、不覆盖旧结构数据库。旧版本不兼容时明确拒绝启动，要求先备份并按新结构单独部署。**不删除、不暗中转移历史数据**。
- `make dev` 与 `npm start` 默认使用根目录 `data/`。自动化测试通过临时 `DATA_DIR` 隔离；开发期 PMS 样本不自动进入 Windows 正式包。
- Windows 发布：`npm run package:win` 产生 `dist/sd-project-win10-x64.zip`；解压到本地可写目录，初始化管理员、启动、备份均使用解压根目录的 `data/`，覆盖程序升级时保留该目录。

项目变更操作：储备范围正式立项后，编辑人员创建变更单草稿并提交；当前仅管理员可批准/驳回。变更单批准会检查协议预算上限、有效需求承接量、历史完成量、已登记净结算、所有相关未关闭执行批次和原批准版本，并原子生成新批准版本。旧执行继续引用旧批准快照，新执行采用新批准版本；不累计重复占用历次预算。

## 框架、协议与操作记录维护（2026-10-30）

“框架与协议”提供独立 Element Plus 工作区，支持新增、详情、名称/年度/额度维护、删除、已删除筛选和修改历史。有正式项目时，名称可由编制人员维护，额度、年度及状态由管理员调整；删除由管理员确认。已有子项目的协议不能单独改挂框架，避免破坏项目归属。

框架额度不低于关联协议授权合计及项目批准预算，协议额度不低于关联项目批准预算及净结算。有关联的删除不会释放历史授权或连带删除项目；已有立项项目可继续实施和结算。删除预览包含关联状态校验标识，预览后出现新关联时须重新确认。项目详情继续显示已删除的框架/协议名称及历史归属。

管理员可在“系统管理 → 操作记录”新增手工记录，按内容/操作人/业务类型/状态分页查询，补充纠错说明，删除显示或恢复显示，并查看原始事实与处理历史。上述操作不覆盖原始审计事件，不撤销业务，不清理字典/框架删除决定。

主要 API：`GET/POST /api/frameworks`、`GET/PATCH/DELETE /api/frameworks/:id`，协议同路径规则；删除影响预览为 `GET /:id/deletion`，删除列表为 `?status=deleted`。操作记录为 `GET/POST /api/audit-records`、`GET/PATCH/DELETE /api/audit-records/:id`，恢复为 `POST /:id/restore`。服务端独立校验权限和版本。

## R02、实际费用与费用结算核对（2026-10-30，最新）

当前统一开发结构为 **107**，历史章节按当轮版本保留。用户明确确认实际费用首轮规则，详见 [费用授权与实施](../decisions/实际费用_首轮流程待确认.md)。

- 完成记录支持更正、撤销、详情及原始/历次历史，所有完成量、计划分配余量、变更和结算依据统一读取有效记录。已结束计划更正不得挤占后续计划已安排量；有效终结结算不能失去完成依据，完全冲销的终结凭证也不能在依据撤销后恢复净额。

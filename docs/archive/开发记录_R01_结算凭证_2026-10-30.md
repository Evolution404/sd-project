| 操作 | 用户入口 | API 与保护 |
| --- | --- | --- |
| 新增 | 项目级未归集凭证、计划内工作项结算与原凭证冲销 | 保持原 POST API 与同项目/范围/工作项/批准版本校验；新增校验真实日期及历史编号占用 |

| 详情与历史 | 详情/历史弹窗，原始登记、历次处理、经办人、时间、依据；正向/冲销互相查看 | `GET /api/settlements/:id`，保留原始完整内容及版本记录 |

| 删除 | 撤销弹窗，预览净额变化、涉及凭证，关联冲销另行明确确认 | `GET /api/settlements/:id/void-preview`、`DELETE /api/settlements/:id`；版本与关联预览提交重检，原始事实不删除 |

“撤销”是已授权的历史凭证逻辑删除：有效列表移除、不再计入净结算、不允许新增冲销，已撤销及全部查询仍可查看。不是停用，也不是永久清除。撤销正向凭证时若存在有效冲销，界面明确列出整组凭证并要求确认；服务端校验明确提交的全部凭证 ID 清单，只按所确认且未变化的预览在同一事务内追加撤销版本。不会静默级联删除其他业务对象。

## 核算与历史保护

- `project_settlement_entries` 保存原始登记，继续禁止 UPDATE/DELETE。`settlement_revisions` 与 `settlement_commands` 追加保存更正/撤销事实及幂等结果，均不可覆盖或删除。
- `settlement_current` 给出每条凭证当前版本；`effective_settlement_entries` 统一有效金额口径。计划工作项、项目、协议、框架、需求实施/结算基础状态、变更校验和资金对象额度校验都引用有效净额，旧版本不会重复累加。
- 原凭证项目、需求范围、计划工作项、批准版本、正向/冲销性质和对应关系不随更正改挂；已更正过的编号也不供其他凭证重新占用。未归集项目凭证继续独立统计，不自动摊入计划。
- 金额必须大于零、最多两位小数；日期必须真实存在。正向凭证金额不得低于其有效冲销合计，冲销不超过当前原凭证余额；当前项目预算与需求批准金额仍受校验。
- 结项后可修正资料、减少净结算、撤销原凭证；沿用既有禁止新增正向资金承诺规则，结项/退出范围/取消计划不允许通过更正金额或撤销冲销增加净结算。实际需要增加的业务须先具备有效正式依据，本轮不发明重新立项/重开审批流程。
- 每个更正/撤销请求使用唯一标识及完整内容指纹，相同内容重试返回原结果；重复标识换内容、过期版本或过期关联预览拒绝且事务回滚。普通新增重复凭证编号也不能重复入账。
- 管理员具有结算维护权限；编辑与只读账号可查询，后端拒绝越权更正/撤销，前端不呈现相应按钮。

## 验证

最终结果记录于《实施计划_2026-10-30_七工作包.md》本轮条目。新增 `tests/settlement-maintenance.test.mjs` 八个场景覆盖：

1. 两计划和未归集凭证、更正及四层资金汇总、原始事实不变。
2. 冲销更正、过期版本、并发更正和幂等重试。
3. 真实日期、精确金额、历史编号、归属及终结结算依据校验。
4. 预览后冲销变化拒绝、整组撤销原子性、已撤销历史及重复请求。
5. 实际项目变更调减预算后，撤销冲销不能越过当前批准额度。
6. 结项后资料纠错、减少净额、历史撤销及禁止新增资金承诺。
7. 编辑/只读账号权限、另一进程重新打开同库后金额与原始事实保持、外键与完整性检查。
8. 部分实施、结束释放余量、新批准版本及原凭证/实施历史的独立性。

扩展真实 Chrome 主应用验收：登记100元→冲销40元→另登记30元→原凭证更正140元→净额130元→明确撤销140元及关联40元冲销→净额30元；返回项目、刷新页面后汇总与历史一致。额外验证缺少更正依据、超预算服务端错误在金额字段附近显示。截图：`release/settlement-voucher-history.png`、`release/settlement-voucher-void-preview.png`（按项目规则忽略提交）。

# Schema 113｜价格特征与参考价格交互优化实施记录（2026-11-09）

## 业务边界

- 价格特征仅描述需要现场补充的额外计价因素，不复制线路电压等级、塔型、停电方式、作业规格、工作量等已有正式事实。
- 作业操作版本只声明额外价格特征的正式身份、版本、是否计价必需；新配置的数据来源统一为现场填写。旧版 `asset/either` 仅供历史正式版本继续读取，不能新增同类引用。
- 一条专业需求可以登记而暂时未完整计价；确认正式参考报价前必须补齐该操作类型的所有计价必需特征。每个作业位置保存自己的取值。
- 参考价格中的内置适用条件与额外价格特征条件共同匹配，计价引擎、公式和结果仍由应用层负责。无适用规则或者规则重叠时不能自动选择。
- 已发布的字典、操作、需求、价格规则和正式报价的版本与计算证据不被后来的修改覆盖。

## 结构复用

不新增业务主表、不改变既有字段身份、不改动 Schema113 SQL。复用：

- `dictionary_item_versions.fields_json`：枚举 `{kind:'enum',values:[...]}`（非空、无重复）；整数 `{kind:'number',min?,max?,unit_id?,unit_version?}`（可选整数范围、可选已有单位及正式版本）。
- `operation_versions.pricing_features_json`：`factor_id`、`factor_version`、`source:'manual'`、`required`。
- `demand_version_work_locations.site_features_json`：逐位置的 `factor_version` 与实际值。
- `reference_price_versions.additional_conditions_json`：枚举精确匹配、整数区间匹配。
- `reference_price_versions` 及 `reference_price_evaluation_lines`：已有计价模式、金额与不可变计算依据。

无独立单位冗余主数据。整数单位版本固定引用已有单位字典；即使单位随后改名，旧版本仍按旧引用解释。

## 用户界面

- 价格特征：独立的枚举选项列表和整数范围/单位编辑器；删除台账来源字段入口。
- 操作类型：原「基本定义 / 录入模板 / 附加字段」基础上新增「计价所需信息」标签；普通用户不需要选择台账/人工/either 来源。
- 参考价格规则：改为「基本信息 / 适用条件 / 计价方式」三个标签；8种计价模型不变，按所选模型动态显示参数。
- 专业需求：逐作业位置显示额外计价条件；内置台账信息继续由业务服务自动读取；必需但缺少的特征在核价时显示准确字段名。
- 规则重叠：保存时针对同操作定义版本、单位和计价作用域做显著重叠提示；报价时仍须明确指定规则并记录选择依据。

## 服务端校验与 Excel

`server/domain/price-features.mjs` 统一枚举、整数范围、条件格式及匹配范围重叠判断，供 API 与 Excel 使用。JSON 仍属于正式完整版本；没有把价格计算或匹配下沉到 SQL 触发器。

Excel 整数值不能把空文本自动解释为0；越界、非法枚举值按所在工作簿行返回错误。需求保存不强制全部计价必需信息即时到齐，但正式报价确认必须完整。

## 验收

- 价格特征：空/重枚举拒绝；整数区间、单位版本合法；内置属性重复拒绝。
- 操作类型：只能新增现场填写的额外价格特征，且同操作不可重复声明。
- 专业需求：逐位置值类型、枚举、整数范围、正式字典版本受校验；需求暂缺计价信息合法。
- 参考价格：缺项不能确认正式完整报价；适用条件匹配正确；规则重叠发出警告并要求选择依据；正式版本计算结果与旧历史隔离。
- 前端：枚举、整数、操作计价标签、参考价格三个标签的实际浏览器交互。

测试命令：`npm run build`、`npm test`、`node tests/e2e/masters-browser.mjs`、`node tests/e2e/independent-ledger-browser.mjs`，以及可选全套浏览器回归 `npm run test:browser`。

# 2026-11-17 验收矩阵核对与项目财务分页收口

## 范围与依据

承接用户“后续还有什么工作”和“继续执行”，核对P0～P9现行代码、14条用户旅程、历史阶段记录及2026-11-16双项目实测证据。唯一开发分支为codex/full-rewrite-20261110，起点622fde8。所有新增测试使用独立临时DATA_DIR。

当前业务规则要求需求整条承接、批准草稿采用需求完整正式版本、批准候选在批准时原子取得归属、已结项财务冻结、最新版正式批准范围禁止解绑。P10维持当前冻结状态。

## 实际问题与修复

项目内真实费用和结算列表以及费用核对列表原先调用完整集合，再由HTTP执行内存筛选排序分页。结算集合还逐单读取根身份、正式版本、草稿、审核、费用明细和解决量。该路径与当前数据库白名单分页要求不一致。

新增数据库模块finance-lists Repository。费用和核对使用SQL筛选、排序、计数与LIMIT/OFFSET。结算先取得当前页身份，再批量读取其正式版本、草稿、当前审核、费用明细和解决量。项目限制通过绑定参数精确匹配，客户端筛选不能改写归属条件。已有真实费用版本ID、费用根身份、结算根身份、冻结科目名称、审核意见、草稿编辑令牌和解决量继续按现有契约返回。

删除过滤按真实稳定身份执行。费用使用entry_id，核对使用record_id，结算使用根id。费用作废、审核退回、正式版修订草稿和管理员逻辑删除均由真实HTTP回归检查。正式总额仍由财务汇总用例计算。

列表查询内部ListSource增加绑定参数及删除身份列配置，字段名只来自服务端固定定义。全局结算及核对列表与项目内正常入口共用相应数据库查询。完整导出和正式历史由原有显式业务用例提供。

性能时间由宿主单次测量记录，门禁以查询次数、分页数量和正式事实正确性为依据。

四角色专项扩展为同一项目连续办理。编辑通过界面编制包含20处原需求及5处完整候选的正式变更，审核批准后建立候选归属。管理员再编制移出候选的正式变更，审核批准后释放归属。只读账号服务端越权返回403，并可回查三版批准历史。候选阶段及移出草稿阶段的归属分别保持对应正式事实。

浏览器另外测量五个当前常用入口，项目列表打开详情、项目详情进入财务、打开完整历史、跨项目费用打开记录、跨项目结算打开记录。每段均一次业务点击，并保存实际HTTP请求及耗时。该测量仅覆盖上述明确起终点。历史版本缺少同口径实测点击基线，完整旅程前后操作次数比较保留为未取证，不填写推算降幅。

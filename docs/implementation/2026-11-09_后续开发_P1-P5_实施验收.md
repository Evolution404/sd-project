## P2 列设置拖动

评估 SortableJS 原生适配与 vue.draggable.next。采用 SortableJS 1.15.7（MIT），直接管理列设置列表手柄，避免引入额外 Vue 包装组件。正式来源为 https://github.com/SortableJS/Sortable 和 https://github.com/SortableJS/vue.draggable.next 。锁定类型包1.15.9。拖动结束先还原Sortable的DOM变动，再让Vue按稳定key重排。关闭面板和卸载均清理实例，减少动态效果模式关闭排序动画。

删除逐行上移/下移按钮，手柄可聚焦，方向键、Home、End完成排序并保持焦点，aria-live播报位置。隐藏、固定、宽度使用原偏好对象，正式审批三项必需列保持不可隐藏。列顺序、隐藏和固定的真实鼠标拖动、键盘及刷新持久化浏览器专项通过，构建和严格UI通过。最终全套测试统一复跑。

## P3 正式页面路由

采用 Vue Router 4.6.4 的 Hash 模式，满足本机HTTP、内网和离线ZIP相同入口。HTML5 History需要部署回退处理，当前内网系统无需SEO，Hash不增加服务器部署要求。官方依据为 https://router.vuejs.org/guide/essentials/history-mode 和 https://router.vuejs.org/guide/essentials/navigation 。该选型由本轮按部署场景确定。

八个主模块全部路由化，需求、项目/财务、四类台账及其他主数据详情使用稳定身份。系统用户/IP/审计分类使用路径，设备正式历史使用history=1。深链接登录、刷新、前进后退均重新通过真实API加载。管理员页面渲染前检查身份，服务端原权限与版本约束继续执行。不存在的路径和业务身份分别显示明确状态，旧详情不会保留在无效身份下。

查询规则为搜索、页码、排序、列筛选、删除范围以及项目标签页写入query，修改查询使用replace，进入详情/返回列表/切换分类使用push。详情携带列表上下文，返回恢复页码和查询。分类新进入重置查询，浏览器后退恢复此前分类查询。财务三类列表分别保存查询和分页。列显示/固定/宽度和主题仍是localStorage偏好。编辑及历史弹窗是当前页面临时状态，刷新会丢弃未保存编辑。正式历史事实继续由服务端读取，不从URL补造。

# UI 交互审计：侧栏、表格、常规操作逻辑

日期：2026-11-09；本轮仅修改 sd_project 主仓库界面及其测试，不变更 Schema113、正式 data/ 与业务身份。

## 已修复

1. 取消“调整侧栏宽度”按钮和弹窗滑块，直接拖动左侧导航右边缘。默认240px、最小208px、最大400px。折叠时不可拖，展开后恢复原宽；双击恢复默认值，键盘左右箭头以8px、Shift加速32px、Home/End至边界。宽度记忆、pointer cancel/blur 清理和无障碍分隔条语义已实施。拖动过程中关闭网格过渡，避免阻滞。
2. 表格列宽此前虽然使用可调整属性及保存事件，但 Element Plus 仅在表格启用 border 时响应鼠标拖拽。现已启用该属性，默认宽度结合表头文字宽度、排序图标、筛选按钮及内边距计算，确保表头初始不换行；用户可拖边界调整、缩窄后标题省略、宽度按业务表保存。数据区可横向滚动，不制造页面横向溢出。
3. 搜索/包含已删除条件变化后重置当前页为1；系统管理标签切换先清除上一标签的排序、筛选及分页再请求数据，避免误用旧页码。
4. 新增真实浏览器拖动测试，验证指针、键盘、双击、折叠、刷新记忆、默认标题可见、列宽拖动后记忆、三档屏幕宽度，以及第2页输入搜索后的复位。UI 契约测试防止列宽拖动前置条件被移除。

## 继续审计后发现的非常规交互

| 优先级 | 已有代码现象 | 偏离常规体验 | 建议与状态 |
|---|---|---|---|
| 高 | 设备台账行操作最多同时列出查看、编辑、更正历史、历史、删除；独立结算单最多一行并排多项操作，固定列宽达530px | 操作按钮挤占数据面积；任务栏拥挤 | 待做：主要动作直接展示，其余收纳到“更多”菜单，保留全部权限限制与确认 |
| 中 | 表格自定义列只能通过“上移/下移”排序 | 多列时逐条点击效率低 | 待做：拖拽重排列，同时保留键盘替代交互 |
| 中 | App 使用内存 active 状态切页面；需求、项目、台账详情用局部 detail 状态替代路由 | 浏览器后退/前进未必恢复列表与详情，无法共享精确详情链接 | 待规划：权限控制的前端路由与深链接，不能破坏历史版本权限 |
| 中 | 复杂结算/审批页面行内放置大量操作，流程层级不够突出 | 正式提交、审核、修订和删除的视觉层级不清晰 | 待专项治理：区分主操作、次操作和危险动作 |
| 低 | 表格列设置中大量上移/下移按钮，部分历史视图仍有技术字段的兜底文案 | 信息密度偏高，降低业务人员可读性 | 待专项文案与组件密度审计 |

本轮按用户明确要求修复两个核心问题，并一并修复分页筛选逻辑；其余跨流程修改列为后续路线，不能视为已完成。

## 验收边界

执行 npm run check、npm run check:schema、npm run test:browser、npm run test:performance。使用独立临时测试数据库；不得改动正式 data/。Windows10/11 原生显示及触控板、屏幕阅读器测试仍需目标设备验收。

# UI 全系统复审与治理记录（2026-11-13）

## 范围与原则

本轮在 `codex/full-rewrite-20261110` 分支对 12 个主业务入口及相关项目详情、费用结算表单、表格和通用操作进行实测。覆盖浅色/深色主题、1500/1280/960/760px 四档宽度、管理员/编辑/审核/只读角色。只修复有明确证据的交互及呈现问题，不新增 P10 功能，不改变业务正式版本、历史和权限模型。

## 已修复问题

1. **主题一致性**：将深色状态下的 Element Plus 表格单元格、文本框、下拉框、弹出层由默认近黑色调整为和系统卡片统一的深蓝灰色；适度收紧顶栏、标题和面板留白，数字使用等宽字形，保留原有明亮蓝色强调与全局色板。
2. **公共表格反馈**：显示“本页 N 条/正在加载”，启用筛选时明显标记列筛选按钮并可一键清除；保留稳定的无障碍名称，使用 `aria-pressed` 告知筛选状态。列设置按钮、表头完整标题提示一致。列宽拖动、筛选、排序、隐藏与固定继续使用既有 BusinessTable 单一入口。
3. **项目办理操作**：项目详情顶部将主要业务办理按钮与资金归属、档案和历史管理按钮分区；窄屏自动折行，保留角色禁用原因。尚未批准的项目明确标注“尚未批准”，禁止误解为零预算。
4. **需求状态说明**：退回确认文本明确仅针对未关联子项目的需求，与后端“已关联禁止退回”裁决一致。
5. **费用核对跨页选择**：原表单直接使用实际费用和结算单的当前 30 条列表，导致超出当前页的合法记录无法选入。现改为独立远程候选检索，明确选择费用正式版本和已批准结算明细版本，不再依赖无关列表的分页、排序或筛选；异步请求有顺序校验，保留已选对象。
6. **异常与登录**：费用读取失败时清空过期项目数据、展示常驻错误及重试入口；跨项目财务列表失败时同样不留旧行。登录表单 Enter 提交和按钮点击共享唯一提交路径、防止重复登录请求；退出失败可见提示。

## 验收证据

- `npm run check`：完整严格 TypeScript 编译、架构边界、API/领域/Excel/前端测试；
- `npm run check:schema`：475 项数据库设计契约、78 张 STRICT 表、27 个视图、252 个触发器；
- `npm run test:performance`：4 项 SQL 查询数量及规模基准；
- `tests/e2e/visual-audit-browser.mjs`：12 个模块、3 类详情、8 类弹窗、四档宽度、两种主题；
- `tests/e2e/finance-cross-page-choices-browser.mjs`：35 笔费用、35 期结算，首 30 条之外的选择及正式核对保存；
- `tests/e2e/finance-roles-browser.mjs`：包含角色权限及接口失败后清空旧记录、成功重试；
- `tests/e2e/auth-login-enter-browser.mjs`：回车单次登录及安全退出；
- 全量浏览器统一入口：`npm run test:browser`。

测试隔离在临时数据目录，不操作正式库。Windows 实机验收与 Mac 上的包完整性检查分别认定。

## 后续观察项

- 大型项目内的费用及结算候选现在支持按关键字远程检索，但 HTTP 分页背后仍使用现有的项目内记录聚合；若项目达到超大规模，应单独以数据库定向 SQL 搜索替代，不在本轮 UI 改动中引入数据库双轨实现。
- 部分业务表格长编号仍依赖悬停提示及列宽拖动展示，后续可按实际岗位使用频率评估“复制编号”入口。
- 费用与结算包含多张独立业务表，当前保持原有完整流程，未擅自以折叠或隐藏模块破坏原有连续操作与验收脚本。

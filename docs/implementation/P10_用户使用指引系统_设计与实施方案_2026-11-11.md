## 一、二次审计结论和实施裁决

**结论：四层设计可行且合理，但原方案存在过度扩张、误写正式数据、引导锚点脆弱和多人演示库串写等风险，需按本文件修正。**

当前系统为Vue3、TypeScript、Vue Router、Element Plus 2.14.x。已确认当前安装包带有ElTour、ElTourStep，**无需新引入独立导览UI库**。使用现有Element Plus UI组件，跨路由、权限与完成条件采用轻量协调模块。

| 评估维度 | 原设想的实际风险 | 确定方案 |
| --- | --- | --- |
| 全按钮说明 | 仅扫描DOM会遗漏弹窗、v-if、不同角色、更多菜单和表格行；装饰性控件虚增分母 | 采用**语义动作注册清单+稳定标识+角色/状态覆盖门禁**；同种行内操作共用一条说明 |
| 交互式教程 | 将12模块所有按钮排成一条长Tour，复杂且易失效 | 四层：即时帮助、短页面导览、模块任务、跨模块分段课程；每段可暂停恢复 |
| 浮层技术 | 新库带来样式许可、打包及依赖风险 | 优先ElTour/ElTourStep，配套ElDrawer/ElTooltip/ElDialog；不自造整套导览组件 |
| 正式数据安全 | 引导代点批准、删除、结算可能修改真实业务 | **引导代码不自动发起任何业务写请求**；用户自主操作仍走现有表单权限和确认；完整练习在隔离训练实例进行 |
| 多人培训 | 当前演示ZIP共享SQLite，学员并发写入相互干扰 | **训练实例=独立DATA_DIR+独立进程/端口**，一人或明确小组一库；不把共享demo视为个人练习沙箱 |
| 权限、状态 | 点击完成不等于正式批准成功 | 说明和练习检查点依据当前Actor/权限、服务端正式事实、版本与业务历史，绝不提升权限 |
| 学习进度 | 立即新建培训数据库和复杂服务将产生技术债 | 首版账号隔离localStorage；不改Schema113，明确首版不跨设备同步 |
| 动态UI | 模态框portal、虚拟/分页列表、深层滚动、路由变化使锚点错位 | 语义锚点、活动弹窗作用域、有界等待、文字退路、焦点恢复和草稿保护 |
| 离线 | 外部教程、CDN和网络服务违反部署约束 | 教程文本和图文与dist/web一同打包，Windows正式及演示ZIP断网可用 |

官方组件开发参考：https://element-plus.org/zh-CN/component/tour 。链接仅供开发者查看；**产品运行不能依赖访问此网站。**

## 二、产品目标与非目标

### 2.1 最终用户能力

1. 所有登录后业务页面都有统一“使用指引”入口，可随时查看当前页面作用、业务操作和下一步。
2. 用户可以查询每类有业务意义的按钮、菜单、批量操作、筛选、行内操作及关键字段的用途、权限、前置条件、操作结果、风险和失败原因。
3. 系统现有12个主入口全部配置短导览和实际模块任务教程，Excel作为跨模块专题提供导览。
4. 存在一套可分段执行的全系统业务课程，从基础配置到项目结项、历史追溯和Excel纠错。
5. 独立训练环境允许学员亲手执行真实业务服务，完成条件由服务端已提交的正式业务事实验证。
6. 用户可退出、暂停、继续和重学，保留业务列表与未提交草稿；可关闭首次引导提示。
7. 严格离线兼容Windows10 x64正式及演示包。

### 2.2 四层设计

- **L1 操作说明**：按钮即时说明、禁用原因及合法下一步。
- **L2 页面漫游**：在当前页面/弹窗解释布局、按钮及操作步骤，建议每个5～10步。
- **L3 模块/跨模块任务**：小课程与分段检查点，而不是数百步单一Tour。
- **L4 安全演示实操**：经服务器确认的独立训练实例，使用现有领域服务而非假API。

### 2.3 非目标与产品边界

不新建业务审批引擎、平行正式业务状态机、财务计算逻辑、PMS兼容、AI自动代办、网络知识库、积分/考试/排行榜或复杂培训管理。首版不要求用户培训合格才能操作业务，不强制跨设备学习进度同步，不为教学增加第二套真实业务流水。

用户已裁决：当前开发阶段没有正式生产业务数据，不做旧数据库/旧接口兼容；**但新系统正式版本、审计、附件、权限、事务和备份恢复仍必须保护**。

## 四、用户界面与交互

### 4.1 帮助中心

在App顶部操作区增加单个“使用指引”按钮，窄屏可用有aria-label的帮助图标。使用ElDrawer展示：
1. **当前页面**：一句话介绍当前模块、关键业务概念、主要动作、“开始当前页面导览”。
2. **操作搜索**：输入“入库、结算、预检、确认需求”等，检索中文名称和同义词，看到用途/适用权限/禁用原因。
3. **模块课程**：现有12入口的任务式课程，支持开始、继续、重学、查看进度。
4. **完整业务流程/练习**：L01～L12主路线、角色交接、前往独立训练实例。

首登只做一次轻量可关闭提示；不覆盖原工作台，不强制用户先完成教程。

### 4.2 控件说明

用户主动开启“认识页面”后突出当前页面的重要操作，点击说明与真正执行按钮行为分离，不能因查看说明触发危险动作。

每条说明包含：名称/作用、何时使用、谁能操作、当前是否可用和原因、用户需填写的事实、操作后的正式结果、审核/历史/删除影响、常见错误及相关课程。

全部用户可执行的**语义操作类型**须有说明：标题按钮、列表、行内、弹窗、更多菜单、批量、保存、取消、下载、筛选、列配置、返回以及管理操作。相同行操作复用一个actionId；隐藏和禁用动作通过状态矩阵登记。纯装饰性元素可注明原因豁免，不计入操作总数。

### 4.3 页面短导览

ElTour负责呈现浮层，GuideHost负责跨路由、弹窗、目标挂载和步骤条件。提供上一步、下一步、暂停、跳过、退出、重学。打开弹窗、深层滚动、v-if变化后需要有界等待目标，失败提供“重试定位、查看文字说明、跳过、退出”，不得无限等待或擅自操作第一条记录。

**正式业务环境引导自身不得执行写入。** 如果用户主动通过原按钮办理，必须继续经原权限、业务校验和确认。课程完成有“已了解”和“已在训练环境练习成功”两种不同结果。

### 4.4 无障碍与非侵入

ElDialog append-to-body的目标要在当前活动弹窗中定位，不能误指向背景同名控件。支持键盘Tab/Escape、焦点还原、reduced-motion、触控、深浅色和760/960/1280/1500宽度。不得出现挡住保存按钮、吞掉原事件、破坏列表筛选、自动关闭带草稿弹窗等问题。

### 6.2 声明式契约示意

    type GuideAction = {
      id: string;                       // 例：demands.create / projects.approve
      module: string;
      title: string;
      aliases: readonly string[];
      purpose: string;
      prerequisiteText: string;
      consequenceText: string;
      courseIds: readonly string[];
    };

    type GuideStep = {
      id: string;
      title: string;
      description: string;
      routeName?: string;
      actionId?: string;
      kind: "explain" | "navigate" | "input" | "observe" | "verify";
      permission?: string;              // 仅用于提示，不替代真实服务端鉴权
      onMissing: "wait" | "explain" | "skip" | "stop";
      checkpointId?: string;
    };

严格TypeScript，不引入any、无类型万能对象、任意执行脚本、任意可写API URL或第二套工作流引擎。帮助文案作为安全文本渲染，禁止未经审查的v-html。

### 6.3 稳定锚点

在业务操作根节点使用稳定data-guide-action属性，匹配语义actionId，不依赖中文按钮文字、DOM第几个节点或易变CSS类。一个表格行操作可能有多份DOM实例：优先当前选中行、活动详情和合法示例；不能唯一确定时只展示文字说明，绝不自动触发某条记录。

v-if按钮不可见时说明为何不可用，ElDropdown未展开时先告知打开菜单（在只读导览中不替用户点击），活动ElDialog通过独立作用域定位。异步加载最多有限时间，过期降级为文字步骤；仅导览活动时局部订阅状态，不永久全DOM轮询。

### 6.4 状态机

推荐idle、preparing、explaining、waiting-user、verifying、paused、completed、aborted。事件start、next、previous、targetReady、targetMissing、serverVerified、pause、resume、logout、finish。

每个课程courseId、courseVersion与stepId稳定；恢复只保存学习状态，不保存业务草稿或真实业务数据。路由变化、登出、权限变化、403/404/409/422或网络断线安全暂停/退出，给出可理解原因。已了解和已实操通过不能混淆。

## 七、学习进度与隐私

**首版不修改Schema113。** 使用localStorage，仅保存按Actor.id与课程版本隔离的课程ID、最近步骤、已学习/已实践状态、首次提示选择；不得存密码、token、项目事实、附件、真实金额等。登出时终止运行态并释放监听；可提供“清除学习记录”入口。

**首版不保证跨设备同步。** 未来用户确需跨设备进度再单独新增最小用户偏好Repository、读写API及必要Schema，并进行鉴权和测试；不得把学习进度做成正式业务审计或历史账。

### 8.2 正式环境与训练实例边界

**普通正式环境**只允许阅读、定位、跳转和用户自己经正常流程办理。引导功能本身没有写业务的权限或执行器，绝不能自动提交、撤销、审核、结算、删除、重置。

**训练环境**必须与正式及其他活跃演示数据库隔离，使用真实业务服务：
1. 一名学员或明确小组分配一个训练实例；每实例独立DATA_DIR、进程和端口。目录由后端受控规则生成，不允许用户提交任意文件系统路径。
2. 是否是training环境由服务器可信配置或受控只读环境能力接口返回，绝不凭客户端URL、query或localStorage自称训练环境。
3. 从现有种子数据机制生成训练数据，但不得覆盖正式库、共享演示数据或其他活跃实例。
4. 学员使用真实训练账号，保持原权限与登录。公开的演示程序不得在前端源码中写死可直接用于管理员登录的口令。
5. 重置训练实例前必须确认并安全处理活动连接，只清理本实例数据。多人同时练习须创建各自实例，不共享一个SQLite写入。
6. 每个完成步骤都要由服务器已提交的正式业务事实验证，不允许“点击了下一步”就算练习成功。

首版可先提供**单用户独立训练实例**；若用户将来要求多学员并发集中培训，另开发最小实例分配、配额、清理与权限管理，不虚报已经具备。

### 8.3 可能需要的最小后端扩展

优先前端静态教学+现有授权GET，不新增业务写接口。仅当缺少可信训练身份时，允许提供一个受控、只读的运行环境能力查询（例如GET /api/runtime-capabilities），不暴露口令、磁盘路径和敏感配置。复杂用户培训进度后台不是首版范围。

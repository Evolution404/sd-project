## 二、结算工作表设计与实测依据

原先重复「添加解决需求 → 选择需求 → 选择位置」卡片已从 `FinancePanel.vue` 移除，新增 `SettlementWorkSheet.vue` 并默认展开。按项目当前关联需求全量列行，冻结批准版本覆盖的位置可编辑，其他只读；冻结单位、数量精度、批准量、历史已生效量及余量按版本查询。服务器入口 `/projects/:id/settlement-worksheet` 仅使用 1 条单对象查询和 3 条集合查询，不读整套批准历史，按项目范围 + 需求 ID + 作业位置 ID 拼接稳定主键以避免展示行号串行。

- 正常工作表保留本次量的默认展示 0；仅编辑过或历史需保留明细提交，零值明细及完成依据可明确保存。按项目总额和按子费用共享同一工作表，结算金额在独立字段。
- 可编辑「本次解决量」和「完成依据」；Tabulator 原生筛选、排序、列宽及框选；工作表级校验与固定比例精度防止单项/Excel 整块粘贴一半成功；一组粘贴是一个撤销步骤，另含 Cmd/Ctrl+Z、重做、Enter 编辑和错误位置跳转。
- 切换采用正式批准版本时预检已填写行在目标冻结范围的去留，以及单位、精度或批准量变化；取消切换不改变草稿。网络/加载失败保留已填值，保存走现有结算命令；正式审批、退回与结项、冲突检查留在服务端。
- 历史结算修订排除本单此前生效的解决量（否则会重复计算）；冻结单位按 `unit_id@unit_version` 分别汇总，不跨单位累加。超批准余量列出差额，是否准予保存依原服务端规则而非前端擅自禁止。

## 字段处理结论

15类主数据都具备不可变UUID。线路、物理杆塔、逻辑杆塔的编码没有独立现场业务含义。单位、优先级、项目类别、电压、作业对象、操作、物资、框架、协议、组织及参考价格目录的code亦为内部身份。价格特征code同时是不可变特征JSON及规则条件的正式键。需求、项目和结算另有系统单据编号，供查询及历史核对。

全部15类主数据编码在服务端分配UUID后生成，客户端传入的新建编码不参与身份分配。变更已有编码被拒绝。需求、项目及结算编号使用本实体完整UUID生成，保持正式历史不变。附加现场字段键允许缺省，由服务端生成。档距本来就仅使用UUID，无额外编码。

本轮数据库删除字段数为0。现有编码列仍受唯一、不可变及引用约束，价格特征键和历史快照已使用其正式值。保留这些受约束的历史身份，避免重写既有事实或使当前库结构指纹失效。新增对象的编码均由服务端控制，没有第二套可变编码来源。

已删除15类主数据的技术编码录入项，以及需求、项目、结算的手工编号录入项。移除Excel中的操作编码、设备编码、物资编码、价格特征编码和项目编码匹配列。维护文件的单据编号、UUID和原版本为隐藏保护信息。移除来源外部记录号的可编辑API与Excel字段，来源录入方式由服务端按在线或普通Excel决定。

source_records中的通用来源方式和旧原始记录号列保留用于历史事实。新来源的external_record_id固定为NULL，当前代码没有外部记录匹配、映射或专用导入能力。历史来源更正继续保留原始证据。

## 创建与历史

| 流程 | 原输入与步骤 | 当前输入与步骤 |
| --- | --- | --- |
| 线路 | 编码、名称、电压，3项必填 | 名称、电压，2项必填，1次保存 |
| 普通杆塔 | 物理编码、逻辑编码、所属线路、物理关联、杆号，跨2张表单 | 所属线路、杆号，2项必填，1张表单、1次保存 |
| 共塔多回 | 分别维护实体与回路 | 明确选择共用已有实物，保存新回路，实体数量不增加 |
| 同号但不同实物 | 容易重复创建或误关联 | 展示候选线路及杆号，用户确认不同实物后才新建 |
| 整基更换 | 分开维护关联容易遗漏 | 核对全部回路，事务内新建实物、修订全部关联、退役原实物并留审计 |

线路必填减少1项。普通杆塔上述身份和关联录入减少3项，保存次数从2次减为1次。塔型、高度、资产铭牌、经纬度等真实事实可按需填写，不编造未知属性。线路排序自动取得当前末位。操作的作业对象类型从所选标准对象推导。

同线路同号重复被拒绝。不同线路同号需确认共塔或不同实物，确认决定有操作者及时间。整基更换校验原实体版本及完整回路版本集合，新增、更换和退役在同一事务内完成。测试确认旧需求位置、已确认参考报价和旧回路版本继续引用原实物。

选择器展示线路名称及电压、杆号、物资型号规格、框架年度、协议真实合同号等业务属性。同名对象显示核对提示。Excel遇到无法唯一确定的同名、同号、项目需求描述时拒绝自动关联。台账页签切换清空旧行，列表请求按顺序接收，并使用稳定行标识，防止旧列表行在异步切换中对应到错误对象。

现场特征按其正式定义版本展示中文名称，后续改名不会把旧特征显示为新的名称。常规详情和历史隐藏技术身份，实物关系确认与更换决定采用中文展示。

## 独立性与永久门禁

正式server、web/src及scripts中没有专用外部系统字段、接口、映射、别名、导入器或兼容实现。本轮清理SQL中的残余专用导入设计注释，历史文档追加明确废止声明，README、AGENTS和开发规范指向现行裁决。原先已删除的专用工具保持历史归档。

check:independent-input检查产品源码及文件名、目录元数据和Excel列。任何专用集成标识、要求客户端填写的主数据code或重新加入的Excel编码列都会使门禁失败。该检查纳入check和package:win。开发规范要求每个新增输入先评估自动生成、关联和推导，保留必要真实事实及授权判断。

数据库对象指纹与1e0cc62的sqlite_master逐项一致。SQL仅修改CREATE语句外的注释。保持77张STRICT表、27个视图、250个触发器、78个显式索引、728字段。继续使用统一Repository、256条LRU语句缓存、外键、不可变正式历史、逐单据保存点、整批事务及幂等收据。

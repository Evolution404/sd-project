# 作业对象双维度数据库重构与验收（2026-11-12）

## 用户最终裁决

作业对象管理两个独立且必填的分类属性：**对象位置**（本体／通道）及**归属单元**（物理杆塔／逻辑杆塔）。本体指杆塔本体上的作业；通道指杆塔之间线路通道上的作业。归属单元确定同塔多回时按实体杆塔还是每条线路的逻辑杆塔计算作业位置与识别重复。**只由作业对象维护，操作类型不得再次配置。**

| 作业对象 | 对象位置 | 归属单元 | 计量身份 |
| --- | --- | --- | --- |
| 杆塔基础 | 本体 | 物理杆塔 | 共塔多回按一基实体归属 |
| 防鸟装置 | 本体 | 逻辑杆塔 | 各回线路独立归属 |
| 树木 | 通道 | 物理杆塔 | 按物理杆塔身份归属 |
| 导线 | 通道 | 逻辑杆塔 | 按线路的逻辑杆塔身份归属 |

计量单位由操作类型维护，具体数量由需求逐位置维护。档距是通道作业可使用的具体点位信息，不是第三种归属单元。

## 权威数据库设计

1. work_objects 只保存稳定技术身份；work_object_versions 记录对象正式定义及 object_position（body/corridor）、attribution_unit（physical_tower/logical_tower）。CHECK、历史追加与正式引用禁止非法值或原地修改。
2. operation_versions 去掉旧的 work_target_type、allow_tower、allow_span、default_location_kind 四个重复字段。增加 work_object_version_no，与 work_object_id 组成正式对象版本的复合外键；操作版本只记录采用的对象正式定义，**不冗余**保存对象两个维度。保留 default_unit_id 和 default_unit_version 独立计量。
3. 专用 Repository 从被采用的对象正式版本投影对象位置与归属单元给操作应用服务与 UI。对象后续改版不能导致历史操作的语义漂移，发布操作新版采用对象当前定义须显式 opt-in。
4. demands 及完整 demand_versions 快照冻结采用时的对象位置、归属单元，数据库触发器核对采用的正式操作与对象历史；物理杆塔和逻辑杆塔具有不同身份及去重规则。正式需求、价格、批准、结算、审计继续不可变与可追溯。
5. 只有通道且逻辑杆塔归属时可选档距作具体点位；归属单元仍为逻辑杆塔，不能将对象位置、归属单元和具体作业点位混淆。

权威 DDL：server/database/schema/schema113.sql。当前为纯开发阶段，不建立旧 schema/API/字段兼容迁移。每次测试以隔离库初始化，保留新系统自身正式历史的完整性。

## UI 与业务流程

- 作业对象基本表单：名称、对象位置、归属单元。没有在操作类型中复制分类。
- 操作类型变为四页签：基本定义（含作业对象和固定计量单位）、录入模板（建议数量、验收标准、提示）、附加属性、正式版本与引用。取消旧“作业范围与计量”。
- 操作类型可显式采用作业对象当前正式版本，默认保持已采用的正式历史版本。
- 专业需求根据操作类型所采用对象版本选择真实物理/逻辑杆塔，避免共塔多回漏算与物理基础重复。导线通道逻辑归属可额外指明档距点位。
- 演示防鸟/绝缘子为本体＋逻辑；导线为通道＋逻辑；物理作业单独配置本体＋物理，禁止仅通过字段默认值猜测分类。
- 设备位置选择器另按实体动态表头，真实服务端自然排序和过滤，避免旧复合列与无效图标。

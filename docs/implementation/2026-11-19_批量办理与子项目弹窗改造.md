# 2026-11-19 批量办理与子项目弹窗改造

用户确认按设计方案执行。专业需求与子项目清单都在勾选后显示操作栏。表头复选框只作用于本页，翻页及打开详情保留选择，变更筛选清空并明确反馈。每次最多办理或导出100条。已删除记录保留查询入口，所选导出要求先取消勾选已删除记录。

| 清单 | 直接操作 | 办理条件 |
| --- | --- | --- |
| 专业需求 | 导出所选 | 导出可维护的中文工作簿，按所选需求身份查询 |
| 专业需求 | 批量确认 | 在待确认页勾选，具备需求确认权限 |
| 专业需求 | 批量关联子项目 | 在待承接页勾选，选择一个允许普通承接的项目，按整条需求纳入 |
| 子项目 | 导出所选 | 导出可供审核的中文项目清单 |
| 子项目 | 批量入库 | 在储备页勾选，具备项目入库权限 |

批量写入前逐条预检，展示可办记录和不可办原因。显式确认后仅提交预检可办记录。服务端复用正式需求状态变更、项目入库和整条需求关联用例。同一批提交在事务内复核权限、状态和版本，遇到变化整批回滚。正式提交具备幂等保护。

子项目弹窗保留单一项目状态并采用概览、承接需求、立项与变更、费用与结算、历史记录五个分区。概览随状态提供明确下一步。已入库且具备范围和权限时可直接打开立项表单。编辑和删除在项目档案处，删除先读取当前关联和批准影响。费用与结算提供实际费用、结算单和费用核对的定位按钮。结项按钮打开核对，结项后由历史记录读取冻结的结项金额和工作量差异。

立项与变更区先显示本次申请再显示明细。变更中对照当前生效的批准版本和本次申请的预算、整条需求新增与移出、作业位置、工作量和物资，审核前提示尚缺预计解决时间的需求。各状态保留原有正式权限、版本、解绑及财务约束。年度框架与可选执行协议继续通过同一档案维护。弹窗内切换分区保留背景列表状态和地址。Schema113结构和P10功能范围未改。

验证覆盖实际HTTP批量预检、权限、并发回滚及重试，浏览器覆盖32条需求跨页选择、两个项目批量入库、两个真实Excel文件、单击编制立项及保留列表状态。四角色变更、两项标黄项目全流程、其他浏览器用例以及最终两版包验收以本轮测试记录及交付回执为准。Windows实机按用户前序安排暂缓。

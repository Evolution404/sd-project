## R1 证据

- 实施提交 `af75c54`。PR #3 同 SHA 的 CI、Browser、Windows 均通过。分支 push 的 Browser 生产、历史、规模与销毁通过，布局冷启动 100×10 点击至就绪 1,234ms 超出 1,000ms，已在 R2 移除加载遮罩拦截并保留表单和工作表禁用，后续同 SHA 复验。

- Univer 1.6.1 的原生排序重排物理行，跳过隐藏行且登记坐标历史。原生删行以连续范围为单位，过滤及权限范围独立处理。工作表业务排序改用当前草稿和稳定身份的整行投影，继续从原生筛选菜单触发。排序和筛选属于视图操作。
- 工作表保留同一实例和原生 `IUndoRedoService`。通过 SDK 依赖注入在记录时将编辑 mutation 的文本按稳定行 ID 和列映射，将增删记录放入同一栈。结构变化保留当前筛选、权限、校验和可见选区。父表单按业务顺序及来源记录更新，工作簿显示顺序不写入业务排序字段。保护范围、下拉、剪贴板、快捷键继续使用 SDK。
- 修改 `BusinessWorksheet.vue`、`univer-engine.ts`、`DemandEditor.vue`。正式 runner 自动纳入 `youlai-worksheet-row-history-browser.mjs`，台账专项改为断言编辑后排序、撤销和原身份提交。专业需求专项加入同时挂载位置与物资时的键盘历史隔离。
- 生产构建正式需求 A/B/C 场景验证编辑 A→排序→编辑 B→原生菜单删除 C→连续撤销和重做。还验证首次选择增加、全删恢复、筛选后只删除可见位置、跨排序保留筛选、非连续行号选择及 SQLite 数量/版本/台账身份。正式台账选区回归覆盖下拉、批量粘贴、只读拦截及排序后保存。真实结算复验采用原正式批准版本、余量及只读范围。
- `make check` 303/303，`make check-schema` 481 项设计约束，正式浏览器首轮 6/6。继续补跑位置历史、台账、双主题作业方式和长表单、需求双实例。证据在本机 `test-results/record-entry/r1-*.log`、`test-results/youlai-worksheet-row-history/`。最终发布须重跑全门禁。
- 布局探针 100×10、500×15、1000×20 分别为 656、575、591 毫秒。30 次结算工作表销毁后 DOM 节点和事件监听器数量与基线一致。规模探针 10,000 单元格粘贴 556 毫秒，25,000 行完整结算草稿保存 2,656 毫秒。探针已在 release-final 和 Browser 矩阵运行入口登记。

## R2 证据

- 实施提交 `707b1af`。PR #3 同 SHA 的 CI 和 Windows 通过，Browser 因后续提交取消。

- 专业需求预计物资由原生表格选择，在一张工作表填写数量和说明。移除选区及恢复沿用 R1 历史。需求来源与新增来源同表，已有正式记录只读，补充行可连续添加、粘贴或删除。源数据日期由网页、正式服务和 Excel 同源校验。
- 八类可明确映射的手工位置属性进入同一工作表。冻结的台账身份只读显示业务名称。含逗号的选项和含斜杠的多选旧定义保留显式选项编辑；这两类分隔符分别与 Univer 的选项定义及多选值存储冲突。同名选项不可通过相同显示值推断身份，保留已采用值，阻止再选择同名项。此例外须在 R7 定义治理继续处理。
- 需求查询页增加批量新增及对所选记录的批量修订普通资料。新增按一批一个操作正式版本，主记录、作业位置、预计物资和补充来源分别采用对应工作表，以需求组号引用；设备和物资通过原生表格选择器。普通修订以正式身份、当前版本写入允许的基础字段。
- `POST /api/exchange/demands/worksheet-preview` 与正式提交沿用需求 Excel 预检和领域保存。在线新增可引用选定正式设备、物资、操作版本，普通修订不开放明细。预检零正式写入，强制整批提交，重检版本及项目状态，沿用幂等键。在线批次不记为培训 Excel 操作。
- `make check` 305 项通过，最后一轮构建预算总 JS 14,377,559 字节、最大 1,142,432、入口 614,790，普通查询仍懒加载。正式 runner 最新定向 4/4，包括两条真实需求各自新增/修订及 SQLite 逐位置数量和身份、浅深两主题行对齐、八种属性与只读拒绝、位置结构历史、单据物资及多来源。API 专项 2/2 覆盖非法精度零写入、拒绝非原子提交、幂等重试、权限、并发版本冲突和旧明细保留。
- 证据位于本机 `test-results/record-entry/r2-{check-final,build-verified,browser-verified,online-api}.log`。截图仅为本机合成数据。云端同提交全量门禁及发布快照归 R10。

## R3 证据

- 实施提交 `65333c0`。正式项目、框架和档案批量浏览器 3/3 通过。随后启用实际跟随系统主题并校验页面主题类，复验项目批量与批准物资。

- 子项目档案新增和允许字段修订通过同一原生工作表录入。批量新增选择一个年度框架及可选协议，普通修订沿用选中档案的最新版本。保留档案中单独处理组织、归属和执行协议的表单，以便核对依赖或权限变动。
- 新增档案批量预检与提交复用正式项目保存、范围与版本规则。最多 100 条。预检在数据库保存点内执行并回滚，提交校验输入指纹后在同一事务重新校验全部记录，正式 HTTP 写入保留幂等保护。API 回归确认非法金额、日期、越权及过期版本时无部分写入。未扩展旧 Excel 的项目批量能力。
- 批准物资使用一张工作表，原生选择器跨承接范围选择需求与物资，数量按冻结单位校验。工具栏和原生右键移除沿用同一历史，切换承接选区后保留隐藏物资草稿。集中核价可切换承接范围，保留各范围试算条件，仍使用原正式试算指纹及核价版本。
- 涉及 `server/modules/projects` 的请求、服务和路由，`ProjectProfileBulkEditor.vue`、`ProjectsAdministration.vue`、`ProjectApprovalAdministration.vue`、`ProjectQuoteDialog.vue`、公共工作表可见行及正式验收入口。项目原四角色回归保持首次批准及正式变更、结算、结项释放、原需求完整剩余量接续断言。
- 本机 `make check` 306 项通过。构建预算总 JS 14,392,180 字节、最大 1,142,432、入口 615,216。项目专项覆盖新建两条档案、选中档案修订、跨需求物资、撤销、选区切换和双主题控件对齐。记录位于 `test-results/record-entry/r3-{check,build-final,browser-final}.log`。正式浏览器及云端同 SHA 的全量复验归 R10。
- 下一步 R4 合并结算子费用的引用和录入区域。项目档案批量全角色权限与更大批次的组合覆盖纳入最终矩阵。

## R4 证据

- `SettlementCompose.vue` 的重复 Element Plus 编辑表已删除。子费用的科目、关联批准需求、金额和依据在同一 Univer 工作表录入。科目通过原生可搜索表格选择器按末级稳定 ID 设置，可对同一选区批量赋值。批准需求以当前选用的正式版本提供原生下拉，共同费用可留空。
- 结构增删、跨行科目更换及单元格输入沿用同一原生历史。费用科目赋值保留已输入金额和依据。公用的科目选择器保留分列消歧，并受科目及祖先启用状态约束。切换结算金额方式保留本次子费用草稿；切换正式批准版本仍需核对差异。
- 现有服务仍在保存、提交和审核阶段校验批准版本和工作量余量。费用正式事实与工作量的两类数据保持各自录入范围。实际回归验证同一科目下有关联需求和共同费用两条明细、三位小数定位并阻止保存、右键移除再撤销、正式审核、历史批准版修订及实际费用核对，SQLite 逐项验证正式引用及两位金额。
- 正式财务及子项目专项 2/2，另有 P10 十条训练检查点、两种结算方式和 R1 工作表历史回归通过。`make check-schema` 481 项通过。构建总 JS 14,393,298 字节、最大 1,142,432、入口 615,217，原生 UI、字段独立性、导览关联及公开源码门禁通过。证据位于 `test-results/record-entry/r4-{theme-recheck,browser,build-final,schema}.log`，标准视口双主题截图位于本机 `test-results/youlai-y4/settlement-itemized-*.png`。
- 下一步 R5 费用科目、实际费用和费用核对的批量业务命令。最终全量和 Windows 仍归 R10。

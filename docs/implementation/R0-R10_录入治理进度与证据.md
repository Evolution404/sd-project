## R1 证据

- Univer 1.6.1 的原生排序重排物理行，跳过隐藏行且登记坐标历史。原生删行以连续范围为单位，过滤及权限范围独立处理。工作表业务排序改用当前草稿和稳定身份的整行投影，继续从原生筛选菜单触发。排序和筛选属于视图操作。
- 工作表保留同一实例和原生 `IUndoRedoService`。通过 SDK 依赖注入在记录时将编辑 mutation 的文本按稳定行 ID 和列映射，将增删记录放入同一栈。结构变化保留当前筛选、权限、校验和可见选区。父表单按业务顺序及来源记录更新，工作簿显示顺序不写入业务排序字段。保护范围、下拉、剪贴板、快捷键继续使用 SDK。
- 修改 `BusinessWorksheet.vue`、`univer-engine.ts`、`DemandEditor.vue`。正式 runner 自动纳入 `youlai-worksheet-row-history-browser.mjs`，台账专项改为断言编辑后排序、撤销和原身份提交。专业需求专项加入同时挂载位置与物资时的键盘历史隔离。
- 生产构建正式需求 A/B/C 场景验证编辑 A→排序→编辑 B→原生菜单删除 C→连续撤销和重做。还验证首次选择增加、全删恢复、筛选后只删除可见位置、跨排序保留筛选、非连续行号选择及 SQLite 数量/版本/台账身份。正式台账扫码选区回归覆盖下拉、批量粘贴、只读拦截及排序后保存。真实结算复验采用原正式批准版本、余量及只读范围。
- `make check` 303/303，`make check-schema` 481 项设计约束，正式浏览器首轮 6/6。继续补跑位置历史、台账、双主题作业方式和长表单、需求双实例。证据在本机 `test-results/record-entry/r1-*.log`、`test-results/youlai-worksheet-row-history/`。最终发布须重跑全门禁。
- 布局探针 100×10、500×15、1000×20 分别为 656、575、591 毫秒。30 次结算工作表销毁后 DOM 节点和事件监听器数量与基线一致。规模探针 10,000 单元格粘贴 556 毫秒，25,000 行完整结算草稿保存 2,656 毫秒。探针已在 release-final 和 Browser 矩阵运行入口登记。
- 下一步 R2 需求预计物资、来源和位置属性。R3～R8 的领域批量命令与 R10 双包交付仍待实施和验收。

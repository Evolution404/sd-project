## 已完成

1. web/src/shared/ui/TabulatorGrid.vue：Vue3 封装 Tabulator，只读列表、PMS 式筛选触发入口、远程列筛选、排序、持久列显示/顺序/宽度、区域选择/复制、业务详情跳转，Element Plus 按钮保持原严格 UI 标准。
2. web/src/shared/ui/ExcelColumnFilter.vue：标题、升降序、文本搜索、候选值与数量、全选搜索结果、独立多选、清除本列、确定/取消，支持大候选值分页。
3. 物资管理 MaterialsPage.vue：首个正式业务页迁移，保留增删改查、历史、删除过滤、查询分页；服务端给出完整去重候选值而非当前页候选值。
4. grid_filters：共享列表查询增加独立类型化多值过滤；在服务端严格校验，非法字段返回400；通用 searchPage 与 searchFacets 复用 SQL 谓词，避免分页／统计／候选不一致。现有 filters 原逻辑仍供尚未迁移的页面使用。
5. web/src/shared/ui/BusinessDraftGrid.vue：专门处理草稿的 Tabulator 可编辑区域，包含双击、框选、剪贴板 TSV 粘贴、撤销、重做和独立业务行勾选。避免启用与 Tabulator Range 不兼容的内置 rowSelection。
6. 专业需求 DemandMaterialTable.vue：预计物资数量使用编辑网格，真实数量文本严格解析为4位定点整数，按计量单位正式版本验证0～4位精度，非法输入阻止父表单正式保存；编辑仍复用原需求版本 API 与审计，不增加第二套写入接口。

## 迁移边界与技术债

尚有大量 BusinessTable 使用点，并未全系统替换；设备台账、需求列表、子项目范围、费用结算等需逐批迁移。操作类型、数量/金额/日期不同筛选语义仍需类型化协议与多维字段元数据；物资目前提供第一批字符串候选值；完整筛选/导出一致性与性能要逐域验收。专业需求位置与结算草稿尚未迁移编辑网格。测试中直接依赖 Element Plus DOM 的场景要逐个换成稳定语义接口，不能通过粗暴搜索替换掩盖业务回归。P10动作指引及四角色权限必须逐场景复验。

# sd_project｜价格治理、界面审查与全空数据库集成验收（2026-11-09）

## 一、实施范围与结论

在原 Schema113 业务身份、不可变历史与正式引用不变的基础上，对价格规则版本、操作类型价格特征、报价匹配说明、界面操作、项目资金分析做了治理。所有测试采用独立临时 SQLite 数据目录，不向真实运行库导入示例数据，也没有清理用户真实数据。

### 价格与版本治理
1. 编辑参考价格规则默认**保持原绑定的操作类型正式版本和计量单位版本**。只有用户明确使用“采用最新作业标准”动作才更新绑定，且须重新核对适用特征。
2. 价格规则新增**复制规则**，新规则独立创建正式身份；原规则的价格及审计历史不覆盖。
3. 新增保存前只读检查：检查必填信息、计价模型、已声明特征的版本和值、可能重叠的参考价格规则，并返回操作版本及重叠清单。用户可以输入示例工作量进行模型试算，费率基数或数量分档不足时给出原因，不产生虚假试算金额。
4. 正式报价逐位置返回实际命中规则名、版本号及人可读的计算摘要。没有匹配时给出电压等级、塔型、作业方式、规格、正式版本、现场价格特征等失配原因。正式价格计算记录仍使用既有不可变字段。
5. 已更新的价格特征与旧价格规则版本冲突时，保存前明确告知版本升级路径，避免直接暴露数据库触发器异常。旧版本历史仍可读取，不自动改写。
6. 操作类型和需求位置的价格特征读取改为一个精确版本的后端聚合查询，统一加载失败/重试状态；新增、编辑保存时不把未成功加载等同于“没有配置”。候选特征/单位分页加载，避免仅能选择前200项。

### 财务治理
项目“费用与结算”同时展示四个互不混淆的指标：**正式参考价格、批准预算、真实费用、已批准结算**，并展示参考价-预算及实际-参考价差异。任一批准范围尚未完整计价时，参考价显示“未完整计价”，不以0冒充完整金额；实际费用、预算与结算不强制相等。

### 本轮发现并修复的实际缺陷
**已修订费用无法删除**：原费用删除会把上一正式版本的 `request_key` 幂等标识复制至下一 `voided` 正式版本，违反唯一约束。已改为产生新正式版本时不沿用旧收据。空库测试覆盖“创建费用→修改金额→撤销/删除→历史留存→重启校验”。

## 二、界面审查与操作改进

浏览器按 **1500、1280、960、760 px** 四种宽度，覆盖 **8个业务模块的空库页面、7类空库创建弹窗**；已有视觉审计另覆盖浅色/深色主题、8模块、3类详情、8类弹窗和响应式布局。检查页面横向溢出、按钮越界、列标题裁切、弹窗边界和固定底部按钮。

本轮针对真实截图完成：
- 参考价格规则配置为“基本信息 / 适用条件 / 计价方式”；规则副本、版本升级、保存前检查、冲突清单和示例金额属于同一编辑路径。点击“保存前检查”后自动将结果区域滚动进入可见区。
- 项目详情在档案信息全空时不显示6行“未指定”，而用一行简洁提示及“完善档案”操作；用户进入“费用与结算”后四类金额在760px下能直接看到。
- 过长的自动项目编号收敛为省略号，悬停可看到完整值。
- 价格模型及组合费用模型统一展示中文名称，不直接把 `per_unit` 等编码暴露给用户。
- 价格特征/现场采集加载失败可重试，不在错误加载期间默默保存空白配置。

## 五、设计边界

- **无Schema113表结构变更**；沿用现有正式版本/引用设计。新增价格特征的单位仍从现有计量单位字典选取；系统不根据“高度”等自然语言猜测和自动替换单位种类。单位量纲如需强校验，应单独明确业务字典规则，不宜硬编码模糊匹配。
- 历史价格规则可追溯，但若其价格特征正式定义已经升级，不能让旧规则编辑时无提示套用最新定义；现在会要求显式升级操作定义及适用条件。正式历史不能被自动改写。
- 真实工程数据源、Windows封装部署、运维场景现场验收属于独立的运行环境验收，不在此次Mac本地空库集成测试中伪称完成。
- 保留既有其他开发中的工作区变更；本轮未执行Git提交、推送或覆盖真实SQLite业务库。

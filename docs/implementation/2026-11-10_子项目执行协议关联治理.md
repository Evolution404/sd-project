# 子项目资金归属：执行协议筛选与预算对比（2026-11-10）

## 业务规则和数据边界

本轮调整 `年度框架与子项目 → 进入项目 → 资金归属`。现有 Schema113 已通过 `project_funding_insert_guard` 禁止跨年度框架关联协议，本轮不再重复建立 SQL 触发器，也不改变数据库结构。

- 一个子项目当前可关联一个执行协议，也可暂不指定；一个执行协议可关联多个子项目。
- 只允许**子项目所属同一年度框架**下、**状态为有效**、**未逻辑删除**、**在生效日期区间内**的协议建立新关联。
- 对历史上已关联但现在停用、删除或过期的协议，允许只读查看，禁止用于新的资金归属；可选其他有效协议或清空，旧版本保留。
- 服务端 `projects.fund` 在事务中检查项目状态、原资金归属版本、跨框架归属、协议状态和生效日期。重复保存相同协议不产生无意义历史；正式结项后不可更改资金归属。
- 后端与界面双重校验；即便绕过下拉框直接请求也无法关联错误协议。

## 额度参考，绝不冒充正式资金分配

当前应用没有单独的“子项目从执行协议预支／分配额度”账本，`project_funding_versions` 只有当前协议关联及历史，而 `project_approval_versions` 记录子项目正式批准预算。两者不能混同。

为了帮助用户了解协议与项目的预算对比，资金归属页展示：

- **执行协议额度**：取当前有效协议版本 `v_agreement_current.limit_fen`；
- **关联项目批准预算合计**：按 `v_project_funding_current` 找出目前关联该协议、未逻辑删除的项目，每个项目按 `v_project_current_approval` 取最新正式批准预算合计；未批准项目贡献0；
- **预算差额（参考）**：协议额度减上述已批准预算合计；可为负数，只供管理参考，**不是可用现金/预支款余额、不是正式分配额度，也不是约束新项目的硬性上限**。

当用户变更项目的资金归属时，这些参考数字会随当前关联关系变化。历史版本保留，不重写既有已批准费用、结算与需求关联。

## 界面操作

1. 左侧打开「年度框架与子项目」，点击「进入项目」；
2. 点击「资金归属」，等待当前框架协议加载；
3. 选择协议；列表以协议名称为主，协议编号及三项金额作为辅助信息；
4. 检查当前协议额度、关联项目预算、差额、关联项目数；可清空选择表示暂不指定；
5. 保存。无实质变更不能重复提交，错误或失效协议不能保存。

无有效协议时提示先在「执行协议与资金」新建；接口加载失败时提供重试。

## 测试与验收

- `tests/api/project-agreement-funding.test.mjs`：框架过滤、正常/已停用/未来生效/已过期、服务端直接提交拦截、同协议禁止无效重复版本、切换协议与清空归属、历史版本、参考预算更新和负数差额不强制拦截。
- `tests/e2e/project-agreement-browser.mjs`：演示数据上真实浏览器打开资金归属弹窗、验证只显示当前框架内有效协议、预算对比可见、修改保存并形成新的历史。
- `npm run check`、`npm run test:browser`、`npm run check:schema` 全量质量门禁。
- 所有自动化测试都使用隔离临时数据库，不覆盖 `data/schema113.sqlite` 或 `data/demo/schema113.sqlite`。

**后续若需要真正的协议资金预支、分配和结余，需设计独立的分配/拨付业务记录与审计模型，不能直接由批准预算推算出“已分配资金”。此项本轮不擅自引入。**

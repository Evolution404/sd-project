# 全系统 UI 按钮布局、内容间距与表单层级复审（2026-11-13）

## 审计范围

基于 `codex/full-rewrite-20261110` 当前重构分支，覆盖工作台、专业需求、子项目、年度框架、执行协议、费用与结算、输电设备台账、物资、作业标准、参考价格、基础数据、系统管理等 12 个业务入口。重点检查：

- 标题和动作按钮是否处于相同基线，新增、刷新、筛选、删除是否形成明确的主次分组；
- 按钮距离标题、表格、表单字段和说明文字的间距是否一致，窄屏时是否折行或溢出；
- 表单标签、必填提示、输入边框、聚焦状态、校验错误、重复明细记录、底部取消/保存区域是否有清晰层级；
- 弹窗在 1280px 与 760px 宽度下的可视边界、滚动区与底部动作是否重叠；
- 上述样式调整是否影响项目审批、费用结算、需求工作台等真实业务流程。

本次仅治理用户界面和可访问性，不变更数据模型、正式版本、权限规则和已有 P10 业务指引。

## 实施结果

1. **卡片标题与按钮**：消除卡片内 `h2` 默认下边距对按钮垂直对齐的影响；标题与操作区之间增加水平分隔，标题向左、办理按钮向右，窄屏自动换行。保留原来的普通筛选栏和表格列设置位置。
2. **统一表单控件**：浅色与深色各自设置输入边界、表单背景、聚焦环，必填标签强调、错误边框优先；原有 hover/focus CSS 特异性不足导致聚焦环被普通边框覆盖的问题已修复。
3. **弹窗布局**：统一标题/滚动内容/底部操作三段式结构，设置独立边框与内边距；底部动作间距和主按钮宽度统一，保持表单滚动和按钮始终可用。
4. **需求编辑器**：基本信息、作业位置与工作量、预计物资、来源依据分段清楚；来源记录转为独立背景卡片，来源删除按钮与对应行对齐，草稿提示与底部按钮分离；窄屏调整内容高度和间距。
5. **项目正式批准**：批准物资明细由没有标签的并排控件调整为“物资名称/批准数量/移除”分区，移动端竖向排布。未改变材料选择及批准数量逻辑。
6. **结算表单**：每笔“费用明细 N”与“解决需求 N”独立分组，右上角提供对应的次级危险“移除此项”操作；新增明细按钮统一与分组边界的间距。减少误将删除操作应用于相邻行的风险。
7. **费用科目**：突出新增科目，删除科目使用次级危险按钮并和版本管理按钮拉开距离；科目详情标题、状态标签与路径换行更明确。

# 桌面操作恢复与关联返回验收

本轮从 `d6b0464` 继续核对结算单定位、关联详情返回、列表导出和批量办理。桌面实操使用隔离演示实例，写入与故障模拟使用独立测试库。

| 操作 | 复现及修复 | 验收证据 |
| --- | --- | --- |
| 切换结算单后查看历史 | 从跨项目查询定位 JS-000001，再选择 JS-000002，原界面会展示 JS-000001 的历史。现在重读和历史始终对应当前选中的记录。返回跨项目查询时恢复原单据和页签。 | Computer Use 核对 JS-000002、166.00 元和同编号历史。浏览器脚本 `finance-direct-record-browser.mjs` 覆盖直接打开结算单后的重读，以及从跨项目查询进入和返回。 |
| 项目财务部分读取失败 | 原界面会同时清空费用、结算、核对和总览。现在逐项保留最近成功的结果，列出失败内容，并提供统一的重试入口。只有结算列表读取成功后才开放对应 Excel 导出及批量修改。 | `finance-roles-browser.mjs` 分别模拟结算总览与结算列表失败，核对可用区域和恢复结果。 |
| 从项目打开关联记录 | 关闭关联需求后原来会停留在专业需求列表。现在关闭需求、年度框架或执行协议时回到来源项目和原页签。执行协议名称读取失败时，项目仍按实际归属显示并提供协议入口。 | Computer Use 逐个打开并关闭三个关联入口。浏览器脚本 `user-journey-navigation-browser.mjs`、`demand-adopted-trace-browser.mjs` 和 `funding-workspace-browser.mjs` 覆盖返回、沿正式版本继续追溯及协议读取失败。 |
| 筛选和勾选后导出 Excel | 项目列表保存最近一次成功查询的条件，筛选导出带上这些条件。项目、需求、设备和项目结算列表读取失败时，暂停基于当前列表的导出或批量修改。跨页勾选保留，返回所在页后更新已选记录的状态及版本。 | `handling-batch-browser.mjs` 下载项目和需求的实际工作簿，检查行数及身份范围，并确认读取失败后重试能恢复导出。 |
| 批量预检或提交遇到断线 | 预检失败可保留勾选重新核对。没有收到提交结果时，可用原内容重试提交，系统沿用同一提交标识并核对首次结果。 | `handling-batch-browser.mjs` 模拟预检断线和服务端写入后响应中断，核对请求标识相同、业务只执行一次。 |

全量门禁通过 265 项，数据库通过 479 项，性能通过 6 项。桌面浏览器门禁的 62 个脚本分批执行，调整后复跑受影响路径。两个标黄项目的全流程脚本通过。

正式包和演示包的校验独立于桌面浏览器实操。Windows 实机验收按现有安排暂缓。

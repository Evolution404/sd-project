# Schema113 重写交付与验收

## 交付范围与状态

本轮以用户提供的全面重写任务为依据，接入独立 Schema113，实施 P0 至 P9 业务代码及 P10 的本机回归、浏览器流程、备份恢复和离线打包。Windows 操作系统实机执行仍待验证。全部代码保存在本地 Git，恢复标签为 `codex/pre-schema113-rewrite-20261108`，对应起点 `9aa88f3`。

用户补充裁决为“完全移除税率概念，本系统不考虑税率”。应用、SQL、模板和报表已移除相应6字段。八种规则中的费用比例按独立计价参数处理。

根目录原 `data/` 保留。测试全部使用独立临时 DATA_DIR，验收未向原 data 写入业务记录。预览也使用独立目录。程序默认创建 `schema113.sqlite`，遇到已有结构不匹配库拒绝启动。

## 专业需求 Excel

工作簿包括使用说明、可选基础数据和六张业务表。

- 需求清单保存业务编号、操作及正式原版本、问题和验收事实。
- 作业位置保存真实设备、数量、作业方式和规格。
- 预计物资引用统一物资定义和预计数量。
- 来源依据保留来源编号、说明与日期，更正采用新原始记录关联旧记录。
- 补充现场字段承接操作专用字段，字段身份和类型由已采用操作版本推导。
- 现场价格特征按设备及特征编码录入，字典版本由操作定义取得，台账来源特征自动获取。

可下载空白模板，导出筛选结果或勾选项，再修改并回导。稳定ID与原版本用于更新校验，也可用精确设备和操作编码新增。金额使用元，最多两位小数，数量最多四位小数。

上传后只保存预检批次，展示单据数、动作、预计需求版本、逐字段变化、重复及版本问题。问题带工作表、行、字段、原值、原因和建议。确认后逐单据事务执行，支持整批回滚，问题与最终处理结果可分别下载。重复请求返回原幂等结果。

三种模式为仅新增、仅更新和混合。缺少字段、空单元格或 `__KEEP__` 保持原值，`__CLEAR__` 清除可空值，`__EMPTY__` 写空文本，明细 `action=delete` 明确删除。缺行继续保留原明细。

限制为5000张单据、25000行业务数据、12MB文件、80MB解压内容和2000个ZIP条目。仅接受xlsx，公式、超链接、富文本和错误单元格须修正为真实值。XML文件通过ExcelJS解析，ZIP解压规模在加载前检查。

## 结算 Excel

三张业务表为结算单、费用明细、需求解决明细。入口继承当前子项目，可用项目编码、科目路径和需求编号精确识别。

费用明细的计价数量、金额与需求解决明细的新增解决数量独立。多个费用项引用同一需求只保留一笔该需求的本次解决量。回导保存草稿，提交和批准分别办理。旧正式单据修订生成新正式版本，原已批准事实保留。

维护导出用于回导。业务报表单独生成适合阅读、打印的中文工作表，带只读标记并拒绝回导。结算报表分别列出草稿金额和当前已批准金额，待审修订不替换当前有效结果。

### 发现与修复

- 单条实体读取反复扫描该类对象全部删除审计，造成写库路径随审计量增长。改用现有idx_audit_entity进行实体身份检查，未增加索引或内存业务状态。
- 来源投影原先扫描全系统来源审计，改为按需求关联读取和按来源身份判断更正、删除。
- 预检重复标准化相同需求，复用同次准备阶段的标准化结果。提交仍从原文件重新预检，保存仍执行完整约束。
- 核对更正表单携带上一正式版本的内部request_key，导致唯一冲突。每次更正使用新的请求身份，正式核对序列及原金额历史保留。
- 结项项目删除后仍可能持有需求，原释放入口因根被删除而失败。管理员可在历史项目中明确解绑，关闭、删除和释放各留独立事实。
- 已采用物资删除后，需求无关修订曾被新选择限制阻断。无关修订继承原版本，新物资采用仍走正式规则。
- 大量主数据下已选记录可能超出首屏选项而显示ID。选择器补取已有记录、支持远程搜索并忽略过期响应，档距使用线路与两端杆号展示。
- 恢复会话失效反馈，约束错误转换为业务提示，备份拒绝复用已有目标目录，Windows路径检查使用平台分隔符。
- 项目、核对和草稿参考费用补齐维护入口，费用更正先撤销草稿旧计算并以新身份重算，失败时整笔回滚。正式批准后继续通过正式变更办理。

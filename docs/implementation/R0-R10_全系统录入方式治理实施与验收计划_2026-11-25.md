## 1. 目标、边界及权威顺序
用户最新裁决：除确有必要外，批量录入默认采用现有 Univer 工作表，尽量取消逐条进入编辑弹窗；查询态仍为有来/Element Plus 原生表格。作业位置直接使用原生右键一级「删除选中行」、工具栏移除，底部清单不再出现。复用组件，不重写第三方源码、样式或再造表格引擎。
本计划是 G0～G9 总治理下的录入专项，补齐 W/B 系列尚未解决的缺陷。仅在录入交互及明确批准的批量普通字段范围内覆盖旧规范；不取消原有业务裁决、权限、版本、事务、历史、设备拓扑、结项释放、审批、金额/数量精度。Schema113 为现有基线；优先复用领域命令与存储，不因界面表格化而改库。确需结构迁移须单列依据、迁移/回滚方案及验证，未经明确授权不自动迁移正式库。
用户明确要求标准办公显示器 1920×1080、100% 缩放、深浅双主题，不做窄屏/移动适配。保留前端体积门禁（单 JS 1200000 字节、总 JS 15000000 字节、入口静态 700000 字节）、原生布局中心线≤1 CSS px、查询页延迟加载编辑引擎。
正式程序不含真实数据，部署选择既有独立 DATA_DIR，不覆盖、不重置账号、不自动升级库；演示账号按现行 AGENTS 裁决。全部测试使用合成夹具及隔离 DATA_DIR；真实台账、账号、附件、日志及截图严禁进入公开 GitHub 或 Actions。保护工作区与用户正在运行的服务。不得以旧库兼容或测试数据为由清空正式、演示业务数据。
不将普通录入与审批、授权、作废、整基更换等专用业务命令混淆；保留必要确认、复杂关系选择器、附件上传及历史展示。

## 3. 交互与数据契约（R0 冻结）
1. 查询态：有来 CrudPage/CrudTable/CrudSearch、原生服务端筛选排序分页，保持只读；用户主动进入批量编辑或新增工作台。不得把全系统查询列表强制换成编辑引擎。
2. 单据：基本信息单一普通表单；多行明细默认直接工作表；引用型明细通过原生可搜索、跨页多选表格选择器加入，禁止任意输入不存在的设备/物资；自由新增型才开放原生插入行/粘贴新增范围。禁止重复编辑面板和逐行移除按钮阵列。
3. 列描述：业务字段独立列、中文标题/枚举显示、稳定字段键、类型、精度、空值语义、权限、引用、冻结版本、校验、可增删策略。稳定内部 ID 不供用户输入；重名通过独立列的原生选择器消歧，禁止拼接多个业务字段。选项 label 与 value 映射可逆；多选结构化处理；不得将公式执行或数值科学计数法引入普通文本。
4. 行契约：稳定业务/草稿 ID 与显示位置分离。新增使用会话内稳定临时 ID，服务端生成正式身份；不得以当前行号、排序索引、名称作为保存主键。行删除：新建草稿移除，已有单据明细显式删除意图；正式主数据退役/作废/逻辑删除保留专用命令及权限。筛选隐藏、锁定、表头不被误删除；全选可明确移除全部明细，保存时仍检查必填/非空约束。
5. 工作表原生交互：正常复制、粘贴、拖填、选择、原生下拉、筛选、整记录排序、撤销重做、允许的插入/删除、查找替换；原生右键一级删除（仅可移除明细），其他安全原生功能按场景启用。只读/越界目标整次拒绝，不部分写入，不跳过保护。筛选隐藏行仍保留并参加校验；跨隐藏行写入按现有整次拒绝，除非原生且业务语义明确的可见行操作通过专项验收。
6. 编辑事务：单元格编辑结束、异步校验、保存/离页/切换引用并发互斥；同一操作不可重复触发。草稿错误保留并标红、定位可恢复焦点。筛选/排序/增删、撤销不会丢其他数据。滚轮实际单元格范围内只滚表，表格之外空白滚外层，原生滚动条保留。
7. 保存：先结束全部工作表编辑，读取唯一草稿源，以稳定 ID 生成差异；服务端按命令权限、组织范围、状态、版本、引用、精度、跨行约束联合校验；独立请求幂等键、预检结果指纹/提交复核、明确错误行及字段。单据明细事务原子；多单据默认整批原子，现有 Excel 显式允许的逐单据提交保留且报告结果，禁止前端循环单条保存冒充批量。网络超时须查询/复用原幂等结果；失败草稿保留，禁止静默部分成功。
8. 批量规模：沿用现有需求5000处、Excel 5000单据/25000明细上限；不要将此直接作为所有模块新上限。按各领域容量及性能证据裁定在线批次，保留后端硬限制；过量明确提示、不得静默截断。基准100×10、500×15、1000×20分别≤1000/2000/3000ms；已有10000单元格粘贴和25000行规模探针全部回归，记录环境、耗时、内存和阻塞。大范围须按需加载而非在查询页加载所有编辑器。
9. 审计例外台账：每个仍保留弹窗/逐条操作须记录路由、字段、业务理由、替代方案和证据；对普通平面字段不得以“复杂”为由永久豁免；无必要不设弹窗。附件、审批意见、作废/结项确认、密钥/密码、组织迁移、拓扑变化及冲突处置属于允许的必要例外。

## 4. 实施阶段（禁止跳过 R1 直接铺页面）
### R0：基线冻结与完整资产清单
逐个盘点 web/src/views/business、views/system、views/workspace、components/business、Crud、BusinessWorksheet、SettlementWorkSheet。形成清单：路由/动作、字段、当前组件、普通/引用/结构/审批类别、现有 API/权限/状态、批量新增/修订/删除策略、例外理由、测试证据、责任阶段。逐页检查真实 1920×1080 基线，保留可复现缺陷和截图（合成数据）。登记原有 G/W/B/P10 未完成事项。更新权威规范、旧限制及导览台账。
### R1：公共工作表架构，阻断门禁
- 先阅读本地安装的 Univer 1.6.1 类型和源码、原生命令、排序 mutation、行插删及 IUndoRedoService；以真实 BusinessWorksheet 及 SettlementWorkSheet 接入做最小验证。确认其 API 能否在保护列、筛选、非连续选区下保持完整行及历史。不能假设官方支持所有业务语义。
- 首选原生单次整行排序及结构命令、不可变行身份/映射同步和 SDK 历史；如原生历史不覆盖外部业务结构，建立一个统一命令历史适配层，将原生编辑和结构事务纳入同一时间线，禁止并行两套 undo、独立键盘模拟、按索引保存或仅在表面移除禁止排序。方案须用可运行证据选型，不以重建并清空历史回避。避免工作簿无限快照和逐格 API 风暴。
- 明确排序为视图操作（不改变正式杆塔 sort_rank 或关联）；排序使用当前草稿值、整行稳定排序、中文及精确数值语义，空值/同值稳定。筛选状态与校验错误行 ID 正确映射。定义视图排序是否进入撤销历史；无论如何，撤销编辑始终作用正确业务行，用户可撤销删除/新增及之前的编辑，重做顺序一致。若 SDK 无法实现排序历史本身，记录视图操作独立不污染业务历史，不能因此禁止编辑后排序。
- 新增/删除/引用变更事务化；允许单格右键直接删除选中行、非连续/连续行号多选、工具栏删除，先同步编辑再移除；禁止误删隐藏、只读身份、锁定行；底部清单永不恢复。全删、空表、重新加行、跨排序筛选恢复选择、失效引用校验、保存失败回滚 UI 需实测。菜单不自绘；列权限、原生复制粘贴/填充/撤销和焦点保留。
- R1 验收：至少两个真实工作表（需求及结算或台账）执行 A/B/C 三行：编辑A数量，排序，改B，删除C，撤销删除→撤销B→撤销A，逐步核对ID/值/可见顺序，再重做；跨筛选、非连续删除、单格非法值、只读范围粘贴、批量粘贴一次撤销、会话切换、30次销毁、主题、滚轮、加载基准。原生菜单直接实测，测试检查实际业务数据库，不只截图/行数。通过前不得进入 R2。
### R2：需求录入
DemandEditor/DemandAdministration：作业位置全部手工属性纳入工作表，台账引用值只读展示；删除临时属性弹窗之前必须通过重复名称、逗号斜杠、八种属性类型、默认值、冻结定义、必填及计价校验。若真正无法安全录入，须记入例外并提供同工作台结构化编辑，不恢复底部逐塔清单。保留工作方式、插入塔区间、5000处、连续长表单导航。预计物资选取后工作表填数量、说明，原生删除移除重复按钮。需求来源补充支持多行草稿，不修改旧正式来源。需求列表增加网页批量新增/普通字段修订工作台，采用需求主表、位置、预计物资、按需来源独立表，以临时关联号及稳定ID衔接；采用现有 Excel 预检/提交业务服务、冻结单位/操作定义、重复需求核对及正式修订规则。不能用批量录入绕过已关联需求退回/取消限制。
### R3：子项目及立项
ProjectsAdministration：档案批量创建/允许的普通字段维护（储备阶段按现行框架/协议规则），关联需求使用现有多选表格。ProjectApprovalAdministration：批准物资统一工作表，需求与物资引用集中选取，可跨需求批量添加，数量/必要字段可编辑、原生移除；引用身份版本明确且无重复。批准位置/数量由独占承接全部剩余量确定，只读，不开放人为缩减范围。核价提供跨范围集中核对/选择，仍按现有八种模型、试算指纹、重叠规则及正式审核；不把报价参考值等同批准预算。保留项目独占承接、正式结项释放、完整剩余量接续、预计解决时间与审批约束。
### R4：结算编制
SettlementCompose：删除子费用重复 el-table，把费用科目、关联批准需求、金额、依据合为唯一工作表；科目只允许可用末级，祖先停用、冻结历史引用及版本处理明确；共同费用关联可空。新增/删除行、复制粘贴、选择器均同表。保留 SettlementWorkSheet 的只读批准/余量及本次解决量、依据；跨批准版本切换须保留原有差异提示，待审核锁定，退回/修订原规则。草稿、直接提交、重提和审批服务端再次复核逐位置余量，排除本单旧生效量，不重复扣减前项目已解决量。
### R5：实际费用、核对和费用科目
ProjectFinanceWorkspace/FinanceAdministration：实际费用批量登记和合法修订；费用核对选择实际费用/结算明细并录入双方金额和依据，逐行版本及剩余额度预检，跨行合计事务约束；同级科目普通维护及新增工作表，层级变更/停用影响继续专用处理。附件按正式记录独立上传。核定、作废、删除、结项保留独立语义、权限与审计，不把草稿行删除变成正式记录删除。金额统一人民币元输入、整数分保存，无税率。
### R6：设备台账与物资
四类设备及物资保持查询态原生列表、既有批量修改入口；新增网页批量新增工作表。线路和档距端点引用、逻辑塔归属线路及共塔必须显式选择并校验，普通新逻辑塔按原规则建立独立实物；禁止自动按杆号推断同塔、任意改挂、无意退役/替换。保持字段白名单、单位版本及身份不可变；新增与修订使用领域批量命令。100条上限先以100/500/1000及业务数据验证，服务端与界面同一约束，未通过不擅自放宽。物资不引入仓储领退流水，计量单位采用历史规则。
### R7：作业标准、附加属性和参考价格
作业对象、操作类型普通字段批量新增/维护；复杂操作定义采用正式工作台（主信息+附加属性表+枚举选项表，选择某定义时集中编辑，非每条属性弹窗），稳定属性/选项编码及版本沿用。支持八类型、需求/位置、手填/台账、计价条件、精度、默认值及历史采用，不增加税概念。参考价格工作台主规则表+动态条件明细表，八计价模型各自必要字段、日期、来源、范围、版本、重叠和缺价检查。保留必要的单规则复杂条件预览及明确确认，普通维护不逐条进入弹窗。
### R8：基础配置与系统管理
字典（单位、电压及其他）、年度框架和执行协议普通字段支持批量新增/维护；单位精度、已引用版本、框架协议关联及生效期不可绕过。组织树保留，同级批量新增和普通字段维护，跨级迁移及引用影响保留正式操作。用户普通资料可批量维护；批量创建须复用明确授权的安全初始凭据流程，密码不进入普通表格、导出或日志；角色授权/初始密码修改/重置单独执行。IP授权可提供集中表格输入，提交前展示范围及影响，服务端保护安全边界；角色权限及数据范围矩阵原样保留。审计、历史只读。低频复杂单据允许必要单条表单，但登记例外。
### R9：贯穿各阶段的服务端批量契约及技术债
R2～R8 每模块前完成对应批量 API 设计与领域事务测试，不最后补安全。盘点现有 bulk/Excel 服务，抽取同一命令校验而非复制业务逻辑；明确批次上限、权限/组织范围、预检/提交、版本冲突、幂等、唯一性、错误定位、返回正式ID。多条记录存在交叉依赖时先整体校验、依赖排序，再在同一事务提交；不逐条外部请求，不绕过领域命令直接写 SQL。同步 API 契约、导览、文档及测试；仅删除有引用证据/回归证明的旧页面和冗余组件，保留隔离历史夹具直至覆盖迁移完成。
### R10：全量验收和交付
每阶段提交并记录实际证据；最终在同一干净 HEAD 完成 make check、make check-schema、make test-performance、make test-browser、历史治理浏览器门禁（pnpm run test:browser:governance）、原生 UI、字段独立性、导览、构建预算、公开源码及密钥扫描。确认 browser runner 纳入新增专项（非 *-browser.mjs 的规模/布局/生命周期探针显式接入门禁）。不得删掉失败用例、只测原型或降低预算。新增所有业务页面的普通/批量/权限/失败/回退/刷新流程及截图。
运行 make release-final（基于同一干净提交），验证实际正式和合成演示 ZIP、清单、SHA256、解包、程序数据分离、原数据复用、强退恢复。GitHub CI/Browser/Windows 同一 SHA 成功，Release candidate 仅按现有 main/审批门禁发布；不得把不同 SHA 的通过拼成当前通过。不上传真实数据、内网日志、真实截图或含真实台账包。Windows Runner 与内网 Win10 现场验收分别标记；未现场验证不得宣称正式生产验收。无需等待用户手工输入才能继续合成测试；真实内网现场验证如无法执行明确标为待用户验收。

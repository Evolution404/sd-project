# 专业需求、项目状态、业务按钮与时间显示最终治理（2026-11-13）

## 适用范围与边界

代码分支 `codex/full-rewrite-20261110`。本轮仅执行现有专业需求和子项目业务的 UI 操作修复、必要的后端拦截与测试，不开发 P10 新功能；不引入旧系统兼容层、不取消原有不可变正式版本和权限规则。数据库 Schema113 仍是唯一业务事实存储。

## 一、专业需求：五种用户可见状态

- 唯一可见列「需求状态」，五种值：待确认、已退回、待承接、已承接、已取消。
- 选项卡与可见列共用 `display_status`，不是额外隐藏的 `handling_view`；已退回和待确认分开。
- 底层仍为 `pending/returned/active/cancelled` 正式生命周期。待承接/已承接通过当前正式承接关系实时推导，不重复存库；既有审计历史不受影响。
- 查询时 `status` 与 `display_status` 过滤使用枚举值精确匹配，防止 `active` 意外匹配 `inactive`。
- Excel 需求导出的用户可见状态与表格完全一致。

## 二、需求编辑器交互

- 需求数量和计量单位采用不可折行的布局，列表和编辑/批量录入均保持同行。
- 顶部「基本信息、作业位置与工作量、预计物资、来源及其他信息」页签根据编辑器 **内部滚动容器** 当前可见章节更新激活状态，点击页签也滚动到对应内容位置。
- 疑似重复校验由纯编号确认框改为当前编辑器中的正式需求对比窗口。显示操作类型、问题与验收标准、作业位置、数量、来源、关联关系；多个重复候选可以切换。编辑内容保留，允许继续修改或会话草稿暂存并恢复。独立保留理由必填，并由服务端重检与留审计。
- 新增预计物资以表格代替简陋多选框。支持关键字搜索、列表表头筛选、排序、分页、跨页勾选、已选摘要和统一提交；新增后还可在需求明细调整各物资数量。停用/删除物资不得选用，已添加物资不得重复选择，保存前验证正式物资身份与当前精度。筛选 `active` 必须排除 `inactive`。

## 三、统一北京时间显示

- `web/src/shared/utils/datetime.ts` 是前端时间戳统一格式化入口。所有 UTC、含时区偏移及无时区标记的 SQLite UTC 时间戳都输出 **北京时间 `YYYY-MM-DD HH:mm:ss`**，不受用户电脑本地时区影响。
- 纯日历日期是 `YYYY-MM-DD`，不得进行时区偏移。对空值保持缺省展示。
- 全局 BusinessTable、专业需求、子项目、费用结算的自定义表格单元格、系统表格、主数据、历史版本记录和审计事实文本均统一格式化；禁止自定义单元格绕过格式化直接渲染原始 ISO 字符串。
- `tests/ui/beijing-time-rendering.test.mjs` 测试 UTC/带偏移/SQLite UTC、多种机器时区及静态源码拦截；`tests/e2e/visual-audit-browser.mjs` 在 12 业务模块、详情、弹窗、多宽度和明暗主题下扫描原始时间戳。该测试曾识别专业需求页原始 ISO 时间，已修复并重新通过视觉审查。

## 四、子项目状态与显式解绑

- 子项目管理列表增加「全部项目、储备、已入库、已批准、已结项」选项卡，项目状态列不可隐藏。两者使用同一 `status` 过滤条件，精确匹配，分页/排序继续保留。
- 当前需求仍在项目**最新正式批准范围**内，或某个未完成批准草稿仍引用它时，禁用「显式解绑」并解释要先在「批准与变更」将需求移出。项目已删除、无当前关联、无权限同样禁用；尚未批准且无草稿占用的正常解绑继续允许。
- 服务端在数据库写入前预校验，给出带明确原因的业务冲突（HTTP 409），不把 `ERR_SQLITE_ERROR` 作为普通用户业务提示。SQLite 触发器依旧是最终兜底。结项后的依规解绑不被误禁用。
- 原需求/项目正式历史、批准版本、范围变更和财务结算事实不改写。

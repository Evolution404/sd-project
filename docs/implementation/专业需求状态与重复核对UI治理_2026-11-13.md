# 专业需求状态与重复需求核对 UI 治理（2026-11-13）

## 本轮用户裁决

1. 需求界面只提供一列「需求状态」，可见的五种取值为：**待确认、已退回、待承接、已承接、已取消**。「待确认」不包含「已退回」。
2. 状态选项卡与表格的同一列共享筛选源；去除额外、不可见的 `handling_view` 办理视图筛选。筛选应在对应「需求状态」表头显示启用提示。
3. **不得为已承接额外存储一个业务状态。** 底层继续保存生命周期 `pending/active/returned/cancelled` 和唯一当前承接关系，查询层计算可见状态。 `active` 且有项目承接关系为「已承接」，否则「待承接」。删除只是附加的逻辑删除标记，保留原状态。
4. 需求编辑器中的数量输入与计量单位不允许换行，包括位置清单、单项编辑、批量填写。
5. 疑似重复需求核对不能要求用户退出编辑器。服务端冲突返回真实匹配 ID 和编号，编辑器内读取正式需求并显示操作、问题、位置/工作量、来源、承接状态。支持逐条比较、返回不丢草稿、明确暂存恢复；独立保留必须人工填理由并勾选确认，服务端重检匹配及理由，随后写正式版本和核对审计。

## 实现说明

- `server/database/queries/business-lists.ts`：`display_status` 查询派生字段、单列排序/过滤，取消 `handling_view`。前端 `DemandPage.vue` 的选项卡与可见状态列使用相同 `columnFilters.display_status`，不再暗中筛选其它字段。
- `server/shared/demand-display-status.ts`：集中处理生命周期与承接关系组合显示。API 直出列表、需求详情、重复核对、Excel 导出一致。
- `DemandLocationTable.vue`：数量输入框与单位使用不可折行的同行 flex 容器，控件宽度可让位于单位。现有计量单位正式版本精度校验未更改。
- `DemandDuplicateReview.vue` 和 `DemandEditor.vue`：双栏核对、真实详情、位置重合高亮、独立理由、暂存；正式保存仍经过统一权限、版本、重复匹配及审计事务。
- `tests/api/demand-status-and-duplicate.test.mjs`：五类视图状态各自独立；重复返回匹配身份，独立保留理由必填，记录审核历史。
- `tests/e2e/demand-status-duplicate-browser.mjs`：实际选项卡/可见列过滤、数量单位同行、正式记录对比、返回编辑、暂存恢复、确认并正式保存的完整浏览器旅程。

## 权限与历史

「已承接」需求不得直接退回或取消：需要依法规和系统业务规则通过正式修订或先显式解绑；已批准的项目范围依然遵循正式变更规则。「已退回」的审核事实保留，必须重新确认才可承接。状态展示的简化不减少历史事件、正式版本、权限或财务结算保护。

# 全系统界面与办理流程重构

## 页面行为

| 场景 | 交互 |
| --- | --- |
| 工作台 | 把待办理放在业务统计之前，按权限进入待确认、已入库、立项中和变更中的实际列表 |
| 外观 | 顶栏一键切换明暗并记住选择。账号菜单可以恢复跟随系统 |
| 列表与详情 | 服务端筛选、排序和分页继续使用原地址。可点业务名称查看右侧抽屉。小表单沿用对话框 |
| 专业需求 | 录入、修订及重复核对在同一办理页完成。重复比较保留录入内容，草稿可显式暂存并恢复 |
| 子项目 | 概览提供当前可办操作。编制和审核在独立页面核对完整承接范围、预算和变更差异。审核按钮直接提交正式动作 |
| 费用与结算 | 项目财务有独立办理入口。结算编制、修订、提交复核和审核分别显示对应的正式事实与动作 |
| 批量选择 | 需求与子项目支持跨页选择、导出所选，以及适用状态下的批量确认、承接或入库 |
| 共用组件 | 统一浅色、深色、列表密度、详情抽屉、操作层级和保存栏。只剩一个次操作时直接显示该按钮 |

## 业务约束

原有鉴权和服务端正式写入校验适用于每个办理页。正式批准范围继续采用整条专业需求，预算、物资、承接关系、结算和版本审计通过服务端业务接口处理。结项项目保存当时的差额快照，最新版批准范围内的需求继续受解绑保护。

## 验收口径

浏览器专项沿用实际业务身份与隔离测试库。外观与其他十二入口覆盖深浅主题与响应式布局。需求、项目、结算覆盖独立页面、返回条件、草稿记录和管理员、编辑人员、审核人员、只读人员的办理权限。真实表格的两个标黄项目继续沿用预算万元和缺失明细模拟口径。Windows 实机验收按用户安排暂缓。

## 实测结果

- 配置中的 60 个浏览器脚本均取得通过结果。执行一轮浏览器清单后，只复核受页面改动影响的失败场景及结项档案保护。
- 两个标黄项目完成 30 步模拟环境浏览器旅程，浏览器页面错误为 0。两个项目的正式批准结算金额分别为 229,449.51 元与 65,463.00 元。报告在 test-results/schema113/two-source-projects/last-run.json。
- 发现结项后项目档案按钮仍可用。现已移除入口，并在应用服务返回明确的 409 冲突，保留既有 SQLite 保护和档案历史。浏览器验证了入口消失、直接请求被拒绝及档案版本不变。
- 常规检查通过 250 个测试。Schema 验收通过 477 项约束检查和结构审计，性能专项通过 6 项。最后的档案保护修正确认了前后端构建、受影响的 7 项 API 检查和项目浏览器全流程。

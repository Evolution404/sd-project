# 表格双模式、视觉恢复及真实浏览器验收（2026-11-23）

## 问题与裁决

用户截图中 Tabulator 直接在物资列表开启 Range，导致整列蓝色、单元格选框与表头严重不协调。此前 AI 只有功能型 Playwright 回归，并未按实际屏幕阅读、对比度和查看／编辑两种状态逐一截图检查；不应称视觉实机验收合格。

本轮明确两种模式：

1. 普通查看（默认）：业务列表只读，关闭 selectableRows、selectableRange、剪贴板写入；保留 PMS 候选值复选筛选、排序、列设置和详情链接。对齐现有 Element Plus 页面字号、内外边框、主题色、行高与明暗主题。
2. 批量编辑（主动进入）：只有具备对应权限、业务状态允许时显示入口。Tabulator 才启用单元格编辑、区域选择、TSV 粘贴、撤销与重做。只读字段与越界粘贴整批拒绝，其他记录与历史版本不被静默覆盖。
3. 需求预计物资：默认只是正常明细，按钮「批量编辑」开启编辑网格，「完成编辑」只保留尚未提交的需求草稿，「取消本次编辑」恢复进入前的全部物资明细。父级仍需明确点击「保存需求版本」才成为正式事实。
4. 物资管理：管理员可对当前页进入批量编辑；仅名称、型号、规格、备注可编辑，单位、状态和编号只读。保存时先确认，后端一次事务调用每条原始 materials.save()，执行版本冲突检查和审计；一行失败全部回滚，不留下部分正式版本。取消直接丢弃浏览器草稿。编辑期间禁止切页。

## 技术实现与业务边界

- TabulatorGrid.vue 是只读列表适配器，禁止默认区域选择；视觉使用应用主题变量。
- BusinessDraftGrid.vue 使用 view/edit 模式；普通查看时停用所有 Excel 行为，编辑时才启用区域选择、剪贴板与历史。
- DemandMaterialTable.vue 明确双模式与撤销草稿入口，严格采用正式单位精度验证；DemandEditor.vue 仍是正式保存唯一入口。
- MaterialsPage.vue 有当前页批量修改草稿；server/modules/materials/http.ts 和 service.ts 新增业务批量入口。未修改 Schema113，未绕开原业务服务。
- 新批量接口仅管理员可用，最多100条，字段白名单、禁止重复身份、逐条预期版本；外层数据库事务包裹原 save 嵌套事务，任何失败全部撤回。

# 费用结算与立项桌面交付

## 项目结算

项目结算进度采用累计生效已批准结算除以当前生效批准预算。待审核、退回或草稿沿用上一生效金额，项目变更批准后采用新预算。预算未批准、为零或超出预算均如实显示。工作台、年度框架、执行协议、项目详情、结项和 Excel 共用该口径。资金组合仅汇总有正数批准预算的项目，并显示其余项目数量。旧结项快照沿用当时记录的进度并标明当时的计算口径。

子项目财务抽屉与财务办理页共用结算总览。默认打开结算记录，支持按项目总额和按子费用办理。本次完成工作量是选填项，累计工作量在项目承接需求页查看。实际费用页保留核定费用和费用科目维护。逐笔对账在具有当前生效分项明细的结算单下发起，列出的历史和新选的结算明细都限定在这张单。跨项目查询仍可查历史核对。
### 2026-11-23 本次完成工作量工作表操作指引

打开结算草稿时「本次完成工作量」默认展开，**无须逐条添加解决需求**。表中列出当前关联需求的全部作业位置，以及所选正式批准版本冻结的位置。未纳入本版的行仍显示，但不可编辑。新草稿的本次解决量默认展示 0，此 0 不自动成为待保存明细。可双击「本次解决量」「完成依据」输入；可以在可写单元格框选，粘贴 Excel 跨行数据，按 Cmd/Ctrl+Z 撤销、Shift+Cmd+Z 或 Ctrl+Y 重做。错误定位及「只看已填写」可帮助核对明细，表头可筛选和排序。冻结单位精度错误会拒绝整块粘贴；超出批准余量时提示差额，保存和审核规则由服务端决定。此前生效解决量对本单修订作自排除，以免重复计算。每个冻结单位单独汇总，不跨单位相加。

切换采用批准版本前显示已填写位置中将消失或因冻结精度变化而不可填写的行，取消切换保留原编辑内容。已有草稿和历史版本修订按原批准冻结位置身份回显解决量及依据。保存草稿不改变正式已生效事实；须继续提交和审核。


## 立项与表格

立项、变更、审核及承接需求从对应正式需求版本读取业务内容。编制页默认显示线路、操作类型、作业位置、数量、单位、作业方式、位置类型和设备规格。勾选作用于完整需求，正式办理所需位置与数量可持续核对。子项目列表补充资金归属、负责人及计划信息。需求、财务、设备、资金和工作台展示可读的业务列，列设置保留显隐、顺序、宽度和固定偏好，同类立项表格采用同一份设置。恢复默认列仅影响布局。

## 验收

- 通过桌面 Chrome 访问隔离验收库。批准预算 1,200 元、累计生效结算 12 元且核定实际费用为零时，子项目抽屉和财务页均显示 1%。进入财务默认选中结算单，新增默认按项目总额。
- 编制立项显示「110kV青禾验收线」「安装防鸟装置」「#7」「3 套」「不停电」。设备规格列可隐藏，恢复默认后需求继续勾选。
- 数据库结构门禁通过 479 项检查。性能回归通过 6 项，立项候选查询与财务分页的读取次数保持固定。
- `npm run check` 通过 267 项自动测试。浏览器专项覆盖四角色、按单对账、跨页候选、历史批准版本、立项和变更、结项冻结，以及需求到结项的训练实操。十二入口的桌面视觉回归覆盖浅色、深色和四种桌面窗口宽度。
- 两个标黄项目用隔离测试数据重新跑完了需求登记与修订、项目立项与变更、分期结算、退回重提、差异结项和重启。最终按各自最新批准预算计算的结算进度为 22.39% 和 7.30%。


## 2026-11-23 Node 26 迁移后终态

当前主版本统一为 Node 26（宿主 v26.12.0、Windows x64 正式/演示包采用同版），取消 Node 24 运行时门禁和依赖。针对通用表格列设置再次打开时状态可能不一致的问题，修复复选框复用与隐藏列去重；需求位置的物理杆塔、逻辑杆塔、档距表格和排序经重测通过。全量 `npm run check` 268 项、Schema 479 项、性能 6 项、完整 `npm run test:browser` 全通过。标黄两项目的结算进度仍为 22.39% 和 7.30%。具体日志、范围和发布边界见《2026-11-23 Node 26 迁移与费用结算、立项桌面最终验收》。

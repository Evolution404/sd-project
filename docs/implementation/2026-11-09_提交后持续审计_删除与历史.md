# sd_project 提交后持续审计：删除、审计历史及财务界面（2026-11-09）

## 审计基线
主线基线提交：`6a62316`（价格治理、全空库集成与 UI 验收）。本轮进一步复查主数据关联删除、财务实体重复删除、删除后的修改权限与 760px UI；在隔离临时数据库和真实浏览器执行，未变更真实数据目录，也未变更 Schema113 SQL。

## 已复现且修复的缺陷

1. **已升级价格特征的旧参考价无法删除。** 价格规则删除原本调用 `save(... status:inactive)` 追加一条新的正式价格版本，受“价格特征必须引用最新版本”的数据库约束拦截。现将参考价格的“删除”明确为独立的审计逻辑墓碑：不伪造新的价格定义；正常查询与新报价排除已删除规则，`deleted=true` 可查看原规则与删除事实，历史正式报价仍保留。原“删除会强制新增一条停用价格定义版本”的旧测试已同步修订。主动修订/停用规则与删除不混淆。
2. **重复删除费用及费用科目会制造重复删除审计记录。** 已分别在删除费用、费用科目、费用核对和结算单的事务中增加删除事实核验，重复请求返回明确状态错误，保证历史只追加一次删除事件。
3. **已删除结算单可能通过底层接口继续提交、审核或清理草稿。** 已对 `submit`、`review`、`discardDraft` 增加已删除状态检查。历史查询不受影响。
4. **“包含已删除费用”界面的删除状态可见性和只读属性不完整。** 已把费用的删除状态显式返回给前端，费用和科目在历史查看模式显示“已删除”，禁用更正、撤销、编辑、重复删除；附件继续可读。
5. **760px 项目财务详情的实际费用表状态列被固定操作列部分遮挡。** 重排“事项—状态—金额—日期”顺序，收敛默认宽度和操作列宽，新增实测遮挡断言。截图：`test-results/schema113/finance-deleted/deleted-finance-760.png`。
6. **重新载入自定义列宽后偶发未铺满页面。** 完整浏览器回归在已保存列宽场景实际捕获“表格容器1150px而内层主体702px”的短暂错误。已在 `BusinessTable.vue` 的列偏好恢复后主动调用 Element Plus `doLayout()`；`table-fill-modal-browser.mjs` 补充稳定布局的显式等待与尺寸检查，单项连续重复通过。

## 尚需下一轮数据库版本治理的边界
**正式停用（区别于删除）一个仍引用旧版本价格特征的参考价格规则仍会受 Schema113 的“新增价格版本必须使用最新价格特征”触发器约束。** 已在隔离库复现。现在通过“删除”可以安全停止规则参与新报价并保留历史；若业务需要“停用后可再次启用”或“保留原条件同时追加停用正式版本”，应以新的正式数据库结构版本统一设计该例外、可核验的历史引用及升级路径。不要为了绕过约束把旧特征自动替换成新特征，或给正式价格版本写入失真的空条件。此项不宣称已经修复。

## 安全边界
此次审计只改应用层、UI 和测试；未清理/迁移/覆盖用户实际 SQLite，未自动推送远程 Git。已有的原始费用、结算与确认报价历史不可变。

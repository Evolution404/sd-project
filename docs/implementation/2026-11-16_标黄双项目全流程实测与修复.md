## 已复现并修复的问题

| 问题 | 复现结果 | 修复 |
| --- | --- | --- |
| 批准表单异步覆盖输入 | 弹窗已允许输入时，候选加载结束重置表单，两项目实际保存预算曾变成0 | 先初始化预算，加载期间禁用表单与保存，增加请求序号和项目校验，失败可重试 |
| 结算修订无法复制明细 | 对Vue响应式数组直接structuredClone失败，弹窗已打开但表单未完成初始化 | 对原始业务数组深拷贝，保留金额、需求解决量和乐观版本 |
| 修订动作默认值不正确 | 首次正式结算的修订表单沿用initial，选择器无法显示完整修订 | 根据已有正式版本默认完整修订，继续编辑注销草稿时保留注销动作 |
| 历史批准版本无法回选 | 项目变更后编辑原结算，选择器只有最新批准版本 | 显式加载完整批准历史，需求选项与数量精度跟随所选批准的冻结需求版本 |
| 结算草稿缺少撤回入口 | 存在未提交修订时阻止结项，页面缺少对应撤回操作 | 提供写入权限控制的撤回操作，分别处理首次草稿和已有正式版本的修订 |
| 撤回的并发保护不足 | 未核对正式版本，撤回后重建草稿复用编辑版本1，旧请求可以误撤新草稿 | 同时核对正式版本和编辑版本，从不可变撤回审计取得已用编辑版本上界 |
| 首次草稿撤回留下空单据 | 草稿删除后空根仍留在列表，并被数据库视为未核定结算 | 撤回后追加逻辑删除审计，保留身份与撤回内容，结项守卫识别已删除且从未正式提交的根 |
| 空预连接阻碍关闭 | 重启验收时浏览器有已连接但未发送请求的TCP预连接，server.close一直等待 | 服务关闭入口停止接入并关闭零字节预连接，已开始请求继续完成，正式启动与浏览器重启共用该入口 |
| 缺价试算误报过期 | 初次试算返回缺价时，界面自动补空计价对象，刚完成的试算被误报为条件已修改 | 试算快照同步同一空对象初始化，用户实际改动仍按原请求快照比较 |
| 撤回缺少完整审计 | 草稿内容删除后没有对应撤回事实 | 在同一事务冻结撤回前完整草稿、编辑版本、操作者及保留的正式版本身份 |

本轮交互未新增必须人工填写的字段。批准加载、数量单位和并发版本均自动处理。撤回需要用户明确确认，正式审核仍由有权限的用户执行。

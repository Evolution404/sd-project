# 专业需求完整承接与 Demo 扩充实施记录（2026-11-13）

## 当前裁决

- 项目承接对象是完整的专业需求，不是其内部位置/数量的份额；需求集合可以按整条纳入/移除。
- 同一需求当前仅有一个项目归属；项目关联禁止传入另一个“承接数量”。
- 立项及正式变更采用需求最新正式版本的全部位置和数量；若要实施部分工作，先正式修订需求。若剩余工作仍有效，应显式拆分、形成独立正式需求，不能无声抹去剩余工作。
- 既有已批准项目需要新批准变更才能更新采用需求版本；已批准历史和已发生的多次结算保留。**完整承接与分次施工/多次结算互不冲突。**
- 项目级的物资批准依旧按现行独立物资审批差异规则处理，不隐含禁止真实现场追加/调整物资。

## 代码调整

- `server/modules/projects/service.ts`：联动数量一律采用需求正式总量；批准明细数量与每个位置精确一致，未包含所有位置时报业务错误并保留回滚。
- `server/modules/projects/requests.ts` 与 `server/shared/types/projects.ts`：移除关联数量字段，HTTP收到旧部分承接输入直接拒绝。
- `web/src/modules/projects/ProjectPage.vue`：整条需求仍可勾选纳入批准，需求内部位置与数量只读，不允许按位置勾选或修改数值。
- `server/database/schema/schema113.sql`：在正式批准写入时再次校验需求位置全覆盖和逐位置数量严格一致，防止绕过应用层写入。

## 参考价格后续重构关系（尚需独立完成）

最新要求是需求参考价自动计算、无人工“确认报价”；本轮完整承接使项目定价无需按比例分摊。应复用需求正式版本的计价范围，但在项目级/批次级独立收费时仍必须分清作用域，保留当次项目批准计价快照。需求新版本、规则新版本与既有批准快照相互独立。当前旧试算/确认逻辑仍在代码中，不可把本轮完整承接修改冒充参考价自动化全部完成。

## 隔离 Demo 数据（全部虚构）

种子脚本：`scripts/demo/seed-demo.mjs`；新种子标记 `SEED_VERSION=4`。仅本地 demo 目录允许依现有锁与备份归档机制安全刷新，非 demo 数据目录不允许覆盖。

- 6条不同电压等级演示线路、72基物理杆塔、72个逻辑杆塔、66个档距。
- 10种操作类型、11条规则覆盖八种计价模型：fixed、per_unit、base_plus_unit、quantity_bracket、progressive_bracket、group、rate、composite。
- 24条需求、16个子项目；示例涵盖储备、入库、立项草稿、批准及既有多次结算。
- 演示规则价格与人工费基数均为虚构，不得作为工程计价标准；演示数字身份由服务端生成，时间日期按业务时点确定。
- 计价模型数据由现有服务直接计算并在隔离数据库保存计算事实；新自动计价系统尚未交付。

## 验收口径

1. 后端禁止传入部分关联数量，单位置数量更改、缺少位置或重复位置均禁止产生合法批准草稿。
2. 即使绕过服务层，SQLite正式批准也须拒绝未完整纳入需求位置/数量。
3. 需求正式修订后，新批准版采用整条新版需求；旧批准金额和已审核结算不变。
4. 已入库、批准、变更中及结项需求正常可看历史；分次结算仍可有少量或超量解决量。
5. demo 的八种模型可独立验证每个公式；独立环境的全部结构与外键检查通过，已有原 demo 仅在受控归档后更新。
6. `npm run check`、`npm run check:schema`、`npm run test:browser`、`npm run test:performance` 与 Windows demo 打包/核验通过后再宣称发布收口。

## 跨模块定位与单一入口规则
- 路由上下文只传现有身份（demand/project）、分区（section）和具体记录（record），普通列表筛选仍使用原有 useListRoute。
- 不增加「下一步状态」数据库列；操作信息由当前服务端事实和权限派生，前端展示不可替代服务端校验。
- 跨模块跳转允许通过路由统一参数，禁止每个页面再发明独立隐藏协议。
- 对未保存表单必须保持现有草稿关闭确认；跨页面跳转先走同一确认机制或保留编辑器。

## 本轮效率基线
当前需求保存后用户通常需再次在清单定位→打开需求→确认→去项目侧栏→进入项目→发起关联→重新选择需求。该流程至少存在三次不必要对象定位；优化后目标为保存后直接查看详情并从详情进入已预选需求的承接操作。
当前跨项目结算查询需先「进入项目」再手工寻找结算单；优化目标是列表一次「查看结算单」直达其正式详情。

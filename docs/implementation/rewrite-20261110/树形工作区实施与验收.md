# 费用科目与归口单位树形工作区

2026-11-10。本轮在 `sd_project-rewrite`、`codex/full-rewrite-20261110` 上承接整体重写。原仓库、正式服务、演示服务及其数据目录保持独立。所有测试用临时目录，示例组织及费用只存在于测试夹具。

## 功能与操作

费用科目位于子项目详情的费用与结算页签，左侧是当前项目的费用树，右侧是所选科目的完整路径、状态、正式版本、下级和末级清单、实际费用及准确归属的正式结算金额。关联实际费用按30条分页，可打开费用及历史模态框。宽屏左右分栏，1000px以下上下排列，长树内部滚动。

新增科目可以留空上级建立根节点，新增下级自动采用所选父级。编辑只修订名称和状态，父级以只读文字显示。服务端对显式篡改parent_id直接拒绝，数据库稳定层级约束继续生效。新增子项检查整条祖先路径，已存在费用或结算历史引用的末级不能再加子项。删除展示下级和正式引用数量，并在事务内复检，保留原节点、版本、引用和审计。已删除节点可勾选查询，失效祖先仍显示在可见后代路径中。

归口单位位于基础数据原有归口单位页签，主工作区改为组织树和单位资料。支持多个真实根单位、直属下级、当前关联子项目及其采用的历史单位名称、项目资料模态框、正式版本和组织历史。新增直属下级自动带入父级。普通资料编辑不展示可修改的父级控件。

调整上级使用独立模态框。用户选择有效目标或清空为根单位，预览前后路径、受影响后代和关联项目数，明确确认。服务端在事务内复核权限、源版本、目标定义及完整层级预览摘要，阻止自身、后代、失效目标及并发过期提交，然后新增正式组织版本。无拖拽移动。项目同一归口单位身份的档案修订继续保留原采用版本，单位改名、删除和移动均不改写原项目引用。

两套树共享搜索、祖先展开、多根构建、展开折叠、选中高亮、刷新定位、异常层级安全处理及空状态。费用与组织的可选规则由各领域提供。费用只能新选有效末级且祖先全有效，组织可以选择任意合法层级。历史原值显示采用版本名称及路径。内部身份由服务端使用，业务控件不要求用户填写技术编码。

## 人工输入与步骤

新增根费用科目和根单位各只需输入真实名称，状态默认启用，上级留空。新增下级同样只需输入名称，父级从当前节点带入。用户可按真实组织或费用分类改选合法上级，技术编码、正式版本、操作人和时间均由系统取得。

普通版本编辑填写真实名称或状态变化，保存一次。费用层级无移动步骤。组织移动需要选择目标上级、预览、确认三个动作，根单位通过清空选择表达。目标是人作出的组织归属判断，预览和确认用于审核影响。影响数量、路径、版本及预览摘要自动计算，不增加人工填写。

查看节点单击一次，在当前工作区查询专用详情。展开折叠无需请求。历史及关联业务使用模态框，关闭后保持背景树的搜索、展开和选中状态。

## 金额与历史

当前实际费用来自各费用事项的当前正式active版本，排除逻辑删除。子树按稳定科目身份聚合一次。撤销、删除及被替代的版本保留在历史视图，不计入当前金额。

正式结算金额从有效已批准结算版本及明细的稳定科目身份直接归属，排除正式注销和删除。项目预算不分配到科目。不存在手工父级累计金额和比例分摊。

组织历史路径依据组织正式版本及对应审计追加顺序重建，避免同一毫秒中多次变更混用新父级。历史审计缺失时标明路径不完整，不套用最新父级。没有增加存储路径、汇总金额或树表。

## API

| 方法与路径 | 行为 |
| --- | --- |
| GET /api/projects/:id/cost-tree | 该项目全部科目、当前汇总和可选资格 |
| GET /api/projects/:id/cost-tree/:nodeId?page=1 | 子树费用分页、版本及审计 |
| POST /api/projects/:id/nodes[/nodeId] | 原有创建与正式版本修订，禁止移动父级 |
| DELETE /api/projects/:id/nodes/:nodeId | 删除版本及影响复核 |
| GET /api/organizations | 当前组织关系及状态、历史删除标记 |
| GET /api/organizations/:id | 当前关联项目、版本、历史路径、引用与审计 |
| GET /api/organizations/:id/move-preview?parent_id= | 管理员组织移动影响预览 |
| POST /api/organizations/:id/parent | 预览摘要及源版本复检，新增组织版本 |
| POST /api/catalog/organizations[/id] | 原正式组织创建或资料版本修订 |
| DELETE /api/catalog/organizations/:id | 专用组织删除影响复检后保留历史 |

全部HTTP入口保留现有登录、IP、权限及写入幂等处理。读权限不扩大写权限。

## 数据库与性能

Schema113权威SQL没有修改，无迁移。77 STRICT表、27视图、250触发器、78显式索引、728字段。没有冗余树、路径或金额事实。

专用Repository对费用树与组织树分别执行一次集合查询，科目详情和单位详情各执行固定四次查询。应用层另有身份存在性复核。节点数量从10增至500不增加查询数。普通展开折叠在前端完成，节点选择只加载专用详情，无完整项目重新查询。

真实库一次测量，500费用科目和500组织的两棵树及两份详情合计75ms。原1000线路、10000逻辑杆塔搜索分页82ms。时间为当前Mac一次执行值，查询次数由测试硬断言。

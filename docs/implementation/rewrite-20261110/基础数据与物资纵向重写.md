# 基础数据与物资纵向重写

2026-11-10，承接设备阶段724001b，继续P2基础数据与设备领域。

## 领域与数据库边界

计量单位、优先级、项目类别及组织正式定义进入独立DictionaryService，物资进入独立MaterialService。两个应用服务均为严格TypeScript，使用限定业务实体的Repository，角色、版本、事务、稳定身份及不可变审计由同一正式用例处理。Catalog只对既有跨领域调用分派，不保留第二套P2写入实现。组织移动及影响复核继续由OrganizationService编排，正式版本直接调用DictionaryService。

新增文件包括shared/types/master-data.ts，database/repositories/dictionaries.ts和materials.ts，modules/dictionaries及materials的service.ts、http.ts。组合根和资源注册明确注入依赖。

没有修改Schema113，没有增加重复当前状态、路径或金额。新的技术身份仍在服务端生成。全部正式历史通过原有实体和版本结构保存。

## 数据保护修正

字典普通修订保留既有sort_order和fields_json，避免表单未展示的旧正式事实被默认值覆盖。物资修订保留既有category_id、未编辑型号规格及稳定unit_id，名称或状态修改不会静默清空分类。新增回归使用隔离的旧事实夹具验证这些情形。

物资修改界面以只读业务名称展示原计量单位。服务端独立拒绝改挂单位身份。原单位删除后，既有物资仍可修订与查看，新的物资不得再选用它。缺少旧单位正式定义的历史物资继续可见，名称明确标示待核对，不通过内连接丢弃该记录。

组织父级版本、历史名称和项目采用版本的树形规则继续有效。组织资料及移动均生成正式版本，树形历史仍从追加审计顺序追溯。

## 查询与删除

基础字典和物资列表复用数据库内部的白名单分页查询，筛选、排序和分页在SQLite执行。物资按单位名称筛选，服务端在同一集合查询中取得名称、型号规格和单位显示信息，无逐行查询补名。

删除影响从当前权威外键关系计算，排除实体自己的定义历史，并补充单位在正式价格特征配置中的关联。数据库模块从canonical schema构建查询计划，只缓存结构计划，引用事实每次实时计数。删除提交在事务内复核正式版本和预览引用数量，预览后出现新关联会返回冲突。逻辑删除保留所有关联及版本，审计记录实际影响。

基础字典和物资详情新增history=true的类型化聚合响应，包含当前item、完整versions及audits。页面用一次详情请求取得这些信息，并由共用实体模态框的请求序号保护，避免快速切换时旧历史覆盖当前实体。

## 前端

基础数据由DictionaryWorkspace按原正式路由展示电压EquipmentPage、OrganizationWorkspace和三个简单字典的DictionaryPage。共用DictionaryTabs承担五个基础页签，取消重复页签模板。

物资使用独立MaterialsPage，包含名称、单位、型号、规格、状态、备注、正式版本和审计。原CatalogPage不再承担基础数据或物资工作区。

两个新页面保留BusinessTable、强类型行、双向排序循环、筛选清除、列偏好、URL列表状态、业务详情模态框、草稿取消保护、只读权限及删除历史。业务界面无手工技术编码。新增物资需要真实名称与计量单位，其余事实按需填写，物资修订不重复选择单位。

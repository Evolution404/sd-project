# 计量单位数量精度：纳入全系统 P2→P9 重构

状态：2026-11-11 P0数量精度、Schema113与隔离测试数据重建已完成独立收口，149项全部工程/API/Excel单元测试及475项Schema契约通过。单位正式版本必须显式包含0～4位精度，拒绝缺失元数据，现有新建/演示数据完整补齐；含批量原子失败、合法部分提交及纠错重试。P1～P8整体重构、14条连续旅程及P9 Windows实机仍须后续验收。

## 业务约束

计量单位正式版本配置数量允许的最大小数位 `quantity_precision`（整数0～4），新增单位默认0位（整数）。例如个、套、台、基为整数；工日、米、平方米按配置允许1～4位。禁止防鸟装置按“个”录入0.5，同时保留对可分计量单位的合法小数。

仍使用Schema113中 `quantity_scaled`×10000定点整数、金额整数分；不用浮点存储，不做自动四舍五入，不对费用超支、工程量不足/超量增加业务限制。数量精度并非数量上限或总量校验。

## 实施与验收顺序

1. **P2 / 基础数据**：数量精度保存在版本化 `dictionary_item_versions.fields_json`，管理员维护单选0/1/2/3/4，列表、详情、历史展示。正式版本必须验证格式和范围。**开发阶段不保留旧配置的兼容分支**：新增和现有单位均需显式补齐精度；基础单位“个、套、台、基”等设0，其余根据计量属性设置。无精度元数据按系统默认整数处理，补齐现存单位数据。
2. **P3 / 作业标准**：操作类型继续冻结 `default_unit_id`、`default_unit_version`；新的精度通过正式操作新版本采用，旧版操作、需求、批准和结算不漂移。
3. **P4 / 需求、物资**：公共严格类型的领域校验 `scaled % 10 ** (4 - precision) === 0`。逐位置工作量与预计物资按各自冻结单位版本校验，422包含字段路径、单位及允许位数。前端依据精度设置数字输入，不以UI代替后端检查。
4. **P5 / 项目、批准与变更**：批准位置数量、分批承接、物资数量按其引用的冻结单位版本验证；保护已批准历史与变更差异，允许合法的不足/超出。
5. **P6 / 财务结算**：解决量、结算项实际计量按真实业务关联的单位版本验证，价格模型金额类字段不套用数量单位；历史更正与撤回不得回写原事实。
6. **P7 / Excel**：中文模板说明精度，预检与整批提交共用正式业务校验；错误精确至行列，保证幂等、事务原子、部分选择与旧明细保留。
7. **P8 / 系统收口**：共用一套版本解析和精度校验，清除各模块自有重复规则；避免列表/批次按数量逐行查询单位（N+1），UI、权限与删除影响统一。
8. **P9 / 门禁发布**：0～4位边界、0/负数语义、溢出、并发版本冲突、原有单位精度补齐、整数反例0.5个、合法正例0.25平方米、API绕开UI、需求多位置、物资、批准变更、解决量/结算、Excel预检/提交；A1～E3业务旅程、Node24全门禁、Windows10离线包与实机分别验证。

## 迁移和历史语义

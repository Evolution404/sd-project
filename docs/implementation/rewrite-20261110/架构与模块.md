# 架构与模块

## 运行链

`npm run build` 分别构建服务端和前端，分别输出dist/server与dist/web。`npm start` 执行dist/server/main.js，bootstrap组合领域服务，HTTP按资源注册路由。SQLite结构、连接、保存点、Repository及查询仅在database模块。

HTTP承担套接字/IP、登录会话、正文与幂等上下文、静态资源和错误转换。各领域http文件只将请求交给相应应用用例。领域纯计价、特征校验、定点数和错误不依赖驱动。

## 类型与数据读取边界（2026-11-17核对）

server目录全部采用严格TypeScript，tsconfig.server.json仅包含server/**/*.ts，未启用allowJs或checkJs。Node26执行正式编译产物。手写前端和服务端均由架构门禁检查显式any、类型检查抑制、循环依赖和共享组件反向依赖。

项目、财务、设备、需求、物资、作业标准、资金与交换使用各自明确类型和命名Repository。Catalog负责目录分派，各领域自行完成校验和正式写入。公共目录和系统动态字段的Row为Record<string, unknown>，动态列展示时检查值类型。

项目工作区只读取当前正式批准及有效草稿，完整批准历史按需加载。批准候选、批准位置及物资按集合读取。项目内费用、结算、费用核对的筛选、排序及分页由finance-lists Repository处理，结算当前页正式版本、草稿、审核、明细与解决量批量读取。完整导出和历史查询沿用对应显式业务用例。

实际补验、当前阶段状态及保留的验收限制见《2026-11-17_验收矩阵核对与项目财务分页收口.md》。

## 发布

Windows包运行dist/server/main.js，包含Node26、dist/web、dist/server、生产依赖、管理脚本和Schema。Manifest分别记录服务端源文件和编译文件SHA256。解压根data独立保留。宿主验证不能代替Windows实机CMD、PowerShell、防火墙及锁文件验证。

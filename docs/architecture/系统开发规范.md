# 系统开发规范

当前业务裁决汇总见 `当前业务规则.md`。操作类型采用基本定义（含固定计量单位）、录入模板、附加属性、正式版本与引用四个实际页签，统一属性按2026-11-12最新作业对象双维度裁决执行。

当前执行版本为独立Schema113。历史检修计划、施工执行与领退料示例属于旧版讨论，当前实体范围以Schema113接入报告和权威SQL为准。涉及旧税率口径的讨论已由用户的完全移除裁决废止。

**最新 UI/架构约束：** 以《技术债治理实施计划_G0-G7_2026-10-30.md》为准。Element Plus 为通用业务 UI 组件库；2026-11-23 用户另授权 Tabulator 6.x 作为唯一专业数据网格引擎，逐步替代 BusinessTable 内 Element Plus 表格，保留严格 UI 门禁与统一业务写入命令；当前开发阶段不做任何旧版数据库、旧 API 或旧 UI 技术兼容。业务版本、批准依据、审计及历史凭证必须按现行规则留存，不属于技术兼容负担。

生效日期：2026-10-30。依据：用户明确要求“所有数据都应该能增、删、改、查；特殊情况无法实现让我授权审核”。本条为强制交付要求，适用于当前整改和后续全部开发。与旧文档冲突时，按用户最新裁决处理；涉及尚未批准的特殊限制，提交用户审核，不自行扩大旧规则为豁免。

## 1. 完整增删改查是默认能力

覆盖基础台账、需求、项目框架、协议、子项目、物资、费用、结算、参考价、系统字典、配置、附件、用户以及历史和审计数据。系统内置内容不是禁止编辑或删除的理由。

每一种用户管理的数据对象，应具备：

| 能力 | 最低交付标准 |
| --- | --- |
| 新增 | 具备界面和服务端校验；系统可生成的信息不要求用户重复填写 |
| 查询 | 可按业务条件检索、查看详情；逻辑删除记录有明确的历史查询入口 |
| 修改 | 可修改业务内容；影响已确认事实时，采用版本/更正流程并说明影响，不静默覆盖 |
| 删除 | 有明确入口和确认反馈；正常列表移除、不再供新增业务选用，已有引用有完整处理方案 |

不得以“只能停用”“只能取消”“系统内置”“有外键”等提示代替删除功能并标记完成。停用和删除是不同操作，状态、列表及交互须明确区分。

## 2. 删除与修改的关联处理

无引用的数据可直接删除，并留下操作依据。有引用的数据应优先设计逻辑删除、引用迁移、版本式更正等可行方式；逻辑删除须同步约束所有正常列表、可选项、详情写入及批量接口，并允许查询删除记录。原始位置、工作量、价格、批准依据及费用不能因删除字典而漂移。

删除前展示关联和影响；在提交事务内重新检查版本与引用，防止预览后出现的新引用被误删。未经明确授权，不自动级联删除需求、项目、费用、结算或历史记录，不把逻辑删除偷换成永久清除。

系统预置数据删除后，启动、升级、初始化补齐及导入不得擅自恢复该项。用户明确再次新增同名内容，是新的录入行为，应使用新的稳定标识。

权限须由服务端校验。“支持增删改查”不代表所有账号无差别拥有权限，但相应能力必须能通过被授权的用户完成。

## 3. 特殊情况须经用户授权审核

遇到确实无法提供某项能力的情况，必须形成具体审核材料：

1. 对象、字段/状态、缺少的操作及当前入口。
2. 技术或业务原因，实际数据关系及可复现的限制。
3. 可实施的替代方案、操作步骤、对金额/历史/引用的影响。
4. 验收标准、待用户批准的范围，以及未批准时保留的整改项。

应先完成与该裁决无关且已授权的工作，再把可审查的方案提交用户。用户没有回复不等于授权。旧代码、数据库触发器、文档或开发者判断本身均不构成豁免授权。

现状与授权记录见《增删改查_待授权审核清单.md》。用户于 2026-10-30 已明确授权其中 R01–R05 采用“保留原始事实，补齐更正/撤销或逻辑删除及历史查询”的处理方向，无需重复申请同一方向。功能仍须实施并通过验收，不属于免做增删改查的豁免。普通功能缺失属于待实现，不应包装成无法实现的特殊情况。

## 4. 当前字典实现口径

内置词条和自定义词条统一支持增删改查。无引用时直接删除；有业务、配置、草稿或历史引用时逻辑删除，保留关联记录，正常列表与新增选项不再提供该词条。“已删除”筛选用于查询删除记录；不能从普通编辑/启用接口恢复已删除记录。

删除操作留存审计，并记录删除方式及引用依据；内置补齐读取删除决定，重启不会复活。此实现不需要重建当前 SQLite 数据库。

## 5. 交付门禁

每个数据模块在验收前列出新增、查询、修改、删除的界面与 API。验证正常操作、角色权限、有关联时的处理、并发冲突、删除历史查询以及重启一致性。仅菜单占位或仅后端接口不算完成。

如仍有功能缺失、被数据库规则拦截或待用户审核的例外，必须在进展和交接中明确列出，不能宣称该模块已完整满足本规范。

## 6. 2026-11-03 UI门禁与操作定义补充

业务UI只能使用完整加载官方样式的Element Plus组件。禁止用ElInput的原生date、number、file等type绕过组件约束；全部ElForm禁用浏览器原生表单校验。新增组件时同步注册官方CSS，上传内部file输入必须不可见。`npm test`、`check:ui`及`check:ui:strict`均检查这些要求；不得提高旧数量基线或让浏览器测试适配原生select来绕过。

操作类型必须定义自己的固定计量单位和唯一作业对象。新录入先选择操作，单位和对象自动带出；Excel中留空可按定义补齐，显式冲突必须修正后提交。数量不自动换算。定义修改采用配置版本，不覆盖任何已有业务采用的单位、对象、数量和快照；旧配置不完整时保留原数据并提示维护，不自动补造。


## 2026-11-12 作业对象分类与操作类型维护权威规范（取代2026-11-03旧版）

- 作业对象正式版本必须分别包含对象位置（本体、通道）与归属单元（物理杆塔、逻辑杆塔），两维度唯一来源均在对象，不能由操作类型再配置。
- 操作类型只关联一个作业对象及其不可变正式版本，另存固定计量单位和正式单位版本、建议数量、模板、验收标准、统一附加属性。旧的 operation scope 四字段已从权威数据库及API定义移除，禁止为历史测试实现兼容。
- 操作类型维护四页签：基本定义（固定计量单位在此）、录入模板、附加属性、正式版本与引用；不得恢复“作业范围与计量”页签。
- 新建与变更作业对象通过不可变版本记录；操作类型如需采用对象更新后的定义，须显式发布引用新版对象的操作版本。需求按采用时的正式定义冻结分类和定位，不得反向重算历史。
- 需求按物理或逻辑杆塔归属身份校验、去重；通道逻辑归属可具体定位到档距，档距不作为第三类归属单元。业务事实、数量、计价仍由实际需求点位决定。

## 2026-11-08 Schema113 接入补充

本次整体重写使用独立 schema113.sqlite，结构只来自 server/database/schema/schema113.sql。用户补充要求系统完全不处理税率。未批准草稿的删除采用有真实审计的撤回，正式核价、范围和证据历史保留。设备台账删除与设备真实运行状态分别记录。金额执行口径、源码目录、验收及Windows平台边界见 docs/implementation/Schema113_重写交付与验收_2026-11-08.md。

## 最终治理门禁

业务层与HTTP通过Repository及应用用例访问数据。单条实体删除检查使用isDeleted按身份查询，列表可一次取得删除集合，不能在循环内反复全量扫描审计。来源当前投影按需求真实关联查询，已有正式采用的物资版本随需求历史保留。

SQLite预编译语句采用256条LRU上限。测试覆盖淘汰、事务内可见性和回滚后复检。npm test同时执行严格UI门禁，TypeScript检查未使用声明。无税务模型检查纳入check和Windows打包。

构建输出固定dist/web，发布包采用校验后的临时ZIP替换。Windows正式版和演示版允许以未提交的源码打包：清单如实记录Git基线、dirty状态及全部构建输入SHA256，结束校验基线未变化且真实输入文件未变化，绝不声称dirty包可完全由Git提交复现。test:package读取实际ZIP并重建前端验证包保留，随后验证生产依赖、源码一致、登录、持久化、附件与备份恢复。Windows实机状态单独记录。

生产安装使用omit=dev和omit=optional，防止Vue的可选同级依赖TypeScript进入离线包。ExcelJS的uuid覆盖固定为已验证的11.1.1，依赖更新必须保留CommonJS及工作簿往返回归，并使用提供安全公告接口的官方源审计。

## 2026-11-09 独立业务与输入字段评估

系统独立管理全部业务，任何专用外部编码、一次性专用导入、映射、别名及兼容设计均已废止。现行依据为 docs/decisions/2026-11-09_系统独立_自动编码_最少录入.md。历史文档仅供审计。

新增每个用户输入字段前，先记录其真实业务含义，再核查能否服务端生成、从已选对象关联或从正式关系推导。可生成的技术身份、单位、作业对象及定义版本自动处理。仅将无法推导的真实事实和授权判断交给用户。不能从数据库必填列直接推导界面必填项。

全部内部编码由服务端创建，客户端提交的技术编码不能决定新对象身份。已有稳定身份保持不可修改。普通杆塔一次保存建立物理实体、逻辑回路及关联，共塔必须明确选择，同号歧义不能自动合并。整基更换保留旧实物、回路历史和真实操作者的更换审计。维护 Excel 允许隐藏保护身份和版本，新建 Excel 不要求手工身份。永久门禁 check:independent-input、专项 API、Excel 和浏览器测试随 check 与发布执行。

## 页面标题与操作区布局

界面只面向桌面浏览器。布局和交互按桌面端设计，验收覆盖桌面窗口与桌面缩窗，包含鼠标和键盘操作。手机端方案、尺寸适配、触屏交互和验收不属于本项目范围。

页面标题采用标题区和操作区两个布局项，全部标题操作集中在page-heading-actions内。按钮间距由统一gap管理，组件默认相邻按钮外边距在该区域内归零。宽屏整体靠右，窄屏随标题切换为左对齐并允许组内换行。新增导入、导出或批量操作入口时继续使用此区域。

UI的AST门禁检查标题结构，check与package:win均执行。浏览器回归必须检查实际按钮间距、同行对齐、标题与操作区分离、边界及窄屏换行，并同时覆盖多个操作和仅单个操作的情况。页面没有横向溢出不能单独作为布局验收通过依据。

## 2026-11-12 统一属性与需求Excel

操作正式版本的attributes_schema_json是属性定义唯一来源。需求正式snapshot_json中的attributes及work_locations[].attributes保存正式值，位置attributes_json由数据库原子投影。参考价格additional_conditions_json引用本操作正式版本的属性key。小数以精确十进制文本存储，使用BigInt定点匹配。停用属性不供新定义填写，历史继续解释原采用版本。

需求多位置表使用稳定客户端行身份，服务端错误映射到该身份。批量赋值仅修改勾选字段。来源遗漏保持，明确删除追加审计，更正保留旧事实。

需求Excel使用导入关联号及位置关联号，物理行号只定位问题。动态属性列使用定义名称元数据绑定，中文表头允许编辑。三个核心业务Sheet为需求清单、作业位置、预计物资，补充来源按需使用。网页、API与Excel共用领域校验，正式编号由服务端生成，回执支持按导入关联号回查。

## 业务页面与确认交互

快速详情使用右侧抽屉。编辑和浏览使用同一业务身份和正式版本。包含多段录入和复核的流程采用正式路由，页面提供可见标题、返回入口和保存或审核区域。短编辑、对象选择和单步确认沿用 Element Plus。

进入办理前记录来源地址和滚动位置。页面返回恢复原有条件，列表查询参数不存放表单内容。已提交的审核与版本动作仍通过领域接口校验权限、状态、版本和幂等。确认页展示办理对象与结果影响，正式按钮直接提交。


## 2026-11-23 专业网格与 Excel 粘贴

- 物资列表使用 `TabulatorGrid`。将筛选箭头放在单行标题右侧，明暗主题共用布局。查看模式保留原表头，数据区按普通业务列表呈现并仅显示行分隔线。预计物资查看使用清单。查看模式提供详情入口、单列升降序、列隐藏、顺序、宽度和左侧固定。缩窗后的横向滚动由网格承载。
- 列筛选的菜单草稿、正式列表条件各自有明确生效点。URL 持有已应用条件、排序和分页，SQLite 统一执行名单内筛选、候选分组、分页和数量统计。候选统计应用其他列条件及当前检索，排除当前列已应用的筛选。候选搜索只在确定后进入正式查询。
- 物资与需求预计物资通过 `BusinessDraftGrid` 提供主动进入的批量编辑。网格仅保存可编辑单元格的前后值，每次单元格提交或矩形 TSV 粘贴分别记一笔。粘贴先校验完整矩形及全部目标，允许带引号、制表符和换行的文本。批量编辑选区用单层边框表示。取消编辑放弃草稿。草稿中存在无效数量时由需求业务表单提示并阻止正式保存。
- 撤销和重做统一回写父级草稿，快捷键仅响应编辑网格内的焦点。输入控件保留文字操作。正式保存继续通过权限、乐观版本、审计、单位精度和业务事务校验。验收同时核对可见单元格、待保存状态和 SQLite 正式版本。

## 2026-11-24 原生浮层与页面生命周期规范

- 直接复用有来、Element Plus 的 Dialog/Drawer、Teleport、原生动画与滚动锁；公共 CRUD 默认 appendToBody，业务自定义弹窗和抽屉亦须明确 append-to-body。禁止全局删除遮罩、手动清除 body 滚动锁或延时重复打开来规避缺陷。
- 页面入场动画只允许作用于明确的普通内容区块白名单，禁止对页面全部直接子元素或原生浮层施加通用动画。
- KeepAlive 缓存页及其子业务组件通过 usePageOverlays 管理自身浮层 model：实际停用或卸载时关闭，失效在途读取序号。仅 _list 查询偏好更新不属于离页；用户主动跨模块追溯后按既定业务上下文返回的行为须显式管理，不得把偶然残留当作返回功能。
- 可能丢失编辑或正在提交时，先通过路由离开守卫使用原生确认框，取消导航须保留原编辑内容；提交期间禁止离页，已确认离开后才清理浮层。不得将全局帮助关闭与业务表单写入关联。P10 在实际业务路由改变时关闭抽屉及导览，阅读进度独立保留。
- 正式浏览器门禁包含 youlai-dialog-animation-browser.mjs 与 youlai-overlay-lifecycle-browser.mjs；覆盖双主题、跨页缓存往返、列表查询变化、嵌套确认、未保存保护及原生滚动锁释放。

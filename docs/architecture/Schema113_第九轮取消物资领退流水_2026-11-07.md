# Schema 113 第九轮：取消独立物资领退流水

> **最终业务裁决（2026-11-07）**：物资领退选择 A。**不需要独立领料、退料流水**；保留统一物资主数据及不可变版本、需求物资、正式批准物资及每次结算。当前仍是候选数据库，未修改运行 Schema 112 或真实数据。

## 1. 数据模型最终口径

年度框架 → 子项目 → 多级费用树 → 各末级真实费用 → 多张按本次金额核定的结算单 → 费用与结算的有效最终核对 → 全部费用结清。

物资主数据与批准物资是独立的**定义和审批事实**，不是物资实物流转系统：

- `materials`、`material_versions`：统一物资稳定身份、内部编码、外部 PMS 编码，以及名称、型号、规格等可追溯正式版本。
- `demand_material_items`、`demand_material_version_items`：专业需求首次及各正式版本的预计物资清单。
- `project_scope_materials`、`project_approval_material_items`：子项目需求范围内的物资身份、当次批准数量和完整历史快照；批准范围与批准物资的变更不能直接覆盖前次历史。
- `cost_entries`、`cost_versions`：包括材料费在内的真实费用条目、正式发生金额和修订历史。
- `settlements`、`settlement_items`、`settlement_versions`、`settlement_item_versions`：不同的结算单各自记录**本次结算的费用金额**。通过 `cost_reconciliation_versions` 分次与有效实际费用核对。

**不建立库存、领退料、实际使用数量或施工实施记录**；不从预计物资数量或批准物资数量推导实际使用量。材料费仍须通过费用树的材料费末级节点和合法结算单进行核对，不能借用伪造的物资流水实现结清。

## 2. 本轮真实删除

| 对象 | 删除内容 | 为什么可以删除 |
| --- | --- | --- |
| 两张数据表 | `material_usage_records`、`material_usage_revisions` | 领料、退料和更正的独立实物流转事实已被用户明确排除 |
| 一个有效事实视图 | `v_material_usage_current` | 没有物资领退事实可选择有效历史版本 |
| 六个触发器 | `material_usage_identity_insert`、`material_consumption_immutable_update`、`material_consumption_immutable_delete`、`material_consumption_revision_insert_guard`、`material_consumption_revision_immutable_update`、`material_consumption_revision_immutable_delete` | 与删除对象严格一一关联，其他费用、物资主数据及审批约束仍然完整 |
| 两个显式索引 | `idx_actual_material_project_material`、`idx_material_usage_optional_settlement` | 原反向查询已没有表或业务需求 |
| 一处附件强外键 | `evidence_links.material_consumption_id` 与相应单一业务归属和唯一性条目 | 删除的对象不再能成为证据归属；保留 `evidence_links.project_approval_material_id` 与主数据版本等强类型关联 |

**没有删除** 统一物资编码/版本、项目批准物资及历史、费用核对、结算单或结算修订记录；没有将库存数量、累计领用数或材料费总额等冗余字段添加到其他数据表。

## 3. 隔离数据库验收

- 独立装载最新 Schema 113 DDL，检查已删表、视图、附件列和 FK **确实不存在**，确保没有删除后遗留的悬空引用。
- 保留物资根及不可变版本的连续性、有效外部 PMS 编码、需求版本物资清单和批准物资历史快照的正反例；确认不同项目可引用同一物资主数据，正式批准的不同历史型号不能互相污染。
- 保留子项目多级费用树、人工费/材料费多张结算单、跨费用版本核对、修订单替换、正式注销、核减与全部结清的完整反例。
- **最新候选结构：71 张 STRICT 表、23 个只读当前事实视图、204 个触发器、74 个显式索引、675 个字段。独立 SQLite 279 项契约测试全部通过；`PRAGMA integrity_check` 为 `ok`、`foreign_key_check` 无异常。**
- 运行代码仍为 Schema 112；候选 DDL 既未替换运行库，也未自动迁移或删除任何用户数据库和附件。

## 4. 后续边界

1. 用户要求业务功能完备基础上的数据库精简，因而保留真实版本、主外键、材料费叶子、预算软上限以及分次结算的核对历史。
2. 目前 `cost_entries.cost_node_id` 与 `cost_versions.category_id/category_snapshot` 仍可能表达不同的费用分类维度，需后续聚焦费用/会计分类时单独判定，不在本次擅自删除。
3. 历史报告中的“独立物资领退流水”属于已被新裁决覆盖的设计快照；最新行为以本报告与候选 SQL 为准。Schema 113 正式冻结、与运行代码接入和真实附件恢复需另行验证。

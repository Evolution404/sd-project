# 统一发布与清理规范

## 唯一入口
- 普通双版本：make release（允许未提交输入，记录实际工作区状态）。
- 最终全量验收发布：make release-final（干净 HEAD，完整门禁）。
- 单版本：make package-win / make package-win-demo（共享发布编排器并进行宿主验收）。
- 仅复验既有 ZIP：make test-package / make test-package-demo。
- make 无参数只显示帮助。

## 发布时序
1. 获取发布锁、记录 Git HEAD 和构建输入 SHA256。
2. 构建正式前后端；执行对应工程门禁。最终模式还执行完整 Schema、性能、正式及历史浏览器回归。
3. 在独立临时输出目录生成正式与演示 ZIP；校验官方 Windows 运行时、生产依赖、数据边界、压缩包内容。
4. 解压实际 ZIP 分别完成宿主验证：正式包初始化、登录、附件、备份恢复、重启与日志；演示包账号、业务样例、持久化与日志。
5. 双包验收成功后检查同一基线及 SHA256，生成报告；仅成功才提升到 dist。提升失败回滚旧文件。单包更新会使既有双包报告失效。
6. 清理本轮打包暂存与隔离测试工作区，保留完整日志。不得清理真实运行数据。
7. Windows 实机另验，不由 Mac 宿主验收推断。

## 目录与保留规则
| 目录 | 用途 |
| --- | --- |
| dist/server、dist/web | 正式编译唯一输出 |
| dist/两份ZIP及两份清单、双包报告 | 唯一交付产物 |
| test-results/release、test-results/legacy | 发布和隔离回归证据 |
| .build/toolchains、.build/windows-cache | 可复用工具链、官方运行时 |
| .build/release-run-*、windows-staging、windows-demo-staging、legacy-browser/run-* | 临时目录，运行后清除 |
| data、data-training | 真实及演示、训练运行数据，绝不作为构建垃圾清理 |
| tests/fixtures/legacy-frontend | 历史回归夹具，非正式发布源码，暂保留 |

历史验收记录、截图、实验工程、WIP 快照与旧版参考仓库迁出项目根目录，保留原相对路径，以免丢失历史审计证据。原厂宣传截图不进入正式 public 资源。保留有来许可证和源组件移植依据。

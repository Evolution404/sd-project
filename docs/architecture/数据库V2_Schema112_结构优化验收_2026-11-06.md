# 数据库 V2 / Schema 112 结构优化与验收

> 日期：2026-11-06。**唯一当前 Schema 版本：112**。本文件描述已落地代码，早期 Schema 109—111 的文件和报告仅供历史追溯。测试验证均在独立新库完成，未对项目 `data/` 执行迁移或清空。

## 一、当前数据架构

- **唯一数据库边界**：`server/database/`。业务 SQL 分布在 `repositories/` 与 `queries/`，表结构仅由 `schema/{tables,indexes,views,constraints}.sql` 四个文件初始化。HTTP、Application、Domain、Infrastructure 不能再直接执行 SQL；`npm run check:database-boundary` 全目录递归拦截。
- **运行结构**：SQLite，外键 ON，WAL，写事务 BEGIN IMMEDIATE。前端 Vue 3 + Element Plus，HTTP 对外接口保持原有操作型式。根 `data/` 是唯一运行数据目录，根 `dist/` 是 Windows 发布结果目录，发布包不含用户运行数据。
- **货币与数量**：费用/预算/结算整数分，工作量按四位小数缩放为整数；已批准、已核定、已实施、已结算、撤销/更正各自为不同事实。
- **不可变历史**：`operation_versions`、`project_approval_versions`、`reference_price_versions`、`completion_records/revisions`、`plan_budget_versions`、`cost_versions/allocations/reconciliation_versions`、`project_settlement_entries/revisions/commands` 等按业务约束防止覆盖历史。

## 二、操作类型（完全独立）

| 当前实体 | 权威职责 | 关系 |
| --- | --- | --- |
| `dictionary_types`、`dictionary_items` | 电压外的普通字典、单位、优先级、费用/项目类别 | `dictionary_items` 明确 CHECK 不允许 `type_id='operation'`，无操作类型业务专属字段 |
| `operations` | 操作名称、编码、生命周期、默认单位、唯一作业对象、允许位置、默认位置、数量与字段模板 | `default_unit_id` FK 指向单位字典，触发器强制 `type_id='unit'` |
| `operation_versions` | 历次不可变定义快照与责任人 | `UNIQUE(operation_id,version)`；`demands(operation_id,operation_version)` 真实复合外键 |
| `demands`、`reference_price_catalog` | 使用操作类型 | `operation_id` FK 指向 `operations`，不再通过通用字典冒名引用 |

`operation_location_settings` 已彻底删除，不存在“双套操作配置”或从最新版 JSON 还原当前设置的执行路径。`dictionary_types` 中保留“operation”作为界面列表分类元数据，不储存操作记录。

**用户最简操作**：选操作类型 → 选设备 → 填工作量；对象、单位、位置选择器、操作版本由系统决定；场景确需补充来源、现场事实、证据与有权审批时才交互。

## 三、需求位置互斥

`demands` 保存一条真实定位关系：

| 作业 | 当前设备定位 FK | 限制 | 业务展示 |
| --- | --- | --- | --- |
| 线路侧杆塔 | `logical_tower_id` | 必须有对应 `observed_physical_tower_id` 历史实体观察 | `location_kind='tower'` |
| 共用物理杆塔 | `physical_tower_id` | 不再复制任一线路的逻辑杆塔锚点；需要电压/参考价时自动关联上下文 `context_line_id` | `location_kind='tower'` |
| 线路档距 | `span_id` | 同时保留 `span_version` 与原始 `span_snapshot_json`；`logical_tower_id/physical_tower_id/observed_physical_tower_id` 全为空 | `location_kind='span'` |

`location_kind` 是 SQLite **VIRTUAL GENERATED** 字段（根据 `span_id` 是否非空计算），不属于用户维护的数据；旧 `location_line_id` 重复字段取消，线路由逻辑塔、档距或实体塔的业务上下文推导。需求历史文字、物理代码及档距端点快照仍保留核实依据，不能以位置归一为由抹去既有证据。

业务操作包括按线路筛选、档距二次核实、需求项目承接、参考单价电压匹配、重复需求判定与实体换塔均切换至真实定位关系。

## 四、拓扑、项目、财务跨表完整性

- **合法档距**：端点必须属于同一线路；唯一允许的例外是支线首档使用所属主线已批准的接入杆塔 `junction_tower_id` 与该支线的真实杆塔连接。任何其他跨线边或非法实体端点禁止入库。
- **资金框架**：`agreements(id,framework_id)` 复合唯一键和 `projects(agreement_id,framework_id)` 复合外键，拒绝跨框架执行协议。
- **项目/计划**：`execution_items` 必须引用所属子项目的 `project_demand_scopes`；`project_change_orders` 的批准基线必须属于同一项目。
- **预算**：`plan_budget_drafts` 和 `plan_budget_versions` 的项目批准版本属于对应计划的子项目；确认历史不可改写；计划取消/结束不意味着自动释放已核定预算。
- **结算**：`project_settlement_entries` 的项目、批准版本、需求范围、计划明细必须同属同一事实链；冲销必须关联同项目和需求范围内的原始付款型凭证。结算凭证不等于现实银行付款。
- **费用**：费用类别须为 `expense_category`，费用确认须来自同执行计划的草稿，实际费用分摊不准跨检修计划；核对关系不能跨批准需求范围。
- **基础字典**：需求单位、优先级、来源类别、项目类别及参考单价操作固定单位，均由 SQL CHECK/触发器保护类别正确，避免任意字典 ID 互换。

## 五、索引、性能和数据安全

- 消除 `operation_versions(operation_id,version)` 的重复二级索引（UNIQUE 自带索引）。
- 新增 `demands` 的逻辑塔、物理塔、档距、上下文线路索引，以及 `line_spans(line_id,status)`；费用类别、变更单批准版本、预算批准版本、需求范围、来源的反查索引。
- **`EXPLAIN QUERY PLAN` 实测**：需求按线路查询使用三路索引 `MULTI-INDEX OR`；逻辑塔从 `idx_logical_towers_name` 获取，档距从 `idx_spans_line_status` 获取，物理塔上下文从 `idx_demand_context_line` 获取，需求定位从 `idx_demands_tower/idx_demand_span` 获取；`project_demand_scopes` 按项目/状态使用 `idx_plan_scope_status`。
- 空新库目前 **52 张正式表**，`PRAGMA integrity_check='ok'`、`PRAGMA foreign_key_check` 结果为空。
- 旧 Schema 109/110/111 或无法识别的非空库**拒绝自动升级或覆盖**。如确有真实旧数据，必须备份、核实和另行批准一次性转换方案；禁止为通过测试清理运行数据，也不实现旧版运行兼容层。

# 内网程序与独立数据集运行规范

## 正式程序与业务数据完全解耦（2026-11-25 最新裁决）

正式 ZIP 是唯一正式程序发行形态，不包含业务数据、默认账号、默认密码、首次部署或数据迁移式升级入口。业务数据集独立存放，账号、权限、设备、需求、项目、结算、附件、日志和备份均属于数据集，不属于程序版本。真实数据不得进入公开 GitHub 或公开发行包。

1. 完整解压正式程序到任意本地可写目录。
2. 把已有数据集（含 schema113.sqlite，若有附件则含 objects）放在与程序互不包含的独立目录。不得复制正在写入的 SQLite 主文件。
3. 双击「启动服务.cmd」，选择数据目录；之后记住该程序目录下 data-location.json 中的路径。可通过「选择数据目录.cmd」重新选择，也可用环境变量 DATA_DIR 显式覆盖本次运行。数据目录必须为绝对路径。
4. 服务启动后在 Windows 本机访问 http://127.0.0.1:8787。使用数据集已有账号、密码。IP 白名单仍默认开启，按单位安全制度授权终端及配置防火墙。

正式服务必须拒绝缺失目录、缺失数据库、未知或不兼容 Schema、程序内数据目录和带演示/训练标记的业务数据。禁止启动时自动建空库、重置账号或迁移数据。相同真实路径的一个数据集仅允许一个正式实例持有跨进程数据锁，不受端口或程序版本影响。新版使用独立 SQLite 控制库的操作系统级互斥锁，退出或强制关闭后由操作系统自动释放。旧运行记录经进程及端口核实后自动清理，不要求用户手动删除；确认仍有旧服务或维护任务时才拒绝重复启动。旧程序不认识新锁，切换前须确保旧服务已停止，禁止并行运行。

## 更新程序

停止旧服务（新版可双击「停止服务.cmd」，旧版手动正常关闭），确认已释放数据锁后，把新正式 ZIP 解压至独立程序目录，启动时选择原数据目录。数据原地使用，不复制、不恢复、不重建；账号和历史自然保留。相同 Schema 版本可停止新程序后切回兼容旧程序。若数据库结构不兼容，拒绝连接；跨结构转换必须单独备份、在副本上验证，不属于日常程序发布。

## 独立数据管理

「备份数据库.cmd」对选择的数据集操作。正式服务须先停止，确保数据库及附件形成一致快照；备份存于所选数据目录 backups。访问日志与历史备份按制度独立保留。恢复业务数据时使用「恢复业务数据.cmd」，选择含 schema113.sqlite 及完整附件 objects 的备份目录，再输入尚不存在的独立目标数据目录；不覆盖、不自动切换数据。恢复验证精确结构、SQLite 完整性、外键和全部附件哈希。空数据集仅在确有需要时，通过单独的「创建空数据集.cmd」明确指定不存在的独立目录及管理员，不是部署必经步骤。

本地合成演示 ZIP 保持自包含，真实台账演示仍为独立隔离环境，禁止混用正式库；正式包训练实例存于所选业务数据目录的 training/instances，训练数据库彼此隔离且不参与正式库备份恢复；演示训练保留独立本机目录。开发工具继续使用独立测试目录。历史复制式升级源码仅用于既有回归，不再随正式包交付。

## 导入注意事项

物理归组采用原系统既有规则；源记录中没有可确认的主支线接入关系，不推断拓扑。设备编码不冒充现场铭牌。逻辑分界点不冒充实物杆塔。输电中心管辖长度按源字段保存；未知为 NULL，明确无管辖为零。导入回执保存逐项映射和排除理由，不包含网格人员联系方式或账号。

## 2026-11-25 最新演示模式强制裁决

所有演示模式固定账号 demo、密码 demo，严禁随机生成、另设强密码、环境变量覆盖及重启轮换；既有演示库只在确认演示标记、隔离目录及备份后修复账号，保留全部业务记录。此规则不适用于正式库或正式管理员。真实台账演示仅本机受控，禁止公网暴露和公开上传真实台账；内网演示仅限授权隔离网络。实际实现及登录验收完成前不得宣称已符合本条。

## 离线包精简构建

正式与演示 ZIP 均采用 esbuild 合并后端及生产依赖；开发编译目录不变。包内不再携带散装 node_modules，保留内置 Node24 运行时、原 CLI 路径、Schema113 SQL、前端资源和许可清单。文件数量上限 400；构建、独立重建比对、解包运行及 Excel 读写预检均为发布门禁。新版正式程序直接连接独立数据目录，禁止覆盖旧数据库和混合解压。

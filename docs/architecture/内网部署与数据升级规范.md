# 内网部署与数据升级规范

## 首次部署

真实台账初始化与普通程序发布分离。正式程序 ZIP 不含业务数据；独立初始化数据库仅包含从原线路统计备份导入的基础台账、字典和管理员，不包含虚构业务。真实台账仅限获准内网环境使用。

1. 在 Windows 10/11 x64 可写目录完整解压正式版 ZIP，例如 D:\SDProject\v1。
2. 双击「恢复业务数据.cmd」，选择独立初始化备份目录，将数据恢复至新版本的 data 目录（目标必须不存在）。不要覆盖已有运行数据。
3. 双击「启动服务.cmd」，等待 SCHEMA113_READY，在服务器本机浏览器访问 http://127.0.0.1:8787。
4. 使用部署约定的 admin 账号和初始密码登录，尽快修改初始密码。无需再次运行初始化管理员。
5. IP 白名单保持开启。由管理员在服务器本机授权内网客户端 IP，并按单位安全制度设置 Windows 防火墙。仅授权终端访问服务器 IP 对应的服务端口。
6. 原始数据与导入回执由管理人员另行保管。导入存在排除和待核记录，不得将未核实数据误报为已经全部纳入正式台账。

## 权威数据

data/schema113.sqlite 包含设备、用户、权限、需求、项目、结算、审核历史等数据库事实。data/objects 保存附件，必须与数据库配套备份。data/logs 为访问日志，data/backups 为备份历史，按制度另行留存。禁止仅复制正在写入的 SQLite 主文件；Excel 不是完整业务数据迁移手段。

## 一键升级（同结构版本）

旧服务和训练实例停止后，将不含初始化数据库的新正式 ZIP 解压至独立目录，双击「一键升级.cmd」，选择旧版本目录并输入旧服务端口。程序检查前后版本和发布文件完整性，自动备份旧数据库、验证附件、恢复到独立临时目录并试启动；全部成功后才创建新 data 目录。可直接按原端口启动新版本。旧程序、旧数据库、历史备份及训练实例留在旧目录，访问日志复制至新目录。不得同时启动旧服务和新服务。失败不会覆盖旧业务数据。当前不自动停止未知进程，也不自动迁移不同结构的数据库。

## 同结构版本升级（命令行备用）

1. 在旧服务器通知用户停止写入并停止服务。
2. 在旧程序目录执行「备份数据库.cmd」，取得带时间戳的数据库与附件一致性备份；另行归档访问日志和备份历史。停机后可另外完整复制旧 data 目录作为保护。
3. 将新正式程序 ZIP 解压到全新目录（例如 D:\SDProject\v2），不覆盖旧版本，不使用首次初始化数据作为升级数据。
4. 在新目录打开 CMD，使用新版本自带工具恢复旧备份：

    runtime\node.exe scripts\restore.mjs "D:\SDProject\v1\data\backups\实际时间戳" "D:\SDProject\v2\data"

目标 data 不得已存在。恢复会校验精确数据库结构、SQLite 完整性、外键和全部附件哈希，再原子创建新目录。
5. 启动新版本，检查账号、权限、台账、业务历史、附件、关键操作，确认后切换用户访问。账号和密码沿用旧数据。
6. 验收失败且新库未发生实际业务写入时，停止新版本、启动旧版本回滚。若新库已经写入，先停机备份并评估回迁，不可直接回滚导致新写入丢失。

## 跨数据库结构升级

当前启动和恢复仅接受与权威 Schema113 完全一致的数据库结构。未来结构变更须提供经过测试的版本迁移程序，在备份副本上核对源目标结构、业务数量、历史和附件，验证后再切换。现阶段没有通用自动跨结构升级能力。禁止直接修改 PRAGMA user_version、覆盖权威 SQL 或清空旧数据库。

## 导入注意事项

物理归组采用原系统既有规则；源记录中没有可确认的主支线接入关系，不推断拓扑。设备编码不冒充现场铭牌。逻辑分界点不冒充实物杆塔。输电中心管辖长度按源字段保存；未知为 NULL，明确无管辖为零。导入回执保存逐项映射和排除理由，不包含网格人员联系方式或账号。

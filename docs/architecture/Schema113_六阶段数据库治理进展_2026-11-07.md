## 本次新增：费用树与费用项分次结算

- `project_cost_nodes` + `project_cost_node_versions` 提供**子项目内多级费用树**及定义版本历史；确认费用与结算只能关联末级节点。
- `cost_entries` 精确归属费用节点，`cost_versions` 锁定当时费用定义版本；`settlement_items` 可一次选择多个费用叶子节点，`settlement_item_versions` 记录每条费用**本次**金额及采用的历史名称定义。共同费用不属于具体作业需求范围时允许 `project_scope_id IS NULL`，避免编造范围。
- `v_effective_cost_reconciliations` 过滤已被新版结算替代的旧核对，仍保留原始历史。对同一稳定实际费用的跨版本多次结算进行额度校验；费用更正后可能重新产生待结余额。
- 新候选结构为 **73 张 STRICT 表、24 个业务事实视图、210 个触发器、76 个显式索引、697 字段**，**289 项**隔离 SQL 契约检查通过。仅变更候选数据库结构、数据库文档与数据库验收测试，未操作运行 Schema112、前后端或已有数据。

## 最新物资主数据版本化设计

1. `materials`：稳定主键、内部编码、计量单位；根记录不允许 UPDATE/DELETE。外部 PMS 物资编码随正式物资版本记录与纠错，不在根表重复保存。单位决定历史数量语义，修改单位必须新建物资身份。
2. `material_versions`：按同一物资 `material_id` 连续生成全量版本，存外部 PMS 编码、名称、型号、规格、分类、启停、备注、原因、责任人和登记时点。全部正式版本不可覆盖，禁止跳号、倒序和没有实际内容变化的虚假改版。
3. `v_material_current`：只读取最新正式版本，不保存第二份当前名称/状态。
4. `demand_material_version_items.material_version_id`：每次专业需求物资清单锁定真实主数据版本；未改物资时继承旧版引用。
5. `project_approval_material_items.material_version_id`：批准物资清单指向当时主数据版本；批准时的名称、型号、规格、数量和单位仍是不可删的项目审批证据。
6. `evidence_links.material_version_id`：附件可直接关联某个精确的物资主数据版本，强制只指向一个业务目标。
7. 初始物资根和 V1 应在应用端统一数据库访问模块的一次 `BEGIN IMMEDIATE` 事务写入；没有发布 V1 的物资身份不得在新需求或项目物资范围中使用。

## 还需要业务明确的设计规则

- 已承接需求跨子项目正式移交，以及关闭项目重新授权开启的正式流程；

- 实际设备台账、附件实体文件、离线灾难恢复、并发性能与角色访问控制的实施级验证。

## 本轮继续执行（2026-11-07）

- **物资与外部 PMS 编码分层进一步治理**：内部物资编码仍是稳定身份；外部 PMS 物资编码实际属于可能被勘误、重映射的外部属性，已迁入不可变 `material_versions.pms_material_code`。历史映射不丢失；同一时点不同物资不得共享同一当前 PMS 编码；旧码退出当前定义后，允许在新物资版本中正式重新映射。
- **结算结构按用户说明精简**：已移除 `settlement_versions` 的 `kind` 和 `amount_basis` 两个非必要字段；每张结算单只记录本次结算的部分费用，可通过多张单据逐步结清；应用层根据真实费用和已审核核对记录计算未结算余额。
- **恢复与并发验证扩展**：新版物资历史、PMS 编码映射、项目批准物资快照及每次结算金额随 SQLite 在线备份恢复；两会话 WAL 写入竞争同一物资的下一版本时，后续旧版本号提交被拒绝。
- **材料编码规范化**：稳定内部编码与可修订外部 PMS 编码均不允许首尾空白；PMS 编码不可只有空格，杜绝难以查重的表面不同代码。

## 六阶段之后的追加治理：结项与跨版本核对口径

- 修复 `project_close_guard` 原先只统计**当前费用版本**核对、无法正确排除已修订结算历史的问题。现在通过 `v_effective_cost_reconciliations` 按稳定真实费用身份跨版本汇总。
- **`is_final=1` 仍是独立最终核对的业务事实**，金额相同并不代表流程自动最终完成；正式关闭同时要求每张当前有效结算单的每条明细已最终核对。
- 专项测试覆盖：同一费用跨版本、三张分次结算、某张单据正式减额修订、无凭据额外结算被阻止结项、该额外结算正式注销、以及发生费用35元、最终结算34.50元的合法核减。
- 实际费用下调后已核对金额暂时超出当前金额，可以如实登记费用更正，**不得自动删账、拒绝历史事实或伪造退款**；超额追加核对则受保护。
- **说明**：第七轮原有统计属于旧版候选；此处同步列示第八轮更新后的当前总数：**73 表 / 24 视图 / 210 触发器 / 76 索引 / 697 字段，289/289 契约检查通过**。候选仍未冻结或切换运行库。
- **最新裁决已解决**：不设检修计划，也不存在施工完成阶段；子项目只有一次次结算，全部实际费用最终核对结清后才正式财务关闭。详见[第八轮纯结算模型治理](Schema113_第八轮取消施工与纯结算模型治理_2026-11-07.md)。

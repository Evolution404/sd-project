# 基础台账删除、共塔解绑及拆合档 · 安全业务裁决与验收

日期：2026-11-01

## 自主裁决及实施
1. **误录删除与历史。** 线路删除已有完整后端依赖检查：存在杆塔、档距、支线或需求即拒绝删除，零依赖的误录数据仍可由管理员写入理由后删除，操作快照留在审计。将“删除误录线路”从隐藏的线路信息 Tab 移动至线路概要操作区，提高可发现性。杆塔删除已拒绝需求、被观察物理实体、相邻档距、支线接入以及其他需求关联；档距删除拒绝需求引用。现有安全检查不重写，禁止自动级联删除。
2. **共塔解除与物理整塔更换分离。** 共同物理杆塔在真实更换时必须整体核对全部回路；当前线路位置因错误关联而需要解绑，新增独立纠错接口 GET/POST /api/ledger/towers/:id/detach。预检返回共享位置、需求引用及阻断原因，要求版本一致、理由必填，并使用事务复制实体当前公共属性、新增独立实体、重绑当前线路逻辑塔。保留原实体、其他回路、完整命名/实体绑定历史和审计事件；相同提交标识幂等。已有需求包含实体观察引用或相邻档距定位时，不自动迁移、不允许直接解除。
3. **拆档合档。** 继续使用已实现的路径替换事务：新旧路径外侧端点一致，无分叉/回路；旧档距状态改为 retired 保留记录，新档距取得新 ID；使用旧档距的需求仍指向旧版本和快照并须再次核实，不能自动生效。距离从端点真实经纬度推导，绝不持久化手填档距长度。
4. **管理员与数据边界。** 以上全部为管理员独占，服务器仍做每条 API 权限及事务审计。未改动现有 SQLite Schema，也没有迁移/清理用户的 PMS 导入测试数据。

- node tests/browser-ledger.mjs 和 node tests/browser-topology.mjs：原台账操作和拓扑完整回归
- tests/ledgers.test.mjs：预检不落库、旧版本阻断、被需求引用拒绝、审计历史完整、重试幂等

采用真实设备/生产历史样本对复杂跨线路/多次更换的时间重叠与人工纠错核验。现阶段测试仅在隔离数据库执行，未宣称生产数据已经完整清洗或现场确认。

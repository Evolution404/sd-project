# 2026-11-09 最终业务裁决：系统独立、编码自动生成、最少录入

> **已批准，永久有效，最高优先级。** 代码执行与验收见同日《独立业务_自动身份与最少录入_实施验收》；所有相反历史方案已废止。

## 1. 与 PMS 完全无关

本系统是完全独立的输电项目管理系统。不得对接、同步、依赖、读取、识别、匹配、导入或转换 PMS 特定数据、编码、标识、字段及格式。**包括“一次性 PMS 清洗导入”也不予考虑。** 禁止专用接口、适配器、外部编码、映射/别名表、同步工具、菜单、索引和兼容性逻辑。旧版相关文件和历史文档不构成当前需求。不得以后续兼容或数据接入为由恢复这些能力。

通用 Excel 只用于用户提供本系统独立业务事实，不按外部系统结构设计。业务来源、原始依据和附件仅用于本系统审计，不承载外部系统编码关系。

不得因本裁决静默删除或改写已存真实数据、审计、历史或备份；有外部来源的历史事实需保留并报告，不能自动清洗抹除。

## 2. 不让用户填写内部编码

裁决提出时线路 line_code、物理杆塔 tower_code、逻辑杆塔 logical_code 在 Schema113 表单中作为必填项，该历史设计已按本裁决整改。三项都是系统技术身份，用户在线创建、编辑以及 Excel 新建时不应填写。后端在事务内产生唯一稳定身份；先评估已有 UUID 是否足够，如编码只是冗余应合理精简，若确需可读内部码则服务端生成，不给用户增加步骤。

其他内部编码（计量单位、作业对象、操作类型、物资、参考价、年度框架、执行协议等）按同一原则审计：可自动生成或推导的内容不要求用户填。用户只输入真实业务事实和不能由系统确定的业务判断。不能用“前端自动生成固定假编码”掩盖后端问题。

## 3. 杆塔创建最短路径

用户选择所属线路、填写杆塔号及必要真实属性即可。普通新杆塔由服务端原子建立逻辑/物理杆塔及关联。共塔多回必须明确选择已有物理杆塔；遇到同名、同号、重复实物或关联歧义时明确报错/确认，不自动合并或错误创建。整塔更换按既有业务流程保留旧物理实体和历史，不覆盖既有正式身份。

界面与选择器优先显示线路名称、杆塔号、设备关系；内部 ID、编码和版本留在后台，不能让普通用户维护。

## 4. Excel、API 和防回归

普通 Excel 新建只填业务字段；维护回导可携带系统生成的隐藏、受保护身份/版本信息，且不得让用户手工填写。服务端做确定性关联与去重；有歧义的情况停止自动匹配，不使用任何 PMS 码解析。在线、批量、API 共用同一规则，保留权限、外键、事务、乐观锁、幂等、历史和审计。

Codex 必须增加自动防回归检查：阻断正式 Schema/应用/API/模板中再次出现 PMS 专用映射或接口；通过浏览器和 API 验证无编码新建线路、普通杆塔、共塔多回、Excel 新增及修订；验证未出现重复设备和历史改写。不要对历史文档或否定性测试误报。

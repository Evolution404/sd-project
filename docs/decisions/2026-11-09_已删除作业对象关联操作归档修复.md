# 已删除作业对象导致操作类型和参考价格规则无法归档（2026-11-09）

## 现场问题与根因

用户先在作业标准中删除标准作业对象，随后尝试删除原操作类型时提示：标准作业对象不存在或已删除。

业务删除当前使用逻辑删除事件，原对象和关联历史全部保留。操作类型删除时会先产生一个不可变的正式停用版本；此前应用会在停用时重新强制查询“未删除”的关联对象。原 Schema113 的 object_type_guard_insert 触发器也无条件要求新操作版本的关联对象处于有效状态，所以单独放宽应用读取仍不足以解决问题。

参考价格规则停用有相同风险：引用的操作类型已删除时，停用规则重新查询当前操作，且可能错误采用最新版本的操作和单位。

## 修复规则

1. 允许已有操作类型在其原作业对象已删除或停用之后归档、逻辑删除，保留原对象身份、原类型和全部历史，不级联修改业务事实。
2. 不允许新建操作类型绑定已删除对象，也不允许在失效引用下发表新的有效操作类型版本；历史停用版本只能保持上一个版本已经存在的对象和设备类型关联，数据库触发器再次进行约束。
3. 允许已有参考价格规则在其原操作类型已删除之后归档、逻辑删除，必须保留原来采用的操作定义版本和计量单位版本。
4. 删除保留身份、版本、审核和审计历史，正常列表隐藏已删除对象；不执行物理删除。
5. 数据库仍为 Schema113，只调整一条不可变归档校验触发器，不改动业务表和字段。

## 受控升级方法

正常服务启动继续严格比较 SQLite 结构指纹，绝不自动升级已有数据库。

在应用程序完全停止之后，使用新的显式维护入口运行：

macOS，在项目根目录：

    DATA_DIR="$PWD/data" node scripts/upgrade-schema113.mjs

Windows 离线包，在解压目录 CMD：

    set "DATA_DIR=%CD%\data"
    runtime\node.exe scripts\upgrade-schema113.mjs

操作要求：
- 必须先关闭正在访问该数据库的服务和全部写入进程。
- 升级只接受已验证的原 Schema113 精确结构指纹（包括本轮修复前版本），未知结构必须拒绝。
- 实施前执行 SQLite 原生一致性备份并复制所有正式附件；在独立临时目录恢复、预演、复核结构与业务记录指纹和外键完整性。
- 只有预演成功后才在真实数据库内部使用事务更新权威 Schema113 的视图、索引和触发器。本轮原结构升级绝不修改任何业务数据行或已归档 JSON。
- 更新成功后在全新备份目录保存 UPGRADE-RECEIPT.json，包含源/目标结构 SHA256 和备份校验值；再次执行应返回 already_current。
- 完成后使用新版服务重新启动，验证作业对象、操作类型和参考价格规则删除顺序。
- 禁止直接手工替换 SQLite 文件、关闭结构指纹检查、删除业务数据，或在服务仍运行时执行。

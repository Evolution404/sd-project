## 实施范围
此前完成的 13 个导航页面、8 类新增弹窗巡检扩展到**有真实业务状态的深层页面**。复用原浏览器测试在隔离库构造需求、项目、检修计划、核定预算、结算凭证，检查需求详情、子项目详情、已立项项目详情、检修计划详情以及其嵌入预算与结算模块。在 1500、1280、960、760 像素宽度下实际采集 Chrome 截图、测量文档流定位、主容器边界及所有非表格操作按钮的横向可见性。

## 发现并修复的问题
1. 窄屏检修计划预算三列表格压缩字段；采用列数 3/2/1 自适应，保留金额原值和审核历史。并推广到实际费用、结算凭证、完成记录、操作记录、杆塔基础信息和框架详情。
2. 1280px 宽度下嵌入结算凭证的工具栏和刷新操作被 CSS Grid 的 min-content 最小宽度撑出工作区。现改为 minmax(0,1fr) 轨道、子区域 min-width:0，并对凭证/完成记录过滤栏换行。
3. 预算操作栏、费用工具栏和编辑字段在窄屏缺少换行；添加相应响应式规则，不截断业务操作入口。
4. 子项目详情使用“关闭 ×”易让用户误认为是侧栏弹窗；调整为“返回项目列表”，保持原路由与上下文。移除旧 project-overlay、execution-overlay 旧类名和相关测试选择器，均按正常内容流渲染。

## 决策边界
本轮专注于排版和现有业务交互，没有私自扩大图形化删除、共塔解除、历史抹除或预算/凭证自动再分配。保守策略：历史事实和审计不因 UI 操作重排而改变。PMS 导入内容始终视为测试数据，不进行自动清理。

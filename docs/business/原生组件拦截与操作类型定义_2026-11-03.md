# 原生组件拦截与操作类型定义

日期：2026-11-03。按用户要求修复原生组件漏检，并将操作类型、单位、作业对象建立确定关联。

## 原生组件漏检修复

原扫描仅检查Vue模板原生标签，未覆盖缺失的Element Plus样式和ElInput的浏览器原生type。补齐collapse、collapse-item、upload、link、radio、date-picker、option、message、progress官方样式；日期改用ElDatePicker，原生number改为保留原校验的文本数字输入，全部ElForm声明novalidate。

`scripts/ui-contract.mjs`结合Vue SFC和TypeScript AST检查：

- Element Plus组件及别名的官方样式必须在统一注册表导入，应用入口必须加载该注册表；包含按需加载页面和ElMessage等服务。
- ElInput只允许text、password、textarea；日期／数字／文件等专用原生type、无法静态确认的type和无审计的v-bind透传均阻断。
- 原生业务模板标签、大小写变体、动态component、render函数、DOM创建、原生alert／confirm／prompt、v-html及HTML字符串注入受门禁约束。
- Element Plus内部原生DOM由组件管理；脚本中不挂载界面的下载锚点用于浏览器文件下载，不是可见业务组件。ElUpload内部file输入必须隐藏。

`tests/native-ui-gate.test.mjs`同时检查反例与当前全项目。`npm test`能直接拦截回归；`check:ui`和`check:ui:strict`都为零容忍，历史409个基线不能放行新控件。

Chrome检查使用`tests/helpers/ui-contract.mjs`，检查实际可见的文件／日期等原生输入、表单校验和消息／进度条样式。覆盖ElUpload隐藏输入、日期弹层、消息以及13个主导航页面；注入可见file输入的反例必须被检查捕获。Element Plus ElDescriptions内部表格属于官方组件，避免把第三方正常DOM误报成自研表格。

## 操作类型作为主定义

每个操作包含：名称、固定计量单位、作业对象（线路侧设备／共用物理杆塔）、状态及可选的默认数量、完成标准、扩展字段。

沿用已有字典稳定ID和配置版本；数据库`default_unit_id`承担固定单位定义，不增加平行字段或迁移用户数据库。新建时单位和对象必填；修改定义时检查单位有效及对象唯一。已有单位被停用／删除时保留原关联及配置历史，相关操作不能用于新录入；元数据维护和删除仍可按既有权限执行。

| 入口 | 行为 |
| --- | --- |
| 数据字典→操作类型 | 明确维护计量单位及作业对象；列表展示关联；新建缺单位就地报错 |
| 在线添加需求 | 先选操作，单位和对象只读带出，不提供自由组合 |
| 逐条编辑 | 选择新操作后更新单位和对象；有单位差异或条件字段时先明确影响；不自动换算数量 |
| Excel模板 | 单一操作预填对应单位／对象；多种操作可留空两列，由每行操作确定 |
| Excel预检／提交 | 留空补齐；明确填写的冲突值报错，不静默覆盖原值；预检和事务提交执行同一规则 |
| 新增参考价 | 计价单位随操作自动带出，服务端拒绝不一致单位 |

`server/operation-definition.mjs`为服务端定义检查，`web/src/utils/operation-definition.ts`为前端只读派生；需求批次、需求修订和参考价接口执行服务端约束。

配置变化不重写旧需求的operation_version、unit_id／version／snapshot、work_target_type和quantity_scaled。原需求修订继续检查项目冻结范围；来源追加不增加原需求数量。旧的未完善配置属于待维护数据，不作为已批准例外，也不自动补造。

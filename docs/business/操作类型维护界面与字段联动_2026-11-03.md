# 操作类型维护界面与字段联动

> **历史关联条款废止声明（2026-11-09）** 本文中涉及 PMS、一次性专用导入、外部编码、映射或兼容的设想全部废止，仅作为历史审计记录。现行系统独立管理业务，技术编码由服务端生成，执行 docs/decisions/2026-11-09_系统独立_自动编码_最少录入.md。

操作类型是需求的录入定义。用户先选择“做什么”，系统据此确定允许的定位方式、作业对象、计量单位和专用字段，再录入每个位置的实际事实。

## 字段归属

| 字段 | 与操作类型的关系 | 需求录入行为 |
| --- | --- | --- |
| 计量单位 | 固定绑定一个有效单位 | 自动带出，不能独立换单位；数量不自动换算 |
| 作业对象 | 固定为线路侧设备或共用物理杆塔之一 | 自动带出，不能自由组合 |
| 作业位置 | 允许杆塔、档距，或两者；默认值必须在允许范围内 | 只有一种时自动确定；有两种时仅在范围内选择 |
| 默认处理部位 | 可维护的文本模板 | 预填后按现场修改，例如横担上部、导线连接部位 |
| 建议每项数量 | 可选，正数且最多四位小数 | 预填每个位置的数量，允许调整，不代表整批合计 |
| 完成标准 | 可维护模板 | 预填后逐条核对、修改 |
| 附加字段 | 操作专用字段集合 | 支持名称、类型、必填、候选值、默认值；实际值逐条填写 |
| 录入提示 | 可选业务说明 | 提示如何填部位、如何计量和需要核对的事项 |
| 具体线路、杆塔、档距 | 每条需求的实际定位 | 不在操作定义中固定某条线路或某个位置 |
| 问题事实、来源类型/日期/提出者/依据、优先级、期望日期、照片 | 每条需求的实际事实或安排 | 不由操作类型统一固定，也不据操作类型补造 |
| 参考价格、预算、费用、审批 | 各自业务规则 | 本轮不并入操作定义，也不自动计算、改写或批准 |

“作业位置”回答按一基杆塔还是按一个已有档距定位；“作业对象”回答作用于线路侧设备还是共用物理杆塔，两者不是同一概念。共用物理杆塔作业仅允许杆塔定位。

## 维护界面

入口：系统管理 → 数据字典 → 操作类型 → 新增或编辑。

1. **基本定义**：名称、状态、固定计量单位、唯一作业对象、允许的作业位置、默认作业位置。必填字段红星，错误在字段附近显示。
2. **录入模板**：默认处理部位、建议每项数量、完成标准模板、录入提示。建议值不替代现场核对。
3. **附加字段**：复用可视化字段编辑器；调整显示名称保留字段标识。
4. **影响与预览**：汇总实际录入时的字段和建议值，显示当前配置版本、业务及配置引用数量和保存影响。切换预览页不创建业务记录。

使用 Element Plus ElDialog、ElTabs、ElForm 等官方组件。宽屏双列，窄屏单列；正文内部滚动，保存/取消在底部可达。列表同时显示位置范围、单位和作业对象，便于发现未完善定义；原有查询、排序、启停、编辑、删除及已删除查询继续保留。

## 在线录入和 Excel

- 在线新增先选操作，再选择具体线路和杆塔/档距。只有一种作业位置时显示只读值；允许两种时提供受限选项。编辑人员使用需求专用只读档距接口选择已有档距，不获得管理员台账权限。
- 切换操作保留数量并提示核对，不做单位换算；新操作不支持当前定位时，须确认后清空本组位置。取消确认保留原操作和位置；其他已加入批次的需求不受影响。
- 行编辑使用同一套约束；换位置须确认并重新选定位，明确清除过期档距引用，不能用变更操作偷偷搬迁已保存需求。
- 模板仍以每行一个位置、一种操作、一份本行工作量组织，最多5000行。新增“操作定义”参考表，列出位置范围、默认位置、对象、单位、部位、建议数量、完成标准和录入提示。
- 标准 Excel 的位置下拉随本行操作限制；单位和对象允许留空，由服务端确定，显式填写必须一致。粘贴可绕过 Excel 校验，因此解析预检和正式提交都会复检。
- 下载单一操作模板时按定义预填；多操作只有存在共同位置范围时才允许批量带入该类位置；无共同范围时按操作分别生成位置模板，或用空白明细逐行选择操作。
- 明细作业位置留空时，已有档距ID或终点编号按档距检查，否则使用操作默认位置；不会自动建立档距。不会用统一位置补值覆盖各行定义。

## 版本和数据保护

位置范围、默认位置、默认部位、提示存入既有 `dictionary_item_versions.snapshot_json` 的 `operation_profile`；计量单位、对象、建议数量、标准、附加字段仍使用既有字典字段。继续使用当前 Schema，没有数据库重建或历史迁移。

创建/编辑、批量启停、排序、逻辑删除均保留定义版本及审计；硬删除无引用误录词条时，配置版本归档在删除审计中。已有需求使用其采用版本和快照，修改操作定义不覆盖实际位置、对象、单位或数量。显式给旧需求采用新操作定义时，已有位置必须属于新定义范围；禁止默默转换。

既有操作未配置位置范围时，显示待完善，管理员须人工确定；不从PMS测试样本推导正式操作规则，不自动猜测或补写用户现有配置。工厂预置的新定义有明确位置范围，但不会覆盖用户已有同名/同码定义。

## 验证

自动验证包含位置约束、物理塔/档距互斥、错误位置拒绝提交、配置版本与原事实保留、启停后配置保留、5000行预检/提交/回滚/并发/重启，以及编辑人员的只读档距选择权限。

真实 Chrome 使用独立临时 SQLite：四个维护页签在1500/1280/960/760px检查字段横向边界和保存按钮可达，验证模板维护与预览、附加字段校验、在线操作切换确认/取消、Excel全流程。截图在被忽略的 `release/operation-*.png` 和 `release/demand-import`。

本轮结果：`npm run check`通过（严格UI门禁、TypeScript/Vite构建、99项自动测试）；17组浏览器脚本全部通过，最终构建后再次通过操作类型维护与5000行导入两组专项。`git diff --check`通过。所有数据库验证使用隔离临时目录，未修改当前用户数据库。

本方案不据此宣称需求正式来源、附件等既有待整改删除功能已完成。

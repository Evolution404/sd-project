# 需求 Excel 导入与批量录入

> **历史关联条款废止声明（2026-11-09）** 本文中涉及 PMS、一次性专用导入、外部编码、映射或兼容的设想全部废止，仅作为历史审计记录。现行系统独立管理业务，技术编码由服务端生成，执行 docs/decisions/2026-11-09_系统独立_自动编码_最少录入.md。

日期：2026-11-03。用户已授权实施，每批上限由 500 调整为 **5000 条需求**。

同日补充裁决：操作类型定义自己的固定计量单位和唯一作业对象。录入时两项只读带出；Excel两列可留空自动确定，显式填写时必须一致，不自动覆盖冲突或换算数量。模板记录每种操作采用的版本，包括无扩展字段的操作；下载后定义发生变化会提示重新核对。当前实现与98项自动测试／17组浏览器回归结果见《原生组件拦截与操作类型定义_2026-11-03.md》。

## 使用流程

进入“需求中心 → 新建需求”，页面以待提交清单为中心。

1. “添加一组需求”：弹窗中跨线路选择杆塔，按实际杆段追加，填写共同工作、来源及逐行差异，加入清单。可以连续添加不同操作。管理员从台账选择档距后发起需求时，同样进入此弹窗。
2. “下载模板”：选择线路、操作、位置类型及共同字段，可带入所选线路的全部有效位置，最多5000个。数量是每条需求数量，不是批次总量。来源日期及提出者按实际填写。
3. “Excel 导入”：上传 `.xlsx`，最大15MB；标准模板自动识别，也可选择外部文件的工作表、标题行、列映射及补空共同字段。列映射在当前浏览器按用户保存，支持查询、修改、另存和删除。业务明细最多200列，模板扩展字段超限时要求缩小操作范围；草稿／预检／提交JSON请求最大32MB。上传解析选项随文件放入表单请求体，避免长文本或大量来源超出HTTP请求头限制。
4. 导入后聚焦问题行；可逐条编辑、勾选批量补空、排除或重新纳入。勾选仅决定批量修改范围，提交范围是**全部未排除行**。每页默认100条，不能用当前页代替整批校验。
5. 来源依据有独立的新增、查询、修改、删除入口。修改来源编号同步更新本草稿引用；删除前说明影响，删除后不删除需求，缺少来源的需求重新提示补齐。
6. 保存草稿允许缺项。恢复后按当前台账和配置重新检查。草稿删除要求版本与依据，删除历史保留原内容和定位信息。
7. “提交 N 条核实”先预检，再显示新建数、关联已有数、排除数，明确确认后一次事务提交。结果仍为待核实；不自动核实、立项或生成费用。可下载明细编号与系统需求编号对应结果。

## 模板

模板不包含可被误提交的示例业务行，示例只放在“填写说明”。

| 工作表 | 内容 |
| --- | --- |
| 填写说明 | 填写顺序、数量口径、来源引用、字段条件、修正方式 |
| 需求明细 | 每行一个明确位置、一个操作及本行工作量 |
| 来源依据 | 同一次巡视或同一份依据填一次，多条需求引用 |
| 可选项 | 下载时有效的线路、操作、单位、来源、优先级等 |
| 杆塔参考 | 所选线路的完整原始杆塔编号及电压等级 |
| 隐藏模板信息 | 字段定义及模板版本提示，不能作为可信业务ID绕过校验 |

需求明细固定列：明细编号、线路名称、电压等级、位置类型、杆塔／档距起点编号、档距终点编号、作业对象、操作类型、处理部位／对象、工作量、单位、问题描述／实施必要性、完成标准、来源编号、优先级、期望完成日期。

操作扩展列按选择的操作生成，名称为“扩展：操作名称／字段名称”。只检查本行操作适用的字段；保留下载时模板版本提示，最终采用服务端当前定义验证。

来源依据固定列：来源编号、来源类型、发现／提出日期、提出单位／人员、依据编号、来源说明。

明细编号和来源编号只在本文件／当前草稿内定位，不是系统业务编号。多来源用分号分隔，例如 `LY001;LY002`，每条需求最多20项来源。工作量为正数、最多四位小数。不同单位分别汇总。

编号按文本保存完整原文及前导零。位置通过原始编号在对应线路中准确匹配；重名线路用电压等级区分；短编号不能自动猜测。档距必须匹配已有有效连接，不新建杆塔或档距。公式业务单元格、合并单元格会提示修正。

## 校验和事务边界

Excel 提供下拉、数量限制和空值标色；上传后和正式提交仍执行服务端校验，不能依赖Excel数据验证。覆盖必填、真实日期、四位小数、有效字典、条件字段、适用对象、来源引用、档距版本、公共实体、台账关系及重复事项。

疑似重复区分本批与已有需求。同一位置不同作业或不同部位可分别登记；公共实体同部位不能重复计量。关联已有需求来源维持核实权限约束，普通编辑人员不能越权。已有需求不被覆盖，原来源和历史保留。

预览只读，不创建需求、来源或台账。保存草稿仅写既有 `demand_batches`。提交在SQLite写事务内重新读取台账、字典、草稿及重复候选，核对位置／配置采用版本及提交校验摘要；任何失败全部回滚。幂等键绑定请求内容，重复请求返回同一批次及结果，修改内容后不能复用已提交键。

错误反馈包含明细编号、工作表、原始行号、字段及原因。原始单元格值保留在草稿行中；问题文件保留业务列与来源，并追加纳入状态和错误说明。重传合并前展示更新、追加及未出现行的数量；不会自动删除原清单未出现行。超5000行整份拒绝，不截断或自动多批提交。

不增加PMS数据治理菜单、审核流程或表结构；不修改当前Schema版本，不迁移、清空或修正现有用户数据库。

## 界面/API 对照

| 能力 | API |
| --- | --- |
| 下载动态模板 | `POST /api/demand-import/template` |
| 读取工作表及列信息 | `POST /api/demand-import/layout?header_row=1` |
| 解析并只读预检 | `POST /api/demand-import/parse`，`multipart/form-data`，`file`为文件、`options`为JSON解析配置；大量来源与长文本不放入HTTP请求头 |
| 统一清单预检 | `POST /api/demand-batches/preview` |
| 下载问题文件 | `POST /api/demand-import/problems` |
| 新建、查询草稿 | `POST /api/demand-batches/drafts`、`GET /api/demand-batches?status=draft` |
| 查询、修改、删除草稿 | `GET/PATCH/DELETE /api/demand-batches/:id` |
| 查询删除历史 | `GET /api/demand-batches?status=deleted` |
| 一次事务提交 | `POST /api/demand-batches/submit` |
| 下载提交结果 | `GET /api/demand-batches/:id/result.xlsx` |

上述录入接口服务端限定管理员／编辑人员；普通账号仅访问自身草稿，管理员可管理所有草稿。业务需求后续核实、修订及历史沿用原流程。已提交需求、正式来源及附件的统一删除仍是《增删改查_待授权审核清单.md》的待整改项；本轮只补齐批次草稿及未提交来源管理，不宣称需求领域已完整满足全部增删改查。

- 原 `tests/browser.mjs`、`browser-audit.mjs`、`browser-ledger.mjs`：在线分组录入、逐基扩展字段、来源、档距草稿及业务回归。
- `npm run check`、`npm run test:browser`、`git diff --check`：严格Element Plus门禁、构建、全量单测及浏览器链路。

截图写入被忽略的 `release/demand-import`。全部场景使用独立临时SQLite数据库，不使用当前Mac测试台账作为校验输入，也不改变该数据库。

大批量读取采用批量目录索引、每页100行预览和复用预编译写入语句。本机5000条合成提交的测试耗时约0.3秒，仅指隔离样本事务请求，不含用户填写、模板生成和Excel解析，不作为生产性能承诺。
